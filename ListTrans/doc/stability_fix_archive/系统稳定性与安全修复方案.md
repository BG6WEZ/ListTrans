## 一、修复目标

| 维度 | 目标 |
| :--- | :--- |
| **安全** | 消除全部已识别的后门级漏洞（无认证降级、硬编码密钥、路径穿越、权限缺失），系统在无 token 访问时必须返回 401 |
| **稳定性** | 消除确定性死锁（RuleHitStatsTracker）、前端永久转圈（showLoading 无兜底）、后端无超时护栏 3 项 P0 级稳定性隐患 |
| **并发** | auth.db 开启 WAL + busy timeout，消除多用户并发 `database is locked` |
| **内存** | upload_tasks 引入 TTL 清理，杜绝长期运行 OOM |
| **兼容** | 修复 Python 3.12+ 废弃 API 警告（utcnow、on_event） |

## 二、修复清单

### P0 -- 必须立即修复

| 编号 | 问题 | 位置 | 修复动作 | 验收标准 |
| :---: | --- | --- | --- | --- |
| P0-1 | **RuleHitStatsTracker 确定性死锁** | `llm_rule_engine.py` L504 `threading.Lock()` | 改为 `threading.RLock()` | 规则命中累计 ≥10 次后，`record_hit` 和 `flush` 不阻塞，线程正常返回 |
| P0-2 | **无 token 自动降级 admin** | `auth_middleware.py` L12-L14 | 移除 fallback 降级逻辑；无 credentials 时返回 `401 Unauthorized`；如需调试模式，通过 `.env` 的 `AUTH_DEV_MODE=true` 显式开启 | 无 Authorization 头访问任意受保护接口，返回 401 |
| P0-3 | **前端 showLoading 无 Timeout 兜底** | `web/app.js` L691-L699 | 在 `showLoading` 中注入 30 秒 `setTimeout` 保底定时器，超时后 `hideLoading` + 提示用户；`hideLoading` 中 `clearTimeout` | 任意 JS 异常或网络阻塞后，30 秒内遮罩自动消失 |
| P0-4 | **后端 /api/upload 无超时护栏** | `server.py` `upload_file` / `async_process_upload_task` | 用 `asyncio.wait_for(..., timeout=90)` 包裹处理逻辑，超时返回 408 或 504 | 清单处理超过 90 秒时，前端收到超时响应而非无限等待 |
| P0-5 | **冷启动模型联网下载卡死** | `vector_index.py` L52-L55 | 设置 `HF_HUB_OFFLINE=1`；模型缺失时立即抛错并返回前端友好提示；`_initialize_model` 加 10 秒超时 | 离线环境下模型缺失时，3 秒内返回错误提示，不卡死 |

### P1 -- 高优先级修复

| 编号 | 问题 | 位置 | 修复动作 | 验收标准 |
| :---: | --- | --- | --- | --- |
| P1-1 | **文件上传路径穿越** | `server.py` L822, L1565 | 对 `file.filename` 使用 `os.path.basename()` 过滤，或直接用 `uuid` 重命名 | 传入 `../../etc/passwd` 作为文件名时，文件只写入 UPLOAD_DIR 内 |
| P1-2 | **/api/system/reset 权限过宽** | `server.py` L407 | `Depends(get_current_user)` 改为 `Depends(require_admin)` | 非 admin 角色调用返回 403 |
| P1-3 | **硬编码 JWT SECRET_KEY** | `auth_manager.py` L27 | 移除默认值；未配置 `.env` 时启动报错拒绝运行 | 删除 `.env` 中的 `SECRET_KEY` 后，服务启动失败并提示配置缺失 |
| P1-4 | **auth.db 无 WAL / 无 timeout** | `auth_manager.py` L33-L36 `get_auth_connection` | 增加 `conn.execute("PRAGMA journal_mode=WAL")` + `conn.execute("PRAGMA busy_timeout=5000")` | 5 个并发线程同时写 auth.db，不出现 `database is locked` |
| P1-5 | **upload_tasks 内存无限增长** | `server.py` L620 | 引入 TTL 机制：任务完成 30 分钟后自动删除该 task_id；或限制字典最大容量为 50，超出时删最旧 | 连续上传 100 次清单后，`upload_tasks` 条目数 ≤50 |
| P1-6 | **hybrid_recall 每行 3 次 SQLite 连接** | `matcher.py` L861-L899 | 改用 thread-local 连接池或预加载 45k 物料到内存 dict | 1000 行清单的 SQLite 连接开合次数从 ~3000 降至 ≤10 |
| P1-7 | **ThreadPoolExecutor max_workers=10 过高** | `server.py` L436 | 降为 `max_workers=4`；禁用 `match_item` 内部的 fallback `encode_single_query` | 500 行清单处理时不触发模型锁竞争 |

### P2 -- 中优先级修复

| 编号 | 问题 | 位置 | 修复动作 | 验收标准 |
| :---: | --- | --- | --- | --- |

| P2-2 | **utcnow() 已废弃** | `auth_manager.py` L240, L242 | 改为 `datetime.datetime.now(datetime.timezone.utc)` | Python 3.12+ 下无 DeprecationWarning |
| P2-3 | **@app.on_event 废弃** | `server.py` L539 | 改为 `lifespan` 上下文管理器 | FastAPI 启动无 DeprecationWarning |

## 三、检验标准

### 3.1 安全性检验

| 检验项 | 方法 | 预期结果 |
| :--- | :--- | :--- |
| 无 token 访问受保护接口 | `curl http://localhost:8000/api/system/reset -X DELETE`（不带 Authorization） | 返回 401 |
| 非 admin 调用 system/reset | 用 employee 角色登录后调用 | 返回 403 |
| 路径穿越 | 上传文件名为 `../../test.xlsx` | 文件只出现在 UPLOAD_DIR 内 |
| JWT 伪造 | 用硬编码 SECRET_KEY 签发 token | 删除默认值后该 token 无效 |
| SQL 注入 | 在用户名/规则名中注入 `' OR 1=1 --` | 查询正常返回空或报错，不泄露数据 |

### 3.2 稳定性检验

| 检验项 | 方法 | 预期结果 |
| :--- | :--- | :--- |
| 规则命中死锁 | 连续触发 ≥10 次规则命中 | 线程不阻塞，`flush` 正常写入 DB |
| 前端永久转圈 | 模拟后端处理超时（断网或 kill 后端） | 30 秒后遮罩自动消失并提示 |
| 后端超时护栏 | 上传 1000 行清单 + 限制 CPU | 90 秒内返回结果或超时响应 |
| 模型离线保护 | 删除 `model_offline/` 目录 | 3 秒内返回错误提示，不卡死 |
| auth.db 并发锁库 | 5 个线程同时写 auth.db | 不出现 `database is locked` |
| upload_tasks 内存泄露 | 连续上传 100 次清单 | `len(upload_tasks)` ≤50 |
