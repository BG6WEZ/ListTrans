 # 广联达清单清洗与物料库匹配技术方案

> **版本**：V1.0  
> **目标**：将广联达导出的半结构化清单与企业半结构化物料库进行自动清洗、特征提取与匹配，输出标准格式Excel。  
> **核心约束**：**不改变现有软件的任何操作界面、交互逻辑、按钮功能、页面布局及用户操作路径**。新增功能以独立后台任务模块形式接入，通过标准接口与现有系统交互。

---

## 1. 概述

### 1.1 目标

1. **清洗**：将广联达清单的「项目特征」半结构化文本解析为标准化特征指纹。
2. **匹配**：将清单特征指纹与企业物料库特征指纹进行比对，找到最佳物料编码。
3. **回写**：按标准格式输出Excel，包含原始数据、清洗结果、匹配结果、置信度及复核标记。
4. **性能**：支持**200人并发**提交任务；支持单次导入**≤2000行**清单的批量处理，单任务完成时间≤30秒。

### 1.2 约束条件（严格遵守）

| 约束项 | 要求 |
|-------|------|
| **UI/UX不变** | 不得修改现有软件的任何页面、按钮、菜单、表单、弹窗、导航逻辑。 |
| **操作路径不变** | 用户现有的「导入→编辑→导出」操作习惯完全保留。 |
| **接入方式** | 以「后台异步任务」形式接入。用户在现有界面上传Excel后，系统后台触发清洗匹配任务，完成后通过现有消息通知或下载中心提供结果文件。 |
| **数据兼容** | 清洗匹配模块的输入输出均为标准Excel文件，不修改现有数据库表结构。 |
| **回退能力** | 模块异常时，现有软件功能不受影响，用户可继续手动操作。 |

### 1.3 术语定义

| 术语 | 定义 |
|-----|------|
| **Source** | 广联达导出的清单行数据。 |
| **Target** | 企业物料库中的物料记录。 |
| **Fingerprint（特征指纹）** | 对半结构化文本解析后生成的标准化五维结构化数据。 |
| **倒排索引** | 以标签/关键词为键、物料ID列表为值的内存索引结构。 |
| **参数对** | 键值对形式的技术参数，如 `{绝缘: YJV, 截面: 95}`。 |
| **L1/L2/L3** | 匹配漏斗的三个层级（精确/强规则/模糊）。 |

## 2. 总体架构

### 2.1 模块划分

系统由四个独立模块组成，通过标准数据接口串联：

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   清洗模块      │     │   索引模块      │     │   匹配模块      │     │   输出模块      │
│   (Parser)      │────▶│   (Indexer)     │────▶│   (Matcher)     │────▶│   (Exporter)    │
│                 │     │                 │     │                 │     │                 │
│ 输入：Source    │     │ 输入：Target    │     │ 输入：指纹+索引  │     │ 输入：匹配结果   │
│ 输出：指纹      │     │ 输出：倒排索引   │     │ 输出：MatchResult│     │ 输出：标准Excel │
└─────────────────┘     └─────────────────┘     └─────────────────┘     └─────────────────┘
```

### 2.2 数据流

1. **启动阶段**：物料库全量文本通过清洗模块生成指纹，索引模块构建倒排索引，**常驻内存**。
2. **任务阶段**：用户上传清单Excel → 解析为Source列表 → 每行Source经清洗模块生成指纹 → 匹配模块查询索引并执行漏斗匹配 → 输出模块生成结果Excel → 用户下载。

### 2.3 与现有系统的交互边界

```
现有系统界面
    │
    ▼
[文件上传接口] ──▶ 保存到临时目录 ──▶ [异步任务队列]
                                          │
                                          ▼
                                    [清洗匹配引擎]
                                          │
                                          ▼
                                    [结果文件存储]
                                          │
                                          ▼
[现有下载中心/消息通知] ◀── 任务完成回调 ◀──┘
```

- 现有系统仅需增加「上传文件后触发异步任务」和「任务完成后推送通知」两个最小改动点。
- 若现有系统无任务队列，可用独立Python进程监听文件目录实现，不侵入现有代码。

## 3. 数据模型

### 3.1 Source 数据模型（清单行）

| 字段 | 类型 | 来源 | 说明 |
|-----|------|------|------|
| `source_id` | string | 系统生成 | 行唯一标识，如 `TASK_001_ROW_0001` |
| `project_code` | string | 广联达Excel「项目编码」列 | 用于专业识别 |
| `project_name` | string | 广联达Excel「项目名称」列 | 核心文本 |
| `project_feature` | string | 广联达Excel「项目特征」列 | 核心文本，多行换行符分隔 |
| `quantity` | number | 广联达Excel「工程量」列 | 透传 |
| `unit` | string | 广联达Excel「单位」列 | 标准化后参与匹配 |

### 3.2 Target 数据模型（物料库行）

| 字段 | 类型 | 来源 | 说明 |
|-----|------|------|------|
| `target_id` | string | 物料库主键 | 物料唯一编码 |
| `mat_name` | string | 物料库「物料名称」列 | 核心文本 |
| `mat_spec` | string | 物料库「规格型号」列 | 核心文本 |
| `mat_material` | string | 物料库「材质」列 | 可为空 |
| `mat_brand` | string | 物料库「品牌」列 | 可为空 |
| `mat_unit` | string | 物料库「计量单位」列 | 标准化后参与匹配 |
| `mat_profession` | string | 物料库「专业分类」列 | 可为空，通过编码或关键词推导 |

### 3.3 Fingerprint 特征指纹模型

清洗模块对 Source 和 Target 的输出统一为此模型：

```yaml
Fingerprint:
  profession: string        # 专业标：土建/结构/强电/弱电/装饰/给排水
  product_word: string      # 产品词：标准化后的核心产品名称
  brand_tag: string         # 品牌标：标准化品牌代码，空表示未识别
  material_tag: string      # 材质标：标准化材质，空表示未识别
  unit_tag: string          # 单位标：标准化单位
  param_pairs: dict         # 参数对：{key: value, ...}，核心字段
  raw_text: string          # 原始文本（用于人工核对）
  parse_confidence: float   # 解析置信度：0.0~1.0
```

### 3.4 MatchResult 匹配结果模型

| 字段 | 类型 | 说明 |
|-----|------|------|
| `source_id` | string | 关联Source |
| `target_id` | string | 匹配到的物料编码，未匹配为空 |
| `target_name` | string | 匹配到的物料名称 |
| `match_level` | string | `L1`/`L2`/`L3`/`UNMATCHED` |
| `confidence` | float | 匹配置信度 0.00~1.00 |
| `match_reason` | string | 匹配依据简述 |
| `review_flag` | string | `AUTO`（免核）/`CHECK`（必核）/`ERROR`（异常） |
| `top_candidates` | list | Top-3候选 [{target_id, target_name, confidence}, ...] |

## 4. 清洗模块（Parser）

### 4.1 设计原则

- **对称性**：同一套解析器、同一套词典、同一套正则模式，同时处理 Source 和 Target。
- **专业性**：先识别专业，再加载对应专业词典，避免术语串扰。
- **参数优先**：优先提取结构化参数对，文本相似度仅作为辅助。

### 4.2 专业识别

**输入**：`project_code` + `project_name` + `project_feature`  
**输出**：`profession` 标签

**识别策略（优先级从高到低）**：

1. **编码前缀匹配**（准确率最高）：
   - `01` 开头 → `土建/结构`
   - `0304` 开头 → `强电`
   - `0305` 开头 → `弱电`
   - `0310` 开头 → `给排水`
   - `0112` 开头 → `装饰`

2. **项目名称关键词匹配**（编码无法识别时）：
   - 含「电缆」「桥架」「配电箱」「配管」→ `强电`
   - 含「水管」「阀门」「卫生器具」「PP-R」→ `给排水`
   - 含「乳胶漆」「瓷砖」「吊顶」「龙骨」→ `装饰`
   - 含「混凝土」「砂浆」「砌体」「防水」→ `土建`
   - 含「钢筋」「钢结构」「预埋件」→ `结构`

3. **特征关键词投票**（前两步失败时）：
   - 统计 `project_feature` 中各专业词典关键词出现频次，取最高频。

### 4.3 文本预处理

对 `project_feature`、`project_name`、`mat_spec` 等文本统一执行：

1. **全角转半角**：字符级转换。
2. **换行符统一**：`\r\n`、`\r` 统一为 `\n`。
3. **去空行**：去除首尾空白及纯空行。
4. **序号去除**：去除行首序号标记（如 `1.`、`1、`、`(1)`）。
5. **分隔符规范化**：将中文顿号 `、`、分号 `；` 统一为换行符 `\n`（便于后续按行处理）。

### 4.4 属性提取规则

预处理后，文本被切分为多行。对每一行执行**关键词前缀匹配**：

**通用属性关键词词典**：

| 属性 | 关键词列表 |
|-----|-----------|
| 名称 | 名称、项目名、品名、设备名称 |
| 规格 | 规格、型号、规格型号、型号规格、技术参数、参数、配置 |
| 材质 | 材质、材料、质地、用料 |
| 品牌 | 品牌、牌子、厂家、制造商、厂商 |
| 单位 | 单位、计量单位 |

**匹配逻辑**：
- 行首出现「关键词 + 分隔符（冒号/空格）」→ 提取为键值对。
- 无明确键名但包含参数模式 → 归入 `param_pairs`。
- 使用 `rapidfuzz` 进行模糊匹配，相似度阈值 **0.75**。

### 4.5 参数对解析（核心）

参数对是匹配准确率的基石。各专业参数解析规则如下：

**强电专业**：
- 电缆型号：正则 `([A-Z]+)-([\d\.]+/[\d\.]+kV)-([\d×\d\+\d]+)` → 拆解为 `{绝缘: YJV, 电压: 0.6/1kV, 芯数截面: 4×95+1×50}`
- 管材：`SC\d+`、`PVC\d+`、`JDG\d+` → `{管材: SC, 直径: 100}`
- 芯数截面：`\d+×\d+` 或 `\d+×\d+\+\d+×\d+` → 拆解为 `{主芯数:4, 主截面:95, 地线芯数:1, 地线截面:50}`

**给排水专业**：
- 管径：`dn\d+`、`De\d+`、`DN\d+`、`Φ\d+` → 统一映射为 `{公称直径: 25}`（建立 dn/De/DN/Φ 到标准值的映射表）
- 压力等级：`S\d+\.\d+` 或 `\d+\.\d+MPa` 或 `PN\d+\.\d+` → `{压力等级: 1.6MPa}`
- 管材材质：`PP-R`、`PVC-U`、`PE`、`PE-RT`、`PB` → 直接提取

**土建专业**：
- 强度等级：`C\d+` → `{混凝土强度: C30}`
- 抗渗等级：`P\d+` → `{抗渗等级: P6}`
- 配合比：`\d+:\d+(:\d+)?` → `{配合比: 1:2.5}`
- 塌落度：`\d+~\d+mm` 或 `≥\d+mm` → `{塌落度: 160~180mm}`

**结构专业**：
- 钢筋牌号+直径：`([A-Z]+\d+[E]?)[Φφ](\d+)` → `{牌号: HRB400E, 直径: 25}`
- 抗震等级：提取「一级/二级/三级/四级/抗震钢筋」
- 连接方式：「搭接/焊接/机械连接/套筒连接」

**装饰专业**：
- 颜色：匹配颜色词库（白/黑/米白/灰/蓝/定制色等）
- 遍数：`\d+遍`、`\d+道`、`\d+层`、`一底两面`
- 基层处理：「腻子找平/界面剂/石膏找平/铲除原面层」
- 部位：「墙面/顶面/地面/柱面/踢脚/门窗套」

**弱电/智能化专业**：
- 通信标准：`CAT[5-8][ae]?`、`OM[1-5]`、`单模`、`多模`
- 端口数：`\d+口`、`\d+芯`、`\d+对`
- 屏蔽类型：`UTP`、`FTP`、`STP`、`SFTP`、`屏蔽`、`非屏蔽`

### 4.6 产品词标准化

从 `project_name` 或 `mat_name` 中提取核心产品词，去除品牌、规格、参数：

- 「华为核心交换机 S5735」 → `网络交换机`
- 「YJV-0.6/1kV电力电缆」 → `电力电缆`
- 「PP-R S4 dn25给水管」 → `给水管`

**方法**：
1. 去除已识别的品牌、规格参数文本。
2. 去除专业停用词（如「优质」「国标」「环保型」）。
3. 保留名词性核心词，使用专业词典做同义词映射（如「网线」→`双绞线`，「开关面板」→`开关`）。

### 4.7 品牌与材质标准化

建立标准化映射表：

```yaml
品牌映射:
  华为: HUAWEI
  华三: H3C
  海康威视: HIKVISION
  海康: HIKVISION

材质映射:
  聚丙烯: PP-R
  聚氯乙烯: PVC-U
  交联聚乙烯: YJV
  铜芯: 铜
  三级钢: HRB400
```

## 5. 匹配模块（Matcher）

### 5.1 设计原则

- **索引先行**：所有 Target 指纹预建倒排索引，常驻内存，查询复杂度 O(1)。
- **漏斗递减**：逐层过滤，上层命中的数据不再进入下层。
- **硬约束优先**：品牌冲突、单位不可换算、专业不一致时直接阻断，不进入相似度计算。

### 5.2 物料库索引构建（离线/启动时）

**构建时机**：系统启动时全量构建；物料库更新时增量更新。

**倒排索引结构**（Python伪结构）：

```python
inverted_index = {
    # 产品词索引
    "product": {
        "电力电缆": ["M001", "M023", "M145"],
        "给水管": ["M301", "M302"],
        "网络交换机": ["M501", "M502"],
        ...
    },
    # 参数索引（参数值 → 物料ID列表）
    "param": {
        "绝缘=YJV": ["M001", "M002"],
        "截面=95": ["M001", "M045"],
        "dn=25": ["M301", "M302"],
        ...
    },
    # 品牌索引
    "brand": {
        "HUAWEI": ["M501", "M502"],
        "HIKVISION": ["M601"],
        ...
    },
    # 专业索引
    "profession": {
        "强电": ["M001", "M002", ...],
        "给排水": ["M301", "M302", ...],
        ...
    }
}
```

**构建逻辑**：
1. 遍历物料库每一行，调用清洗模块生成 `Fingerprint`。
2. 将 `Fingerprint` 中的 `product_word`、`brand_tag`、`profession` 及每个 `param_pairs` 的键值对加入对应索引。
3. 同时维护 `target_id → Fingerprint` 的内存映射表，用于后续精排时取完整指纹。

### 5.3 四层匹配漏斗

对每一行 Source 指纹执行以下流程：

#### 5.3.1 L1 精确匹配

**触发条件**（满足任一）：

1. **历史映射表命中**：`source_id` 的 `project_code` + `project_feature` 摘要存在于历史映射表中 → 直接返回对应 `target_id`。
2. **型号精确匹配**：Source 提取的型号代码（如 `S5735-S24T4X`）与 Target 指纹中的型号代码完全一致。
3. **参数全等匹配**：`param_pairs` 中所有关键参数对完全相等，且 `material_tag` 相等，且 `unit_tag` 可换算。

**输出**：`match_level=L1`, `confidence=0.98~1.00`, `review_flag=AUTO`。

#### 5.3.2 L2 强规则匹配

**候选集生成**（倒排索引粗筛）：

```
候选集 = 专业索引[profession] 
         ∩ 产品词索引[product_word] 
         ∩ (品牌索引[brand_tag] 若 brand_tag 非空)
```

若候选集为空，直接进入 L3。

**精排计算**（仅对候选集中的 Target 指纹）：

```
score = name_sim × 0.30 + param_sim × 0.45 + material_sim × 0.15 + unit_sim × 0.10

其中：
- name_sim = TF-IDF余弦相似度(Source.product_word, Target.product_word)
- param_sim = 参数匹配率 = 匹配参数对数 / max(Source参数对数, Target参数对数)
- material_sim = 1.0 if 材质相等 else 0.0
- unit_sim = 1.0 if 单位可换算 else 0.0
```

**判定**：
- `score ≥ 0.90` 且 `param_sim ≥ 0.80` → `match_level=L2`, `confidence=score`, `review_flag=AUTO`。
- 否则进入 L3。

#### 5.3.3 L3 模糊匹配

**候选集扩大**：
```
候选集 = 专业索引[profession] ∩ 产品词索引[product_word]
```
（放宽品牌限制，同一产品词不同品牌可能为同一品类不同厂家）

**精排计算**（同 L2 公式）。

**判定**：
- `0.75 ≤ score < 0.90` → `match_level=L3`, `confidence=score`, `review_flag=CHECK`。
- `score < 0.75` → `match_level=UNMATCHED`, `confidence=score`, `review_flag=CHECK`。

#### 5.3.4 L4 未匹配处理

- `match_level=UNMATCHED` 时，`target_id` 为空。
- `top_candidates` 记录 L3 中 score 最高的 3 个候选，供人工参考。
- **不调用 LLM 做运行时匹配**。LLM 仅用于离线辅助优化解析规则。

### 5.4 冲突检测规则（硬阻断）

在 L2/L3 精排前，对候选集执行硬约束过滤：

| 冲突类型 | 规则 | 处理 |
|---------|------|------|
| **品牌冲突** | Source.brand_tag ≠ 空 且 Target.brand_tag ≠ 空 且 两者不等 | 该 Target 从候选集移除 |
| **单位不可换算** | Source.unit_tag 与 Target.unit_tag 不在同一换算族 | 该 Target 从候选集移除 |
| **专业冲突** | Source.profession ≠ Target.profession | 该 Target 从候选集移除 |
| **材质冲突** | Source.material_tag ≠ 空 且 Target.material_tag ≠ 空 且 两者不等且不在近材质映射表中 | 相似度上限封顶 0.70 |

**单位换算族定义**：
- 长度族：米、千米、厘米、毫米、100米/盘
- 面积族：平方米、平方厘米
- 重量族：千克、吨、克、公斤
- 数量族：个、套、台、根、块、卷、盘、箱
- 体积族：立方米、升、毫升

### 5.5 置信度计算

最终置信度由匹配层级和精排分数共同决定：

| 匹配层级 | 置信度公式 | 说明 |
|---------|-----------|------|
| L1 | `1.00` | 精确匹配 |
| L2 | `max(score, 0.90)` | 强规则，分数保底0.90 |
| L3 | `score` | 模糊匹配，0.75~0.89 |
| UNMATCHED | `0.00` | 未匹配 |

## 6. 批处理与性能设计

### 6.1 异步任务模型

```
用户上传Excel
    │
    ▼
[生成任务ID] ──▶ 返回任务ID给用户（现有界面提示"任务已提交"）
    │
    ▼
[任务队列] ──▶ 按专业分片（强电/弱电/给排水/土建/结构/装饰）
    │
    ▼
[工作节点池] ──▶ 多进程并行处理（每进程处理一个专业分片）
    │
    ▼
[结果聚合] ──▶ 按原始行序合并结果
    │
    ▼
[生成Excel] ──▶ 写入临时存储
    │
    ▼
[回调通知] ──▶ 现有消息系统推送"任务完成"
```

### 6.2 并发与分片策略

| 维度 | 策略 |
|-----|------|
| **任务分片** | 2000行按专业分为6个队列，同专业行进入同一队列，避免进程间词典切换开销。 |
| **进程模型** | 每个工作节点启动 N 个进程（N = CPU物理核心数），每进程顺序处理一个分片。 |
| **内存模型** | 倒排索引和 Target 指纹表作为**只读共享内存**，多进程只读不写。 |
| **I/O隔离** | 原始Excel读取和结果Excel写入由主进程完成，工作进程仅处理内存数据。 |
| **进度反馈** | 每完成100行，向Redis写入进度（`task_id:progress`），前端轮询或SSE推送。 |

### 6.3 性能指标

| 指标 | 目标值 | 保障措施 |
|-----|-------|---------|
| 单任务处理时间（2000行） | ≤30秒 | 倒排索引O(1)查询 + 多进程并行 |
| 单节点吞吐量 | ≥200行/秒 | 每行解析+匹配控制在5ms以内 |
| 并发用户数 | 200人 | 任务队列削峰 + 工作节点水平扩展 |
| 内存占用（1万物料库） | ≤2GB | 倒排索引为哈希表 + 字符串池化 |
| 索引构建时间（1万物料） | ≤10秒 | 启动时一次性构建，增量更新 |

## 8. 准确率保障机制

### 8.1 分层准确率目标

| 匹配层级 | 预期占比 | 准确率目标 | 复核策略 |
|---------|---------|-----------|---------|
| L1 | ~25% | 99% | 免复核 |
| L2 | ~40% | 95% | 抽检5% |
| L3 | ~20% | 85% | 必复核 |
| UNMATCHED | ~15% | — | 必复核，走新增物料流程 |

**整体有效准确率 = (99%×25% + 95%×40% + 85%×20%) / 85% ≈ 94.1%**，满足≥80%基线。

### 8.2 人工复核闭环

- 用户下载结果Excel后，在「复核标记」列标记 `已确认` 或 `已修正`。
- 修正时填写「修正后物料编码」列（预留空白列）。
- 系统定期（如每日）扫描复核完成的文件：
  - `已确认` 的 L3 匹配 → 加入正样本库，用于调整 L2/L3 阈值。
  - `已修正` 的条目 → 加入历史映射表，下次 L1 直接命中。
  - `ERROR` 标记 → 分析冲突原因，优化阻断规则。

### 8.3 持续进化机制

| 进化项 | 触发条件 | 动作 |
|-------|---------|------|
| 历史映射表 | 人工修正确认 | 追加 `project_code+feature_hash → target_id` |
| 参数模式库 | 解析失败日志 | 补充新型号的正则模式 |
| 品牌/材质映射 | 新品牌出现 | 追加映射条目 |
| 权重调优 | 季度复核统计 | 根据正/负样本调整 L2/L3 权重 |

## 9. 边界与异常处理

### 9.1 输入校验

| 校验项 | 规则 | 异常处理 |
|-------|------|---------|
| 文件格式 | 必须为 `.xlsx` | 返回错误：「请上传Excel文件」 |
| 必填列 | 必须包含「项目编码」「项目名称」「项目特征」 | 返回错误：「缺少必要列：XXX」 |
| 行数限制 | 单次导入 ≤ 2000 行 | 返回错误：「单次导入不得超过2000行，请分批上传」 |
| 空行处理 | 跳过完全空行，不计入2000行限制 | 日志记录跳过行号 |
| 编码异常 | 项目编码为空或格式异常 | 尝试用项目名称+特征推导专业，标记 `解析置信度=0.5` |

### 9.2 运行时异常

| 异常场景 | 处理策略 |
|---------|---------|
| 清洗模块解析失败 | 该行 `parse_confidence=0`，`match_level=UNMATCHED`，`异常说明=解析失败`，不阻塞其他行 |
| 索引查询异常 | 降级为全量扫描（O(n)），记录告警日志 |
| 内存不足 | 触发索引分片加载（按专业分片），只加载当前处理专业的索引 |
| 任务超时（>60秒） | 强制终止，标记任务状态为「处理超时」，用户可重新提交 |
| 物料库为空/未加载 | 返回错误：「物料库未初始化，请联系管理员」 |

### 9.3 对现有系统的约束（再次强调）

- **不修改现有数据库表结构**：清洗匹配模块使用独立的内存索引和临时文件存储。
- **不修改现有API接口**：新增任务提交接口为独立端点（如 `/api/v2/clean-match/task`），现有接口不变。
- **不修改前端页面**：结果通过现有「下载中心」或「消息通知」组件推送，不新增页面。
- **可独立启停**：清洗匹配模块作为独立服务进程，异常时不影响现有软件的核心功能。
