# 华康洁净物料清单匹配系统 · 硬件资源需求评估与容量测算报告 (V0.0.8)

> **报告版本**：V0.0.8  
> **评估目标**：针对 20人、50人、100人 团队规模下的服务器硬件配置、网络带宽及性能容量进行科学测算与评估。

---

## 一、 系统资源消耗模型拆解

系统的资源消耗分为 **静态常驻开销 (Base Overhead)** 和 **动态并发开销 (Dynamic Overhead)** 两部分：

### 1.1 静态常驻开销 (Base Memory & CPU)
* **离线文本向量模型 (`paraphrase-multilingual-MiniLM-L12-v2`)**：加载至内存占用约 **800 MB - 1.0 GB**。
* **全局物料库向量索引 (`45,789 × 384` 维矩阵)**：常驻内存占用约 **100 MB**。
* **SQLite 数据库 (WAL 模式页缓存)**：`materials.db` + `auth.db` + `sessions.db` 缓存占用约 **100 MB - 200 MB**。
* **FastAPI / Uvicorn 主进程**：常驻占用约 **150 MB**。
* **总结**：系统启动后的**静态基准内存开销约为 1.5 GB - 2.0 GB**。

### 1.2 动态并发开销 (Per Concurrent Task)
* **Excel 解析开销**：用户上传 1,000 行原始 Excel 清单时，Pandas 与 OpenPyXL 在内存中进行单元格解析与对象映射，单次占用 **200 MB - 300 MB RAM**。
* **结构化与向量比对耗时**：
  * 单行清单项目的正则清洗 + 属性提取 + 4.6万条向量点乘比对，消耗 **20 ms - 40 ms CPU 时间**。
  * 单 CPU 核心每秒可完成约 **30 - 50 行** 清单的毫秒级比对。
* **大模型 LLM 规则生成开销**：
  * 大模型推理托管在云端（DashScope / DeepSeek），**本地零 GPU / 显存需求**。
  * 本地仅需承担 HTTPS 异步请求转发与 JSON DSL 解释运行，CPU/内存消耗极微（< 5MB/次）。

## 二、 硬件需求测算矩阵 (20人 / 50人 / 100人)

企业级应用中，非所有注册用户都会在同一秒上传清单。根据行业通用**并发系数**测算（日常并发率 15% - 25%）：

| 评估维度 | **20 人规模** (部门级) | **50 人规模** (工程公司级) | **100 人规模** (集团采购中心级) |
| :--- | :--- | :--- | :--- |
| **典型并发场景** | 3 ~ 5 人同时上传比对/规则调试 | 8 ~ 12 人同时上传比对/规则调试 | 15 ~ 25 人同时集中批比对/规则审核 |
| **推荐 CPU** | **4 核心 (vCPU)** | **8 核心 (vCPU)** | **16 核心 (vCPU)** |
| **推荐 内存 (RAM)** | **8 GB** | **16 GB** | **32 GB** |
| **推荐 磁盘 (SSD)** | **100 GB NVMe / High-Speed SSD** | **200 GB NVMe / High-Speed SSD** | **500 GB NVMe / High-Speed SSD** |
| **推荐 上行带宽** | **5 Mbps** | **10 Mbps** | **20 Mbps+** |
| **推荐 部署架构** | 单机部署 (Windows Server / Docker) | 单机多进程 (Nginx + 4 Worker) | 高性能单机多进程 / 容器化集群 |
| **预估平均匹配吞吐量**| ~120 行 / 秒 | ~300 行 / 秒 | ~600+ 行 / 秒 |

## 三、 详细容量与性能推演

### 3.1 20 人规模测算 (部门级)
* **业务特点**：日常以暖通、电气独立工程师单打独斗为主，峰值并发约 3 - 5 人。
* **内存计算**：基准 2 GB + 5 并发 × 400 MB + OS 预留 2 GB = **约 6.0 GB** $\rightarrow$ **推荐 8 GB RAM**。
* **CPU 计算**：4 核心可轻松支撑 3~5 人同时上传 1,000 行清单，平均比对响应时间在 **10~20 秒内** 完成。
* **磁盘**：主要是历史暂存 session 与基础库，100 GB NVMe 完全满足 1-2 年数据积累。

### 3.2 50 人规模测算 (工程公司级)
* **业务特点**：多专业工程师同时进行大型项目清单匹配，峰值并发约 8 - 12 人。
* **内存计算**：基准 2 GB + 12 并发 × 400 MB + OS 预留 3 GB = **约 9.8 GB** $\rightarrow$ **推荐 16 GB RAM**。
* **CPU 计算**：8 核心配置下，使用 Gunicorn/Uvicorn 启动 4-6 个 Worker 进程，保障高并发下请求不排队。
* **磁盘 IOPS**：由于多用户同时暂存进度与更新规则命中统计，强烈建议采用 **NVMe SSD**（读写 > 1500 MB/s），保障 SQLite WAL 写入不卡顿。

### 3.3 100 人规模测算 (集团采购中心级)
* **业务特点**：跨区域采购团队、预算员集中比对，高峰期并发约 15 - 25 人。
* **内存计算**：基准 2 GB + 25 并发 × 400 MB + OS 预留 4 GB = **约 16.0 GB** $\rightarrow$ **推荐 32 GB RAM**。
* **CPU 计算**：16 核心配置，启动 8-12 个 Worker 进程，多核并行处理向量点乘运算。
* **网络带宽**：导出标准 Excel 报告（单文件约 5MB - 15MB）时，20 Mbps 带宽可保障秒级下载。

## 四、 生产环境优化部署建议

1. **磁盘介质要求**：
   - 强烈建议使用 **NVMe 固态硬盘**。系统使用的是 SQLite 数据库（WAL 模式），高并发写入时磁盘 IOPS 是决定锁表体验的关键。
2. **操作系统选择**：
   - **Linux (Ubuntu 22.04 LTS / Rocky Linux 9)**：推荐生产环境使用，内存利用率比 Windows 高约 15%-20%，且 PyTorch/OpenBLAS 在 Linux 下多线程开销更小。
   - **Windows Server 2019/2022**：若必须在 Windows 部署，建议配置 16GB 以上内存以抵消系统自身开销。
3. **大模型网络连通性**：
   - LLM 规则生成功能依赖外网调用（阿里云 DashScope / DeepSeek API），服务器需具备访问公网 HTTPS (端口 443) 的能力。若处于纯内网环境，大模型规则生成模块需配置内网私有化模型网关。
