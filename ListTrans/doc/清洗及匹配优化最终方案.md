# 华康洁净物料清单清洗与匹配引擎优化最终方案

## 1. 概述与核心约束

根据广联达清单清洗与物料库匹配架构规范，以及对前几阶段用户反馈的深入分析，我们实施了对清单数据清洗解析（Parser）和检索匹配（Matcher）模块的深层次技术优化。

**核心约束**：
* **不改变现有软件的任何操作界面、交互逻辑、按钮功能、页面布局及用户操作路径**。
* 保留原有的 Web 工作台界面，所有特征剥离、硬冲突阻断以及参数批量对齐逻辑在后台底层模块中无缝生效。

## 2. 优化方案核心技术实现

### 2.1 清洗模块（Parser）深层提取规则优化
为了能够更细粒度地分析材料规格特征，避免语义和模型混淆，我们对 [app/preprocessor.py](file:///c:/Users/wangd/project/ListTrans/app/preprocessor.py) 进行了以下两项核心优化：

1. **多维度物理量参数拆分（给排水/纯水/医气）**：
   * **需求背景**：如“PSP钢塑复合管，DN65（75*5.5）”，需要单独识别材质、内径（公称管径）、外径和壁厚。
   * **技术实现**：新增括号表达式嵌套的正则提取模式：`r'(?:DN|de|Ф|Φ|管径|口径)\s*(\d+)\s*[（(]\s*(\d+(?:\.\d+)?)\s*[*x×]\s*(\d+(?:\.\d+)?)\s*[）)]'`。
   * **解析输出**：对于上述特征，系统现可精准识别并剥离输出：
     * `材质` = `"PSP钢塑复合管"` (将材质词典扩充以全面覆盖 `PSP` 复合材料系列)
     * `管径` = `65` (对应 `DN65` 内径)
     * `外径` = `75.0`
     * `壁厚` = `5.5`
   * 这些剥离出的属性均会作为独立维度呈现在前端特征栏，支持独立启用/禁用。

2. **型号提取的“排干/规格过滤”规则**：
   * **需求背景**：过去经常发生“复合管”和“液位计”因为规格描述里都包含 `"DN65"` 或 `"DN50"`，从而被误判为“型号完全吻合”导致高分错配。
   * **技术实现**：在 `extract_model` 提取函数中新增排干过滤。若正则提取到的型号值以 `DN`、`De`、`PN`、`Ф`、`Φ` 等标准尺寸或压力前缀开头，则直接**判定为规格特征而非型号，做过滤忽略处理**。从根本上杜绝了尺寸单位引发的型号匹配偏置。

### 2.2 匹配模块（Matcher）三硬阻断规则优化
我们在 [app/matcher.py](file:///c:/Users/wangd/project/ListTrans/app/matcher.py) 顶部引入了硬性过滤约束函数，并在 `score_candidate` 入口处执行“硬阻断”，一旦冲突直接返回 `0.0` 得分，不再进入后续的打分运算，不仅消除了跨专业/跨品牌错配，还节省了 CPU 相似度计算损耗。

1. **专业冲突阻断**：
   * **机制**：基于数据库物料表 `category` 字段和规格描述，使用判定规则对候选库物料进行专业分类归纳（强电/弱电/给排水/暖通/医气/纯水/装饰）。
   * **阻断规则**：如果清单行所属专业与候选物料所属专业不一致（且两者均非通用类别），直接触发 `专业冲突阻断`，强制得分为 `0.0`。
   * **示例**：杜绝了“给排水”专业的复合管去匹配“弱电/暖通”专业的液位计。

2. **品牌冲突阻断**：
   * **机制**：引入品牌标准化映射器 `standardize_brand`，将同义词（如“华为/huawei”，“大华/dahua”）做统一标化。
   * **阻断规则**：若原始清单列或项目特征中指定了特定品牌，而物料库候选项也指定了不同的标化品牌，直接触发 `品牌冲突阻断`，强制得分为 `0.0`。

3. **单位不可换算阻断**：
   * **机制**：定义了 5 大核心单位换算族（长度族、面积族、重量族、体积族、数量族）。
   * **阻断规则**：若清单行与候选物料的单位均不为空，且它们不属于同一个可换算换算族，直接触发 `单位不可换算阻断`，强制得分为 `0.0`。
   * **示例**：避免了单位为 `米`（长度族）的管材去匹配单位为 `台`（数量族）的泵阀设备。

### 2.3 前端交互修补：特征同步与保留
* **需求背景**：用户在特征过滤区域勾选/启用特征并点击“批量应用”后，同类相似行的其他未重叠特征被重置为 `false`，导致全部特征被取消。
* **技术实现**：优化了 `web/app.js` 的 `batchApplyParamsAndRematch` 逻辑。在批量更新同名设备的 `active_params` 时，仅同步当前选定设备行明确做过开启/关闭操作的属性状态；对于相似设备行原本独有的其他规格特征，**默认保持 `true`（启用）状态**，彻底解决了“批量应用取消所有特征”的缺陷。
