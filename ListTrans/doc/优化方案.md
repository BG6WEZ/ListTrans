# 企业物料清单智能匹配工具优化技术方案 V2.1（终稿）
## 文档元信息
- 文档版本：V2.1 正式终稿
- 编制日期：2026-07-14
- 文档用途：项目正式落地技术实施文档、评审验收依据、开发交付标准
- 适用系统：企业通用物料清单智能匹配转换平台（暖通/电气/给排水多专业）
- 核心优化目标
  1. 匹配综合成功率由基线60%提升至≥85%；带完整型号物料匹配成功率≥95%；纯语义场景匹配成功率≥70%
  2. 性能扩容支持最大2000行清单批量处理，严格控制响应耗时与内存占用
  3. 维持原有SQLite+FastAPI单文件轻量架构，不新增独立中间件、无集群运维成本
  4. 完善全链路容错、运维便捷性、人工交互兜底、长期自迭代能力

## 一、项目现状与核心痛点
### 1.1 现有系统基础架构
系统采用 Python FastAPI 后端 + 原生前端 + SQLite FTS5 全文检索轻量化架构，标准业务流程：
1. 用户上传Excel物料清单；
2. 后端提取规格文本，通过SQLite FTS5单轮关键词检索召回候选物料；
3. 固定30%/30%/30%静态权重执行相似度打分；
4. 返回Top3物料推荐至前端人工确认；
5. 确认后回写标准Excel模板导出。

### 1.2 当前业务与技术痛点
1. **召回能力不足**
    - FTS5分词器对工业型号、管径拆分失真，精确型号无法命中；
    - 仅依靠关键词检索，俗称、语序变体、语义等价物料无召回通道，存在固定准确率天花板；
    - 单轮召回候选覆盖量不足，复杂多专业清单易丢失正确物料。
2. **文本与参数解析能力薄弱**
    - 无行业别名纠错、单位统一转换逻辑，CMH/m³/h、DN/dn/Φ被识别为不同参数；
    - 未区分专业正则规则，区间参数（风量3000~5000）无法标准化提取；
    - 修饰停用词干扰相似度计算，放大匹配噪声。
3. **打分机制不符合工业业务逻辑**
    - 固定静态权重无法适配「完整型号」「无型号仅参数」「仅名称描述」三类清单场景；
    - 线性参数偏离度扣分，无法适配行业公差标准，次要尺寸偏差拉低核心参数完全吻合物料得分；
    - 缺少品类、介质、管径互斥过滤规则，无关物料挤占推荐席位。
4. **大批量处理性能瓶颈**
    - 原有串行处理逻辑，500行以上清单前端卡顿，不支持2000行超大清单业务场景；
    - 无并发、分片、超时熔断机制，超大文件易出现接口超时、内存溢出。
5. **运维与迭代能力缺失**
    - 物料库更新需重启服务全量重建检索索引，等待耗时久；
    - 无离线部署方案，内网环境无法加载语义模型；
    - 行业规则修改需线下编辑配置文件并重启服务，无可视化配置入口；
    - 人工校对修正记录无法沉淀，系统无自主优化迭代能力。
6. **前端人工校对效率低**
    - 无匹配依据可视化展示，操作人员无法快速理解算法推荐逻辑；
    - 缺少参数手动补全重匹配功能，非标缺失参数清单只能完全手动检索。

### 1.3 优化硬性约束条件
1. 存储约束：唯一持久化存储为SQLite，禁止引入PostgreSQL、Elasticsearch、Milvus、Redis等独立服务；
2. 部署约束：保持单目录、单文件部署形态，支持pip一键启动，无需Docker、集群部署；
3. 资源约束：语义向量索引内存增量≤250MB，整机进程内存峰值可控；
4. 推理约束：不接入实时大模型LLM推理，所有非标场景依靠前端人工交互兜底，规避模型幻觉与性能损耗；
5. 通用约束：暖通、电气、给排水规则全部配置化，无专业硬编码；
6. 性能约束：兼容最大2000行清单批量处理，单行匹配耗时≤150ms。

## 三、核心模块详细设计
### 3.1 文本标准化预处理模块
#### 3.1.1 五级标准化处理流水线
1. **符号清洗标准化**：全角字符统一转为半角，清除不可见控制字符、多余空格，统一分隔符格式；
2. **行业别名与错别字修正**：读取配置词典自动替换俗称、笔误、字符混淆，示例：
    - 新风柜→新风机组、风两→风量、余亚→余压、DN8O→DN80；
3. **参数单位归一化**：统一行业参数计量单位，转换规则固化配置：
    - 风量：CMH/立方米每小时 → m³/h；功率：kw/KW/千瓦 → kW；管径：Φ/dn → DN；
4. **停用修饰词过滤**：剔除无匹配价值商业修饰词（定制、升级款、含支架、全新、标准型等）；
5. **分专业结构化参数抽取**
    - 根据清单品类自动加载暖通/电气/给排水独立正则表达式库；
    - 识别区间参数（如3000~5000风量），自动取区间中值参与打分；
    - 输出结构化参数字典，未识别参数标记为`None`，用于后续动态权重切换。

#### 3.1.2 配套能力
- 行业词典支持前端在线编辑，保存后实时热加载，无需重启服务；
- 输出结构化数据：清洗后标准文本、结构化参数集、型号、品类识别标记、缺失参数标记，供给召回、打分、前端全链路复用。

### 3.2 FTS5+FAISS双路混合召回引擎
#### 3.2.1 两路并行召回策略
1. **路径A：关键词召回（SQLite FTS5）**
    - 执行FTS5 BM25全文检索，召回Top300关键词相关物料；
    - 新增独立型号普通索引，针对提取到的型号执行`LIKE`前缀匹配，修复型号分词拆分失真问题；
    - 两路合并后关键词来源候选上限800条；
2. **路径B：内存语义向量召回（FAISS）**
    - 采用轻量级CPU友好语义模型`paraphrase-multilingual-MiniLM-L12-v2`，输出384维稠密向量；
    - FAISS选用IndexFlatIP暴力内积索引，无近似召回损失；单次检索召回Top200语义相近物料；
3. **候选池合并规则**
    - 对两路召回物料编码去重合并，总候选池上限800条；
    - 每条候选标记召回来源（精确型号匹配/关键词检索/语义匹配），作为打分正向加分依据。

#### 3.2.2 向量索引运维优化（适配物料库频繁更新场景）
1. **离线模型部署**：项目内置完整离线模型压缩包，内网无外网环境可直接加载，无需在线下载；
2. **增量索引更新**：物料库少量新增、修改物料时，仅增量编码向量并追加至索引，无需全量重建，单次增量耗时≤30s；
3. **双模式索引刷新**
    - 自动刷新：系统启动时比对SQLite数据库文件时间戳，检测物料库变更自动重建索引；
    - 手动刷新：提供后台API接口`/api/refresh_vector`，支持不停服更新向量索引；

#### 3.2.3 资源管控标准
4.6万条全量物料向量内存占用≤200MB，系统内存峰值上限控制250MB，满足部署约束。

### 3.3 自适应动态权重+阶梯公差打分引擎
#### 3.3.1 三场景动态权重分配逻辑
系统根据预处理输出的型号、参数完整度自动切换打分权重，底层计算采用0~1归一化小数，对外输出0~100直观百分制置信分：
1. **场景A：清单包含完整设备型号**
    型号匹配分50%、参数偏离度分30%、文本相似度分20%、语义向量附加分20%、基础属性分10%；
2. **场景B：无完整型号，但提取到核心物理参数**
    参数偏离度分50%、文本相似度分30%、型号匹配分10%、语义向量附加分20%、基础属性分10%；
3. **场景C：仅设备名称，无型号、无数值参数**
    文本相似度分60%、语义向量附加分30%、型号匹配分5%、参数偏离度分5%（参数缺失不扣分）。

#### 3.3.2 工业阶梯公差计分规则
针对参数偏离度替换原有线性扣分逻辑，适配行业公差标准：
1. 预设行业公差：风量T=15%、功率T=10%、管径DN T=0%；
2. 实际偏离度`D = |查询值-物料标准值| / max(查询值,物料标准值)`；
3. 计分阶梯：
    - D ≤ T：该参数维度得满分；
    - T ＜ D ≤ 2T：得分线性递减至0.5；
    - D ＞ 2T：最低保留0.1分，不完全淘汰物料；
4. 缺失参数处理：查询或物料缺失同一参数时，该维度不参与加权计算，不产生扣分。

#### 3.3.3 正负向Boost偏置规则
在基础加权总分基础上叠加业务偏置，拉大正确物料与噪声物料分差：
##### 正向加分项
- 型号完全精确匹配：+0.15
- 全部核心参数偏差在公差范围内：+0.10
- 物料品类与清单识别品类一致：+0.08
- 型号属于同一产品系列：+0.05
- 品牌完全匹配：+0.05

##### 负向扣分项
- 品类强冲突（风机vs冷水机组）：-0.30
- 介质不匹配（冷水vs热水）：-0.20
- 管径完全不符（DN100 vs DN50）：-0.30
- 核心参数偏离度超过2倍公差：-0.15

#### 3.3.4 分层过滤与排序输出
1. 所有候选按总分降序排序，保留前200条；
2. 执行业务互斥规则过滤，剔除强冲突低置信物料；
3. 输出Top10完整候选集合，前端默认展示Top3，支持展开查看全部10条；
4. 每条候选附带`match_reasons`标签集合，用于前端展示匹配依据。
5. 同清单批量匹配增加系列聚类优化：同等得分下，与已确认物料同系列条目优先置顶。

### 3.4 2000行超大清单并发分片处理与全链路容错
#### 3.4.1 分片并发处理机制
1. 线程池配置：固定10个并发处理线程，支持配置文件动态调整；
2. 分片策略：单次批量处理上限500行，2000行清单自动拆分为4个分片串行调度线程池；
3. 线程安全保障：SQLite采用线程本地独立连接，FAISS索引仅提供只读检索，无共享资源竞争；
4. 结果整合：分片处理完成后按原始行号重组结果，保证清单顺序不打乱。

#### 3.4.2 全链路降级容错策略
1. FAISS索引加载失败：自动降级为纯FTS5关键词检索，打印告警日志，业务流程不中断；
2. 单行匹配500ms超时熔断：临时关闭语义向量检索，仅使用关键词召回返回结果；
3. 参数全部抽取失败：强制切换场景C权重，避免无候选返回；
4. SQLite只读保护：所有匹配查询均为只读操作，不会修改物料库原始数据；
5. 低置信拦截：物料置信分＜40分时，前端强制标记红色未匹配，引导人工干预；
6. 内存过载保护：进程内存接近250MB阈值时，自动缩减并发线程数量，降低内存占用。

#### 3.4.3 硬性性能指标标准
| 性能指标 | 约束标准 |
| ---- | ---- |
| 单行匹配端到端平均耗时 | ≤150ms |
| 单分片500行批量处理总耗时 | ≤5s |
| 2000行完整清单分片处理总耗时 | ≤18s |
| FAISS全量索引构建耗时 | ≤5min；增量更新≤30s |
| 向量索引内存占用 | ≤200MB，进程峰值上限250MB |
| Excel模板导出生成耗时 | ≤2s |

### 3.5 前端工作台交互与自学习迭代模块
#### 3.5.1 工作台核心交互功能
1. **清单三色状态看板**
    - 绿色：精确匹配/人工确认绑定编码；黄色：算法推荐待校对；红色：低置信未匹配；
    - 顶部全局进度条展示已确认行数/清单总行数，支持2000行清单实时渲染；
2. **参数补全弹窗**
    点击红色/黄色行可弹出模态框，支持编辑、补充风量、功率、管径、型号等关键参数，提交后实时重匹配刷新候选列表；
3. **匹配理由可视化彩色标签**
    - 蓝色标签：型号吻合；绿色标签：参数一致；紫色标签：语义相近；灰色标签：品类匹配；
    - 每条物料卡片展示2个权重最高的匹配理由；
4. **全局人工检索入口**：支持绕过算法，直接全库检索物料手动绑定编码；
5. **前端本地缓存**：人工校对记录存储sessionStorage，页面刷新不丢失操作记录。

#### 3.5.2 自学习迭代闭环（系统长期优化能力）
1. 操作员手动修正、替换算法推荐物料后，前端自动提交正负匹配样本至后端；
2. 后台定时任务解析样本数据，自动生成行业别名、错别字、参数公差优化建议；
3. 前端配套样本审核面板，业务人员一键确认规则自动写入配置文件，实时生效；
4. 按月沉淀样本，持续提升系统匹配准确率。

#### 3.5.3 可视化行业配置后台
新增独立配置页面，无需线下修改配置文件，在线编辑以下内容：
- 单位转换映射表、行业别名/错别字词典；
- 暖通/电气/给排水参数公差标准；
- 打分权重模板、Boost加分扣分项阈值；
- 停用修饰词列表。

### 3.6 Excel标准报表回写生成模块
1. 模板隔离处理：加载标准Excel模板后，清空历史数据，仅保留表头与未参与匹配的历史行；
2. 样式完整复刻：写入数据行完全复制模板字体、边框、填充色、数字格式；
3. 历史价格自动回填：读取模板内物料编码-单价映射，自动填充价格列；
4. 全局序号重组：匹配行与保留行合并后，序号连续递增排版；
5. 数据合法性校验：人工绑定的物料编码不存在于物料库时，前端弹出明确错误提示，禁止导出；
6. 导出日志记录：成功写入行数、价格回填行数、未匹配行数。

## 四、系统全业务流程
### 4.1 服务启动初始化流程
1. 加载前端可配置行业规则（词典、公差、权重）；
2. 读取项目内置离线语义模型，完成模型加载；
3. 建立SQLite数据库连接，校验业务表、FTS5虚拟索引完整性；
4. FAISS向量索引初始化：
    - 索引缓存文件有效且物料库未变更，直接加载缓存（耗时1~2s）；
    - 缓存失效执行增量/全量向量编码，重建内存索引；
5. 初始化批量处理线程池、自学习样本定时任务；
6. 启动FastAPI服务，监听前端接口请求。

### 4.2 单行实时匹配流程
1. 接收前端传入原始规格文本、可选手动补全参数；
2. 文本预处理模块执行清洗、参数结构化抽取；
3. FTS5关键词、FAISS语义两路并行召回，合并去重生成候选池；

## 八、全链路风险兜底机制
1. FAISS向量库加载失败：自动关闭语义召回，仅保留FTS5关键词检索，日志告警；
2. 离线语义模型读取失败：系统禁用向量召回通道，基础关键词匹配正常运行；
3. SQLite数据库文件损坏：服务启动抛出明确告警，禁止进入匹配业务流程，提示运维修复数据库；
4. 进程内存接近250MB阈值：自动下调并发线程数量，控制内存峰值，防止OOM崩溃；
5. 批量处理分片文件损坏：跳过异常分片，正常分片正常输出，前端展示异常行标记人工处理。

## 九、核心技术决策汇总
1. 保留SQLite+FTS5作为基础检索底座，内嵌FAISS内存向量索引，全程不引入独立中间件，维持单文件轻量化部署；
2. 采用关键词+语义双路并行召回，补充型号前缀索引，解决型号分词失真、语义物料召回丢失问题；
3. 基于清单信息完整度实现三场景动态权重，搭配工业阶梯公差计分，贴合工程物料匹配业务逻辑；
4. 分片+10线程并发架构，原生支持最大2000行超大清单批量处理，严格管控响应耗时；
5. 不接入实时LLM大模型推理，依靠前端参数补全弹窗作为人工兜底方案，规避推理延迟与模型幻觉风险；
6. 分阶段迭代落地，快速上线基础优化能力，同时完整架构保障长期稳定运维；
7. 配套离线模型、增量索引、可视化配置、人工样本自学习四大长效运维能力，支撑系统持续迭代优化。
