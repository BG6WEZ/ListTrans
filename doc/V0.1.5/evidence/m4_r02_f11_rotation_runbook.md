# V015-M4 / F11 外部与持久化凭据轮换操作及核验指南（R02 更新）

> 适用范围：授权运维/统筹方对生产及云端环境历史暴露凭据进行实际轮换与验证。本指南不执行远端操作，亦不含任何真实凭据或主机信息。

## 1. 两类凭据机制的核心区别（防误判说明）

1. **启动环境变量 `ADMIN_PASSWORD`（仅首次引导有效）**
   - `app/auth_manager.py:init_auth_db()` 仅在认证库尚无 `role='admin'` 账号时消费一次 `ADMIN_PASSWORD` 创建初始管理员。
   - **关键结论**：当持久化认证库（`auth.db`）已存在管理员记录时，仅修改 `.env` 或容器环境变量中的 `ADMIN_PASSWORD` 并重启服务，**不会**改写数据库里已有的 `admin` 密码哈希，旧密码依然可以登录！

2. **既有持久化数据库账号轮换（必须走数据库重置/改密流程）**
   - 对已经落盘在 `auth.db` 的管理员/员工账号进行历史凭据失效，必须执行以下任一持久化路径：
     - **管理员重置**：已认证管理员调用 `PUT /api/admin/users/{user_id}/password`（系统在事务内自动签发全库唯一高熵随机临时口令、写入新哈希、置 `must_change_password = 1` 并递增 `token_version`，立刻作废该账号全部既有 JWT 会话）；随后操作员使用临时口令登录并强制改密为新口令。
     - **本人改密**：已认证账号持有当前有效口令，调用 `PUT /api/auth/profile`（输入 `old_password` 与 `new_password`）写入新强口令，原子置 `must_change_password = 0`、递增 `token_version` 并注销当前会话 `jti`。

3. **禁用误用 `must_change_password = 1` 作为已轮换证明**
   - `must_change_password = 1` 仅表示账号“待改密”状态标记，不证明旧密码哈希已被替换或旧密码已被拒绝；**必须实际验证旧密码调用 `POST /api/auth/login` 被拒绝（返回 `400`/非 `200`）且轮换前旧 Token 返回 `401`**。

## 2. 授权方逐项轮换与强制核验清单

| 凭据对象 | 轮换动作 | 必需核验（全部实测通过方可签收） |
|---|---|---|
| **应用 JWT 签名密钥 `SECRET_KEY`** | 在目标环境 `.env` 生成 ≥32 字节强随机密钥（`openssl rand -hex 32`）并重启服务 | 1) 旧密钥签发的历史 Bearer Token 访问 `/api/auth/me` 返回 `401`；<br>2) 新登录获取 Token 访问 `/api/auth/me` 返回 `200`；<br>3) 清空 `SECRET_KEY` 启动生产容器触发 fail-closed 非零退出 |
| **持久化库 `admin` 及受影响员工账号口令** | 对既有 `auth.db` 中每名相关账号执行“管理员重置或本人改密 + 强制换新”；不得仅改 `.env` 的 `ADMIN_PASSWORD` | 1) 使用轮换前旧口令调用 `POST /api/auth/login` 必须被拒绝（当前接口返回 **`400`**，不得放行）；<br>2) 轮换前旧 Bearer Token 调用 `/api/auth/me` 必须返回 **`401`**；<br>3) 使用最终新口令登录成功（且 `must_change_password=false`）并访问 `/api/auth/me` 返回 `200` |
| **云主机 SSH 凭据 / 运维密钥** | 更换 SSH 登录口令或轮换 ED25519 密钥对、从 `authorized_keys` 删除旧公钥，更新部署侧环境变量 `DEPLOY_SSH_KEY_PATH` / 凭据注入 | 1) 使用旧密钥/旧口令登录目标主机拒绝；<br>2) 新私钥 SSH 连通成功（禁用 `AutoAddPolicy`，使用已知主机指纹校验） |
| **LLM 服务商 API Key（`LLMProviderManager` / `.env` / 控制台）** | 在外部平台（如硅基流动）签发新 Key 并作废旧 Key；同步更新 `llm_providers` 节点配置 | 1) 旧 Key 调用外部推理接口返回鉴权失败（`401`）；<br>2) 新 Key 连通正常且日志、响应与配送清单零明文泄露 |

## 3. F11 外部实操签收证据格式要求

- 授权方实际执行轮换后，应保存“脱敏核验记录”（仅记录时间戳、账号代号/指纹前缀、状态码 `401/200` 及外部控制台吊销回执，严禁记录任何明文密钥、密码、Token 原文或公网主机真实口令）。
- 在授权方完成并提交实操核验前，F11 仅可视为“代码与镜像配置边界已整改，外部真实凭据轮换待授权方签收验证”，不得单方关闭。
