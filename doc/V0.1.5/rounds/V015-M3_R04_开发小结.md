## 本轮完成

严格按 R03 统筹裁决仅闭环剩余 P1（`A-M3-01` 历史记录客户端 `unit` 与服务端权威证据来源混淆漏洞），不改其他已关闭分支（`A-M3-02`/`03`/`04`/`05`），未调权、未改模型、未触及暂挂 `R-M3-01`（P2）：

1. **`A-M3-01`（P1）区分单位值与服务端权威确认证据来源**
   - [app/binding_decisions.py](../../../app/binding_decisions.py)：
     - 新增常量 `UNIT_EVIDENCE_VERSION = "r04-v1"`、`UNIT_EVIDENCE_SOURCE = "server_live_material"`、`_AUTHORITATIVE_UNIT_EVIDENCE_KEYS`，以及严格正有限浮点数判定 `_to_strict_positive_float`（拒绝 `bool`、字符串、`NaN`/`Inf`、`<= 0`）；
     - 拆分并加固 `_validate_saved_binding_unit_evidence`：在强证据模式（`require_saved_unit_evidence=True`，由 [app/server.py](../../../app/server.py) 的 `_annotate_restored_items` 与 `_gate_export_row` 传入）下**绝不**将 `sb.get("unit")` 降级/伪升格为 `confirmed_unit`；仅凭旧客户端 `unit`（即使非空，如 `"km"`）或缺失/部分/类型异常/自相矛盾的 `confirmed_*`（需完整包含非空字符串 `confirmed_unit`、非空字符串 `confirmed_orig_unit`、正有限 `confirmed_unit_mult`，且与原行 `original_unit`/`original_qty` 及实时 `materials.unit` 自洽一致，并校验证件元字段 `confirmed_unit_source`、`confirmed_unit_version`）一律阻断恢复为 `recommended` 并拒绝导出（422）；
     - 加固 `_enrich_saved_bindings`：落盘前先剔除请求中可能挟带的 `_AUTHORITATIVE_UNIT_EVIDENCE_KEYS`，且**仅当实时物料库存在且 `materials.unit` 非空**时写入 `confirmed_unit = live_unit`（不再回退 `req_unit`）、`confirmed_orig_unit`、`confirmed_orig_qty`、`confirmed_unit_mult`、`confirmed_unit_source` 与 `confirmed_unit_version`；空单位物料无法借客户端 `unit` 或伪造字段洗白出权威证据。
   - [app/server.py](../../../app/server.py)：保持 R03 对 `_annotate_restored_items` 与 `_gate_export_row` 传入 `require_saved_unit_evidence=True` 的强证据校验调用；确认状态与导出校验均只从 SQLite `binding_decisions.payload_json` 读取 `saved_bindings`，请求端篡改或补填 `unit`/`confirmed_*` 无法提升旧确认资格。

2. **R04 正式回归新增（+4 项，M3 专项 95 → 99，全量 241 → 245）**
   - [tests/test_m3_hard_constraints.py](../../../tests/test_m3_hard_constraints.py) 新增 `TestM3R04LegacyUnitEvidenceUnit`（3 项单测）：
     - `test_r04_legacy_nonempty_unit_without_confirmed_fields_blocked`：覆盖历史非空 `unit="km"`、历史空 `unit=""`、历史缺 `unit`、漂移前后及客户端伪造证据变体在强证据门下全阻断；
     - `test_r04_partial_malformed_and_inconsistent_confirmed_fields_rejected`：覆盖仅部分 `confirmed_*`（如仅 `confirmed_unit` 或缺 `confirmed_unit_mult`）、类型异常（`int`/`bool`/`str`/`<=0`/`NaN`）、伪造 `confirmed_unit_source`/`confirmed_unit_version` 及自相矛盾换算上下文一律拒绝，同时对照完整权威证据正例通过；
     - `test_r04_record_decision_strips_forged_evidence_and_derives_from_live_material`：验证 `record_decision` 清除客户端伪造 `confirmed_*` 并严格按实时物料持久化权威上下文，且空单位物料不会生成权威证据。
   - [tests/test_m3_hard_constraints_http.py](../../../tests/test_m3_hard_constraints_http.py) 新增 `TestM3R04LegacyUnitEvidenceHttp`（1 项真实 FastAPI HTTP / SQLite / `openpyxl` XLSX 端到端闭环）：
     - 直接写入不含 `confirmed_*` 仅含客户端 `unit="km"`（`10 km -> 10000, ratio=1000`）的 R01 风格 `binding_decisions` 历史记录，验证在实时物料为 `m`（漂移前）及 `km`（漂移后）两种状态下，无论客户端提交 `unit="km"` / `"m"` / `""` 还是伪造 `confirmed_*`，`/api/session/annotate` 全部降级为 `recommended`（`downgraded >= 1`）、`/api/export` 全部拒绝（422）；
     - 同步覆盖历史空 `unit`、仅部分 `confirmed_*`、伪造 `confirmed_unit_version` 记录的恢复降级与导出 422；
     - 按当前实时 `unit="m"` 物料经 `/api/binding/submit` 显式重新确认后恢复为 `manual_confirmed`（`downgraded=0`）并成功导出 200（`openpyxl` 重读 XLSX 验证原行 `10 km`、目标 `10000 m`）；随后再次漂移 `m -> km` 仍阻断；并附带合法 1 倍率一对多系数（`200 米 -> 300 m, qty_ratio=1.5`）正常确认、恢复与导出 XLSX 重读 200 对照。
