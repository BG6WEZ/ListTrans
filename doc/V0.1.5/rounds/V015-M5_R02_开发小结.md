## FM5 断言修正专节（裁决第 15 行强制逐条记录）

裁决仅授权修正"超时立即解锁"这一项与锁安全要求冲突的不安全预期，原故障、恢复与 owner 单次释放覆盖全部保留，另新增真实互斥覆盖。未借此删除任何其他失败断言、金标难例或降低门禁。

- **修改位置**：[tests/test_m5_file_boundary_and_compat.py](../../../tests/test_m5_file_boundary_and_compat.py) 的 `test_f24_db_upload_lock_concurrency_all_5_failure_modes_and_recovery`（L609）Failure Mode 5。
- **R01 旧断言（备件版 L712-716，超时后立即断言解锁，属不安全预期）**：

```python
assert st5["status"] == "failed" and "超时" in st5["error"]
assert not server._db_import_lock.locked()
time.sleep(0.4)
# Slow thread exited cleanly without late overwrite; task status remains failed
assert late_write_attempted == []
assert client.get(f"/api/upload/status?task_id={r_f5.json()['task_id']}", headers=headers).json()["status"] == "failed"
```

- **R02 新断言（当前版 L711-721，worker 存活期间互斥锁保持占用，退出后才释放）**：

```python
assert st5["status"] == "failed" and "超时" in st5["error"]
# A-M5-02 (R02 ruling-authorized correction of the old unsafe expectation): the
# timed-out worker thread is still alive here, so the write mutex must stay owned
# instead of being released before the worker actually exits or isolates itself.
assert server._db_import_lock.locked()
time.sleep(0.4)
# Slow thread exited cleanly without late overwrite and released the owner token
# exactly once; task status remains failed.
assert not server._db_import_lock.locked()
assert late_write_attempted == []
assert client.get(f"/api/upload/status?task_id={r_f5.json()['task_id']}", headers=headers).json()["status"] == "failed"
```

- **保留项与覆盖去向**：409 并发拒绝与 `release_for_token` True/False 单次释放保证原样保留（L627-629）；Failure Mode 1～4（流式保存失败 500、同步预检失败 400、调度失败 500、导入异常可查询 failed）断言全部未动；`late_write_attempted == []` 晚写拦截、任务终态 failed、末尾恢复导入 completed 且 `query_by_code("M5-MAT-001")` 可读（L723-733）均保留。
