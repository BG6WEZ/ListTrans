## 本轮整改（逐项对应 R01 审核发现）

### A-M0-01（P1）llm_client 硬编码生产库且导入即建表

- [app/llm_client.py](../../../app/llm_client.py)：
  1. 物料库路径接入 `MATERIALS_DB_PATH`，新增 `_DEFAULT_DB_PATH`（原 `app/materials.db` 默认值保留为 fallback）与实时解析函数 `_resolve_db_path()`（每次读取环境变量，保证 conftest 在模块导入后注入的变量生效）；三处 `sqlite3.connect` 全部改走该函数。
  2. 消除模块导入期实例化：删除模块级 `llm_client = QwenLLMClient(...)`，改为 PEP 562 模块级 `__getattr__` + `_get_llm_client()` 惰性单例，首次访问 `llm_client` 属性时才构造，导入阶段不再触发 `init_cache_table()` 建表写库；现有调用方均为函数内访问，行为兼容。
- [tests/test_llm_integration.py](../../../tests/test_llm_integration.py)：`setUp()` 改为强制断言 `MATERIALS_DB_PATH` 已注入（未注入即失败，禁止连业务库），`DELETE FROM llm_cache` 仅作用于隔离库，sqlite 连接包 `try/finally` 关闭。
- 静态佐证：AST 探针确认模块级 `QwenLLMClient(...)`/`init_cache_table()` 调用数为 0（本机缺 dotenv 无法 import 该模块，AST 仅作补充静态证据，不替代装齐依赖后的运行时复验）。

### A-M0-02（P1）llm_rule_engine 导入即写库与 uploads/sandbox/eval 路径未隔离

- [app/llm_rule_engine.py](../../../app/llm_rule_engine.py)：
  1. 删除顶层无条件 `init_rule_engine_db()` 调用；改为 `_initialized_db_paths` 集合 + `threading.Lock` 双检锁的惰性建表，首次实际 `get_db_conn()` 时按路径仅初始化一次，模块导入零写库副作用。
  2. `get_db_conn()` 与 `init_rule_engine_db()` 双护栏：`TESTING=1` 且解析到生产 `app/materials.db` 时立即抛 `RuntimeError`，杜绝测试态误写业务库；路径同样经 `_resolve_db_path()` 实时解析。
- [tests/test_auto_binding.py](../../../tests/test_auto_binding.py)：`test_report_generator_multirow` 强制断言隔离 `UPLOAD_DIR` 已注入，输出固定落 `UPLOAD_DIR/test_output_split.xlsx`（不再硬编码 `app/uploads`）；模板缺失改 `skipTest`；工作簿打开/删除纳入 `finally`，异常路径也保证清理。
- [app/flywheel_sandbox.py](../../../app/flywheel_sandbox.py)：沙箱克隆的配置源由固定生产 `config/` 改读 `CONFIG_DIR`（默认 fallback 仍为生产 `config/`），子进程 env 经 `os.environ.copy()` 注入隔离配置快照。
- [tests/eval_golden_set.py](../../../tests/eval_golden_set.py)：可写明细路径改读 `GOLDEN_DETAIL_FILE`（金标/基线本身只读、不重定向），不再固定覆盖 `tests/fixtures/golden_last_run.json`；业务模块保持函数内延迟导入。
- 运行时佐证（隔离 env 实测）：导入模块后隔离库 `db exists = False`；首次 `get_db_conn()` 后 `db exists = True` 且仅含规则引擎四表；`MATERIALS_DB_PATH` 指回生产库时 `get_db_conn()`/`init_rule_engine_db()` 分别抛护栏 `RuntimeError`。

### A-M0-03（P2）conftest 过度跳过与 verify 漏检

- [tests/conftest.py](../../../tests/conftest.py)：
  1. 废除 `MISSING_CORE_DEPS` 下对全部非 smoke 用例的一刀切 skip 与按 nodeid 关键字猜测依赖的回退规则；保留 `pytest_ignore_collect` 按 7 个重依赖模块的顶层导入依赖在收集前显式忽略，新增 `_RUNTIME_REQUIREMENTS` 模块映射，仅对运行期才触发重依赖链路的 `test_flywheel_sandbox.py`（faiss/sentence_transformers/pandas）显式 skip，smoke 豁免。R01 被误伤的 36 个纯标准库单测（31 项 Query 清洗/预处理 + 5 项 F25 规则引擎）现全部真实执行。
  2. 会话护栏重构为 `_check_module` 逐模块独立 try import 校验，补齐 `llm_rule_engine.DB_PATH`、`llm_client.DB_PATH`（优先调 `_resolve_db_path()` 取运行时实际值）、`feedback_train.FEEDBACK_FILE`；可写产物逃逸隔离根即失败，不可导入模块如实记「未校验」而非伪通过；布局新增 `GOLDEN_DETAIL_FILE` 注入。
- [tests/verify_isolation.py](../../../tests/verify_isolation.py)：拆除 pandas+fastapi 总闸门，6 个模块逐个独立导入做路径校验（同补三项），不可导入记 `status: 未校验` 环境缺口且不影响 verdict；顶部修正脚本运行时 `sys.path`（`python tests/verify_isolation.py` 时显式 insert 项目根，否则 `app.*` 无法导入）；布局同步 `GOLDEN_DETAIL_FILE`。
