## 一、阻断发现

### A-M4-01 / P1：Excel同步改变角色后，旧Token没有失效

位置：`app/auth_manager.py:409-417`，`import_users_from_excel`现有账号更新分支；对应F22。

同步直接更新`role`，没有比较旧角色或在同一事务递增`token_version`。在隔离SQLite中将已登录manager同步为employee，角色实际改变，`token_version`仍为2；使用同步前Token请求真实`GET /api/llm-rules`，前后均200，锁定验收要求同步后401。专用`admin_update_user_atomic`同样角色变更的对照则使旧Token返回401，证明是入口遗漏，不是测试身份失效配置问题。

复现中的Excel解码器替换为合成行提供器，未读取真实人员文件；账号更新、JWT校验、HTTP依赖和SQLite均为真实实现。证据：[探针源码](../evidence/m4_r01_audit_probes.py)、[结果：excel_role_change_old_token / admin_role_change_token_control](../evidence/m4_r01_audit_probes.json)。整改须覆盖所有角色/停用/重置入口，并用两个既有Token与新登录对照验证，不能只修管理页面。

### A-M4-02 / P2，当前验收阻断：服务层把“账号存在”当作“调用者已认证”，另有无操作者写入口

位置：`app/auth_manager.py:620-645`、`app/llm_rule_engine.py:760-768`、`app/server.py:897-906`；对应F04服务层门禁。

`resolve_verified_user`接受任意dict，按其中id/username查询账号后即返回数据库角色，没有认证凭据证明。构造仅含另一现有admin的id/username、且显式写`role=employee`的字典，不提供Token，`publish_rule`仍返回成功并把真实隔离规则写为published。另直接调用公开持久化入口`save_auto_binding_rules(rules)`省略`actor_user`，因条件只在非None时鉴权，全局绑定规则文件实际被写入。

**边界：这是下发要求中的直接服务调用反例；没有证明员工能仅靠HTTP正文伪造身份。** 同一规则的正常employee HTTP发布、全局绑定确认均403，HTTP角色依赖有效，因此本项按P2服务层缺口登记，但属于当前锁定验收，不延期。证据：[service_fabricated_existing_admin_identity / binding_persistence_missing_actor及HTTP对照](../evidence/m4_r01_audit_probes.json)。整改须要求真实验证的调用上下文，并让缺失/伪造/撤销上下文不能写入；持久化函数不能保留省略身份即放行的公开业务入口。

### A-M4-03 / P2，当前验收阻断：临时口令仍可由调用方设为多人共用

位置：`app/auth_manager.py:340,425,816,963`及`app/admin_api.py:19-43,60-95,149-165`；对应F22“唯一初始/重置凭据”。

默认随机生成分支有效，但保留显式password/default_password/new_password分支。通过真实admin HTTP为两个不同账号传入相同的合成强口令，创建均200，返回的临时口令只有1个不同值；对两账号重置为同一个合成强口令也均200、仅1个不同值。批量导入传显式强`default_password`同样使两人共用。强度合格和must_change_password=1不能替代唯一性。

证据：[http_shared_initial_and_reset_passwords / excel_shared_explicit_initial_password](../evidence/m4_r01_audit_probes.json)。证据仅记录数量/状态码，不包含临时口令。整改须消除共享入口或提供服务端可验证的唯一性保障；登录后本人自主改密不纳入“临时凭据”限制。保留合法创建/一次性交付/首次改密/旧会话失效正例。

### A-M4-04 / P1：Docker上下文与目录复制白名单仍存在敏感文件入口

位置：`.dockerignore`数据库/业务数据排除段、`Dockerfile:20-22`的`COPY config/`等目录复制；对应F11。

审核时Docker引擎已可连接（29.9.3），因此没有沿用开发时“离线”作为本轮环境事实。使用**完全合成的临时上下文**和交付原样`.dockerignore`，以`FROM scratch; COPY . /context/`真实离线构建并保存/检查层tar，发现：

| 合成对象 | 进入构建上下文 | 按生产COPY路径构建的scratch诊断层 |
|---|---|---|
| `.env`、`.env.production`、`app/auth.db`、WAL、人员XLS、脚本账号快照 | 否 | 否 |
| `app/auth.db.backup` | **是** | 否 |
| `data/audit_disabled_materials.csv` | **是** | 否 |
| `config/runtime_credentials.json` | **是** | **是** |

第二次离线构建复用生产Dockerfile的requirements/app/web/config复制路径，额外凭据canary进入了镜像层，说明“白名单目录”仍接收目录内新增敏感文件。`data/`属于既有业务快照保护目录，不能只排除xls而放行CSV；账号库备份也不能只靠排除`.db`/WAL覆盖。

证据：[离线探针源码](../evidence/m4_r01_audit_docker_probe.py)、[结构化结果/全部层路径/命令/哈希](../evidence/m4_r01_audit_docker_probes.json)、[上下文构建日志](../evidence/m4_r01_audit_docker_context.log)、[COPY路径构建日志](../evidence/m4_r01_audit_docker_copy_patterns.log)、[上下文层tar](../evidence/m4_r01_audit_docker_context.tar)、[COPY路径层tar](../evidence/m4_r01_audit_docker_copy_patterns.tar)。所有canary均是明确标记的合成字符串，未复制真实业务文件/秘密；不据此宣称真实凭据已经泄露。两次诊断构建并非生产依赖完整镜像，后者仍须在修复后实测。
