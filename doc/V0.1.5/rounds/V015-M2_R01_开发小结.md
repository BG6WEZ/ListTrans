## 实现与兼容性

| 文件 | 本包改动 |
|---|---|
| app/binding_decisions.py（新增） | 定义`recommended/auto_accepted/manual_confirmed/rejected`及决策来源；在隔离账号库维护服务端`binding_decisions`；提供行内容/完整绑定双指纹、当前编码新鲜查询、专业/品牌/单位硬冲突复核、确认/拒绝记录读写 |
| app/server.py | 匹配与规则结果统一四态；名称-only旧规则只推荐，约束逐项匹配且编码有效才自动接受；人工确认/拒绝使用真实鉴权与服务端记录；旧草稿保守恢复；导出逐行fail closed并返回行级原因 |
| app/session_manager.py | 幂等初始化绑定决策表；系统重置时级联清空，保留既有工作会话结构 |
| web/app.js | 显示与筛选只认`decision_status`；编辑、换绑定及重算使旧确认失效；确认使用服务端返回决定；恢复注释失败时保守降推荐 |
| tests/test_binding_decisions.py（新增） | 26项决策、确认、导出、真实HTTP/XLSX及草稿兼容回归 |
| tests/test_auto_binding.py | 名称-only旧规则不再自动接受；保留`M_001,M_002`及`300/160`一对多真实XLSX难例 |

`is_exact`仅保留算法提示，不再作为前端已确认显示、草稿恢复或服务端导出凭据。普通matcher候选、0分/无答案不自动预绑定；明确硬冲突不可自动接受或经伪造状态导出。DN100不会因DN15同名旧规则被接受。人工确认保存账号、`scope_key`、当前行内容、目标编码、数量/比例、双指纹和来源；确认后改行、改数量/比例或重算，旧记录不再命中。人工拒绝优先于同名自动规则，后续可重新选材并显式确认。

导出不默选top1。自动接受在导出时按当前规则、当前行数量重新推导完整绑定；人工确认必须命中服务端记录及双指纹。两者都再次检查当前编码与硬冲突，其余请求统一HTTP 422，失效编码/硬冲突确认返回HTTP 409。直接调用API同样受限。

旧`bindings/matched_code/is_exact`不升级为可导出；无可靠来源的旧记录恢复为`recommended/legacy_draft`并提示。合法人工确认可按双指纹恢复，编码失效时立即降推荐；合法一对多数量/比例可重新确认继续使用。本包新增账号库幂等表结构，但**未对真实业务库执行迁移、未迁移真实草稿**。
