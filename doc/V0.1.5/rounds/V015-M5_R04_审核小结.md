## 2. 分项审核结论

### 2.1 `A-M5-06 / P1（已闭环）`：缓存备份阶段中断不误删未备份旧文件

- [vector_index.py](../../../app/vector_index.py) `commit_candidate_cache`（L617-707）显式追踪三组不相交集合：`backup_moved`（已实际移入 `.backup_*` 的旧文件）、`promoted_files`（已实际提升的新文件）、未触碰旧文件，并记录 `failure_stage`（`backup_move`/`candidate_promote`）。
- `_restore_cache_backup`（L590-615）不再按全部 `staged_names` 删目标文件，**仅删除 `promoted_files` 中已实际提升的新文件**，随后仅将 `backup_moved` 回移。备份移动阶段（0/1/2/3）任一失败时 `promoted_files == []`，尚未移动的旧文件零触碰、不丢失——直接消除 R03 统筹终审抽查中"第二个旧文件移动失败导致另三件旧文件丢失"的反例。
- 恢复自身再失败则 `block_cache_writes(...)` 落盘 `.recovery_blocked.json`、保留 `.stage_*` 与 `.backup_*` 双目录恢复材料并抛 `CacheRollbackError`，符合裁决"失败不可恢复时保留原材料并进入阻断"。
- 专项覆盖：备份移动失败参数化 `[0,1,2,3]`、目标缺件+陈旧 FAISS、提升首/中/末 `[0,1,2]`、双失败阻断、server 五态回滚（`test_r04_am5_06_*`），逐文件字节摘要前后断言全等。

### 2.2 `A-M5-07 / P1（已闭环）`：恢复失败统一隔离、持久化阻断与真实核验解除

- **唯一仲裁新终态**：[server.py](../../../app/server.py) `ImportCommitArbiter.RECOVERY_FAILED`（L3077）区别于安全回滚 `ROLLED_BACK`；提交门异常分支（L3317-3419）逐层记录 `layer_results`/`recovery_errors`/`preserved_materials`，DB 反向交换、内存恢复、缓存恢复**任一失败**即 `block_db_writes` + `block_cache_writes` + `arbiter.fail_recovery`，任务返回 `recovery_failed=True`、`recovery_status="recovery_failed_manual_required"`、`write_blocked=True`，错误文案含 `"恢复失败/需人工处置"` 与 `"写入阻断"`。不再只记 critical 日志后按正常 rolled_back 收尾。
- **持久化跨层阻断（重启不可绕过）**：`db_manager`（L54-167）落盘 `<DB_PATH>.recovery_blocked.json`、`vector_index`（L65-167）落盘 `.recovery_blocked.json`，`is_db_write_blocked`/`is_cache_write_blocked` 均先查内存再查磁盘标记。专项 `test_r04_am5_07_restart_cannot_bypass_block_and_all_write_entries_reject` 仅清内存布尔位并重建锁/索引管理器实例后，阻断仍生效。
- **锁与全写入口阻断**：`RecoveryAwareDbImportLockManager.try_acquire()`（L3032）阻断期恒返回 `None`；`/api/db/upload`、`/api/refresh_vector`、`/api/db/reparse` 阻断期均 409；`vector_index` 的 `save_cache`/`build_index`/`add_to_index`/`check_db_timestamp_and_build`/`write_candidate_cache_to_dir` 与 `db_manager` 的 `import_materials_from_excel`/`commit_staged_materials_import`/`reparse_*` 全部挂 `_assert_cache_writable()`/`_assert_db_writable()`。
- **核验后解除**：`verify_and_clear_recovery_block`（L3684-3813）实检锁未占用、无残留 `*_stage`/`*_old` 表、无残留 `.stage_*`/`.backup_*` 目录、materials/FTS/metadata/内存索引/磁盘缓存四件套一致后才清除持久化标记；任一项不匹配返回 409 `cleared=False` 并维持阻断。专项演练含"未恢复直接调解除 409"、"仅修 DB 未清 stage 残留仍 409"、"全层一致后 200 解除并恢复 replace/append"完整反例链。
- **并发互斥**：DB 回滚失败专项用 `threading.Event` 卡点在回滚进行中发起并发第二导入，实证 409 且不释放 worker 1 的 `owner` 锁、不触碰数据。

### 2.3 `OBS-R03-1` 阻断期写入口保护（已闭环 R04 范围内部分）
