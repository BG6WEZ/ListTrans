### 2.3 根因归因错误（最关键问题）

#### "全候选满分"现象——现象真实，归因错误

**现象确认**：实测完全复现，且真实物料库形态（带全角冒号）同样复现。8 个不同半周长区间候选**全部得 100.00 分**：

```
半周长：1~500mm     -> 100.00  ['品类名称一致','核心参数在公差范围内','分类精准匹配']
半周长：1001~1500mm -> 100.00  ['品类名称一致','核心参数在公差范围内','分类精准匹配']
半周长：3501~4000mm -> 100.00  ['品类名称一致','核心参数在公差范围内','分类精准匹配']
```

**报告的归因（[分析报告 5.2](file:///c:/Users/wangd/project/ListTrans/doc/V0.1.2/material_library_revamp_analysis_report.md#L133-L139)）**：
> 1. 清单端抽取 `尺寸="630*400"`；候选端 `尺寸=None`
> 2. Matcher 发现候选端缺少 `尺寸`，且 `has_conflict` 判定跳过
> 3. 其余字段完全匹配 → 满分

**实测证伪**：若该归因成立，[matcher.py:L531-L533](file:///c:/Users/wangd/project/ListTrans/app/matcher.py#L529-L534) 必然触发 `missing_penalty += 0.15` 并输出 `必填属性缺失处罚: 尺寸`。但**实际 reasons 中并无此项**。

**真实根因链条（实测追踪）**：

```
extract_device_name("多叶调节风阀 半周长：1~500mm，...")
    -> '多叶调节风阀 半周长：~'        ← 数字被剥离，"半周长："残留并污染名称
route_domain(cat='多叶调节风阀', name='半周长：~', ...)
    -> 'valve_water'                  ← 领域误判！(正确应为 damper)
domain_config = valve_water
    -> must_keys = ['阀型','管径','材质','连接方式']   ← 不含"尺寸"！
循环判定: '尺寸' in must_keys == False
    -> 不触发 missing_penalty，静默跳过
attr_scores = {'材质': 1.0}            ← 仅材质参与打分，且完美匹配
    -> all_attrs_in_tolerance = True  -> +0.10 "核心参数在公差范围内"
    -> 名称一致 +0.12、分类精准 +0.12、cat_sim>0.9 +0.08
    -> 累加后被截断至 100.0
```

对照实验证实该链条：候选规格改为明确尺寸 `630*400，镀锌钢板，手动` 时，`route_domain` 正确返回 `damper`；而含"半周长："时返回 `valve_water`。

> [!CAUTION]
> **这一归因错误具有直接的工程后果**：
>
> 改版方案 [7.1 节](file:///c:/Users/wangd/project/ListTrans/doc/V0.1.2/material_library_cleaning_and_matching_solution.md#L251-L252) 据此设计的修复是"在 `damper` 的 must 属性中扩展尺寸比较逻辑"。但**实际执行路径根本没有走到 `damper` 分支**，而是走进了 `valve_water`。即使完整实现方案中的半周长区间打分器，只要 `route_domain` 仍误判为 `valve_water`，**新代码将永远不被触发，满分问题依然存在**。
>
> **必须追加的前置修复（方案完全遗漏）**：
> 1. `extract_device_name` 需将 `半周长`、`长度`、`面积`、`风量` 等**参数标签词从设备名中剔除**，避免污染领域路由；
> 2. `route_domain` 应优先信任 `category` 字段（本例 `多叶调节风阀` 已足够判定 `damper`），而非被污染的 `name`；
> 3. 增加断言测试：改版物料的 `route_domain` 结果必须与其 `category` 语义一致。

**附带发现的第二个抽取缺陷**：
`extract_params` 对半周长的抽取产生了**键名污染**与**语义错误**：

```
输入: "多叶调节风阀 半周长：1~500mm，镀锌钢板，手动"
输出: {'多叶调节风阀 半周长': '1~500mm',   ← 键名混入设备名
       '厚度': 500.0,                      ← 语义错误！区间上界被误认为"厚度"
       '材质': '镀锌', '手动': '手动'}
```

`厚度=500.0` 这一**错误属性**在 `damper`/`silencer` 领域可能参与打分并造成误判，方案中未提及此项清理。

## 三、改版方案评审

### 3.1 高危缺陷（阻塞项，必须修改）

#### 缺陷 H1：禁用正则 `26\d{4}` 冗余且存在误杀风险

方案 [3.2 节](file:///c:/Users/wangd/project/ListTrans/doc/V0.1.2/material_library_cleaning_and_matching_solution.md#L87-L90) 设计：

```python
DISABLE_KEYWORD_PATTERN = re.compile(
    r'(?:禁用|停用|废弃|\(?（?\s*禁用\s*\d{4,6}\s*）?\)?|260930|260729|26\d{4})',
    re.IGNORECASE
)
```

**问题分析**：

1. **`废弃` 造成 1 条确定性误杀**：唯一命中的 `[3.61.19.0001] PP废液收集车 | 废弃物收集车，280613，双桶` 是**正常在用物料**。方案的 39,419 这个数字正是由这次误杀凑出的。
2. **`26\d{4}` 是裸数字模式，语义危险**：它会匹配任何位置的"26"+4位数字。当前库中恰好无有效物料命中（实测 0 条），但库中**确实存在 85 条有效物料含 6 位纯数字**（如上例的 `280613`）。一旦后续批次出现 `26xxxx` 形态的规格编号、图号或日期（如 `260115`），将被**静默误删**，且无任何告警。
3. **`260930`、`260729`、`26\d{4}` 三者完全冗余**：前两者已被 `26\d{4}` 覆盖；而 `260729` 在库中根本不存在。

**修订建议**：

```python
# 收紧为"必须与禁用/停用语义共现"，杜绝裸数字匹配
DISABLE_KEYWORD_PATTERN = re.compile(r'禁用|停用|无效')
```

理由：实测该三词口径命中 **10,955 条，漏杀 0 条，误杀 0 条**，已达到 100% 拦截目标。**不需要任何日期数字模式**。
若确需防御未来形态，应改为 `(?:禁用|停用|无效|作废)\s*\d{0,6}` 的**共现约束**写法，并对命中行输出审计日志供业务复核。

### 3.2 必须修订项

#### 修订 M1：区间打分数学模型存在缺陷

方案 [6.1/6.2 节](file:///c:/Users/wangd/project/ListTrans/doc/V0.1.2/material_library_cleaning_and_matching_solution.md#L207-L233) 的公式与其 [6.3 节](file:///c:/Users/wangd/project/ListTrans/doc/V0.1.2/material_library_cleaning_and_matching_solution.md#L236-L241)示例**自相矛盾**：

| 问题 | 说明 |
| :--- | :--- |
| **示例与公式不符** | 6.3 称候选 2（`501~1000`，$v=1030$）得 **0.80**。按公式：$1-\frac{1030-1000}{1000\times0.15}=1-\frac{30}{150}=0.80$ ✓ 公式自洽。但候选 1（`1~500`）按公式为 $1-\frac{530}{75}<0$，得 0.0 ✓。**候选 4（`1501~2000`）**：$1-\frac{1501-1030}{1501\times0.15}=1-\frac{471}{225}<0$ 得 0.0 ✓。三者自洽，但**文档将候选 1/4 标注为"尺寸冲突阻断"而候选 2 为"轻微越界"，实为同一公式的连续输出，不应用不同定性描述**，易误导实现者写成两套逻辑。 |
| **区间不连续时打分断裂** | 实测半周长级距**存在跳段**：`其他通风空调材料` 为 `...(3501,4000),(6001,6500),(6501,7000),(7001,7500),(9501,10000)`；`钢门窗` 为 `(1501,2000)...(4501,5000),(7001,7500),(8001,8500)`。当清单值落入 `4001~4500` 这类**空档**时，所有候选均越界，公式将输出一组接近 0 的分数，**Top-1 退化为随机**。方案未设计"最近邻区间兜底"策略。 |
| **除零/极小值风险** | 当 `min_val=0`（实测风量区间存在 `(0,1000)`、`(0,49)`）时，`min_val*tol_ratio=0`，代码虽有 `max(...,1.0)` 兜底，但会使分母失真为 1.0，导致偏差 1 单位即扣满分。 |

**修订建议**：统一采用**相对级距归一化**，以级距宽度而非边界绝对值作分母：

```python
def score_point_vs_interval(v, lo, hi):
    if lo <= v <= hi:
        return 1.0
    width = max(hi - lo, 1.0)          # 用区间宽度归一，天然适配级距语义
    dist = (lo - v) if v < lo else (v - hi)
    return max(0.0, 1.0 - dist / width)
```

并补充：若全部候选得分 < 0.3，回退选取**距离最近的区间**并标记为"级距空档，需人工确认"。

#### 修订 M2：`樘 ↔ ㎡` 单位映射违背业务方案原文

方案 [7.2 节](file:///c:/Users/wangd/project/ListTrans/doc/V0.1.2/material_library_cleaning_and_matching_solution.md#L257-L261) 建立映射 `("樘","㎡")`。

但业务《瘦身方案·编码原则》第 3 条**明确禁止**：

> 例如防火门，现按"樘"各种尺寸非常多，可改为"㎡"，同实际采购的计价原则匹配。
> **修改意见：级距控制，分类处理；门：单/双开/子母门，不能按㎡；防火门 钢质门 木门 按材质来区分；**

业务结论是"**门不能按㎡**"，需按开启方式与材质区分。实测现状亦支持：防火门 187 条中 **183 条为"樘"**，仅 1 条为"㎡"。

**修订建议**：删除 `("樘","㎡")` 映射。门类应按 `材质 + 开启方式（单开/双开/子母）` 建立匹配维度。

同时 `("项","批")`、`("项","套")` 映射过于宽泛——业务原文仅说明"管件类的还是保持批或者项，**计量单位不变**"，即**无需换算**。建议限定作用域至管件辅材类，避免全局生效造成跨类误配。

#### 修订 M3：遗漏"半周长 × 长度"双区间复合形态

实测 **96 条**消声器物料采用**双区间复合**规格：

```
消声器 | 半周长：3501~4000mm*长度：1501~2000mm，玻璃钢
```

这是**两个独立区间维度的笛卡尔组合**（半周长 8 档 × 长度 3~4 档）。方案的半周长解析器 [4.1 节](file:///c:/Users/wangd/project/ListTrans/doc/V0.1.2/material_library_cleaning_and_matching_solution.md#L137) 正则 `r'半周长\s*(\d+)...'`：

1. 未处理 `半周长：` 中的**全角冒号**（实测库中**全部**为全角冒号形态，方案正则将 100% 匹配失败）；
2. 未解析 `*长度：a~b` 第二维，导致 96 条消声器**同一半周长下的 3~4 个长度档位无法区分**，满分问题在消声器品类上依然存在。

**修订建议**：正则补充全角冒号 `[：:]?`，并增加 `长度` 区间的独立解析与加权打分。

#### 修订 M4：验收基线数据严重失真

方案 [10.1 节](file:///c:/Users/wangd/project/ListTrans/doc/V0.1.2/material_library_cleaning_and_matching_solution.md#L313-L319) 所列"现状基线"与仓库真实基线 [golden_baseline.json](file:///c:/Users/wangd/project/ListTrans/tests/fixtures/golden_baseline.json) 对比：

| 指标 | 方案所称现状 | **真实基线（2026-08-17，1067 用例）** | 偏差 |
| :--- | :--- | :--- | :--- |
| Hit@1 | ~83.5% | **22.31%** | 虚高 **3.7 倍** |
| Recall@3 | ~89.2% | **35.61%** | 虚高 **2.5 倍** |
| MRR | ~0.865 | **0.307** | 虚高 **2.8 倍** |
| miss@10 | ~6.5% | **48.92%** | 低估 **7.5 倍** |
| 禁用拦截率 | 6.1% | 673/10,955 = **6.14%** | ✅ 此项准确 |

> [!CAUTION]
> 方案的验收目标 `Hit@1 ≥ 88%` 是建立在虚假基线 83.5% 上的"提升 4.5 个百分点"。真实基线为 **22.31%**，要求一个版本内提升至 88%（**提升 65 个百分点**）**完全不具可行性**。
>
> 若以此为验收门禁，阶段 4 必然失败。**必须以 golden_baseline.json 实测值重设目标**，建议改为分档目标：Hit@1 ≥ 30%（暖通专业 ≥ 45%），并单列"半周长/容差品类专项 Hit@1 ≥ 80%"作为本次改造的直接验收项。

### 3.3 建议补强项

| 编号 | 事项 | 建议 |
| :--- | :--- | :--- |
| S1 | **级距边界语义未落实** | 业务方案明确标注"**±符号，含上限不含下限**"。方案打分器用 `lo <= v <= hi` 为**闭区间**，与业务语义不符。实测区间为 `1~500, 501~1000` 形态（数据上已无重叠），建议保留闭区间实现但**在文档中显式说明**该偏差无害，避免后续误改。 |
| S2 | **重复编码未处理** | 实测 817 版存在 **37 行重复 `code`**。入库若以 `code` 为主键将触发冲突或静默覆盖，方案的原子热切换流程未涵盖去重步骤。 |
| S3 | **面积计量落地极少** | 业务方案要求风口改按 `㎡`，但实测风口类分类中 `个`=1047 而 `㎡`=1，面积区间物料仅 **7 条**（且是防虫网/过滤网，非风口）。方案 4.1 节计算 `面积` 衍生属性优先级可下调，当前收益极低。 |
| S4 | **`医用` 剥离影响面需评估** | 实测 817 版 `name` 含"医用"仍有 **1,965 条有效物料**（811 版 10,579 条，大部分随禁用一起下线）。方案 4.3 节全局无条件剥离"医用/医疗"会使这 1,965 条物料的名称与清单端同步失去区分度，**存在误合并风险**（如"医用不锈钢球阀"与"不锈钢球阀"可能是不同物料）。建议改为**双写**：保留原名并额外生成归一化别名参与召回，而非破坏性替换。 |
| S5 | **`废弃` 误杀需审计输出** | 无论最终采用何种正则，建议将命中行**导出 CSV 供业务确认**，而非静默丢弃 10,955 条。 |
| S6 | **`厚度` 污染属性需清理** | 前述 `extract_params` 将区间上界误抽为 `厚度=500.0`，需在抽取器中修复，否则会污染打分。 |

## 五、评审结论

**分析报告**：核心发现（禁用穿透 10,281 条）**成立且价值重大**；四大冲击方向判断正确；对源码缺陷的定位准确。但存在 **7 处事实性数据错误**（集中于"改版前基线"）与 **1 处关键根因归因错误**。**结论：需修订后作为设计依据。**

**改版方案**：整体架构、模块划分与实施节奏合理，多数技术设计经实测验证有效。但存在 **1 项高危缺陷**（禁用正则误杀与冗余）、**4 项必须修订项**（区间打分模型、单位映射违背业务原文、遗漏双区间形态、验收基线失真）。**结论：有条件通过，完成 P0 与 P1 修订后方可进入编码实施。**

> **最需要引起重视的一点**：报告对"满分无区分度"的归因错误，会导致方案中的核心修复（半周长区间打分器）**因领域路由误判而永不生效**。这是本次评审最具工程价值的发现，建议优先验证并修复。
