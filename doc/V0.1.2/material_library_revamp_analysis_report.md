## 一、背景与改版全景概述

为了解决物料库历史积累导致的“一尺寸一编码、颗粒度过细、冗余物料庞大、多业态描述不通用”等问题，业务侧正式出具并推进了《物料编码瘦身方案》。

在本次改版（20260817 部分改版数据及后续批次）中，物料库呈现出明确的演进趋势：
1. **老旧/细分编码停用与瘦身**：对历史物料打上 `（禁用260930）`（10,157条）和 `（禁用260830）`（125条）标记并逐步淘汰，精简有效物料行数。
2. **尺寸规格改为“尺寸段 / 半周长”**：暖通风阀、消声弯头、风管、矩形风口等从“明确长宽尺寸”转为“半周长级距区间”（如 `半周长：1001~1500mm`），消声器出现“半周长×长度”双区间复合形态。
3. **箱体/柜体规格改为“容差区间”**：消声静压箱、消声器、各类洁净柜体从“单点长宽高”转为“基准尺寸±150mm 容差区间”。
4. **设备核心参数精简与级距化**：风机、换气扇等主要按风量级距控制，弱化或去除静压/机外余压等次要约束。
5. **名称去虚就实**：统一规范物料名称，逐步淘汰非通用的修饰前缀。

> [!NOTE]
> **关于存量缺陷的澄清**：  
> 经与 20260811 原物料库比对，半周长、三维容差、参数区间等形态在 0811 版本中已存在一定存量（如半周长 74 条、三维容差 32 条、参数区间 3,307 条）。改版后上述形态大幅增加（如半周长增至 340 条、容差增至 279 条、参数区间增至 5,812 条）。
> **本质定性**：这并非单纯由改版引入的全新问题，而是**系统长期存在的存量抽取与打分缺陷被物料库改版集中放大**，使得系统底层升级的紧迫性更加突出。

## 三、核心隐患发现：禁用物料屏蔽机制与现有代码缺陷

### 3.1 禁用物料在数据表中的真实分布与形态迁移
在 `20260817（部分改版）.xlsx` 中，共有 **10,955 条（21.75%）** 物料为已停用或待禁用的历史编码，其各列分布为：
- **`code` 列命中**：**673 条**（全部形态形如 `[WL1000386422（禁用）]`，继承自历史库）
- **`name` 列命中**：**10,281 条**（形如 `UPVC管管件（禁用260930）`、`消声静压箱（禁用260930）`、`生物制药离心式排风机(箱）（禁用260930）`）
- **`specification` 列命中**：**1 条**

### 3.2 现有代码的过滤机制失配
审查 [app/db_manager.py:L372-L375](file:///c:/Users/wangd/project/ListTrans/app/db_manager.py#L372-L375) 的入库逻辑：
```python
# 当前系统的过滤代码：
disabled_mask = df_cleaned["code"].apply(lambda x: any(kw in str(x) for kw in ["禁用", "停用", "无效"]))
```

> [!CAUTION]
> **代码缺陷分析**：  
> 原代码设计时物料库仅在 `code` 列存在禁用标记（673条），因此仅过滤 `code` 列在当时能够生效。但改版后业务将 **10,281 条新禁用标记标注在 `name` 列**。  
> **后果**：标记形态迁移导致原过滤器彻底失效，**10,281 条已被淘汰的物料全部穿透进入数据库、FTS5 索引与向量索引**。线上匹配时系统将继续向用户推荐老旧淘汰物料，必须重构为全字段联合过滤。

## 四、对物料清洗与特征抽取规则的深度影响剖析

### 4.1 影响一：半周长（Half-Perimeter）规则的抽取与全角冒号断层
- **业务定义**：半周长为矩形截面长与宽之和，即 $\text{Half-Perimeter} = \text{Length} + \text{Width}$。
- **现有规则断层**：
  1. 清单端抽取 `630*400` 为字符串 `attrs["尺寸"] = "630*400"`，未计算衍生属性 `半周长 = 1030`。
  2. 物料端文本为 `多叶调节风阀 半周长：1001~1500mm`，含有**全角冒号** `：`。现有抽取正则未兼容全角冒号，导致尺寸返回 `None`。
  3. 消声器存在 96 条**双区间复合形态**（如 `半周长：3501~4000mm*长度：1501~2000mm`），现有规则完全遗漏了第二维 `长度` 区间的提取。

### 4.2 影响二：三维容差区间 `(L±ΔL)*(W±ΔW)*(H±ΔH)` 正则失效
- **改版形态**：消声静压箱、洁净柜体等物料规格重构为 `（1500±150）*（1500±150）*（900±150）mm`。
- **现有抽取正则**：仅支持单点数字 `\d+ * \d+ * \d+`，无法匹配中文全角括号与 `±` 容差符号，导致长宽高特征全为空。

### 4.3 影响三：名称“去虚就实”与在用物料保护
- **现状分析**：
  - 817 版物料库 `name` 列中仍有 **1,965 条有效在用物料包含“医用”**（如 `医用不锈钢地漏`、`医用自动气密门` 等）。
  - 若在归一化清洗中全局无条件破坏性剥离“医用/医疗”，会导致上述 1,965 条有效物料与普通物料失去区分度，存在误合并风险。
  - **正确做法**：采用“保留原名 + 生成归一化别名”双写策略参与检索与对齐。

### 4.4 影响四：设备参数精简与 Schema 必须属性（Must Keys）冲突
- **改版形态**：换气扇/排气扇取消静压，普通风机余压放宽为区间。
- **冲突机理**：[config/domain_schema.json](file:///c:/Users/wangd/project/ListTrans/config/domain_schema.json) 将 `机外余压` 定义为 `fan` 的必填 must 项，物料库精简后将触发 -0.15 的必填缺失惩罚，造成非预期降分。

## 五、对候选召回与多维打分规则的深度影响剖析（根因追踪）

### 5.1 召回层（Recall Layer）影响
1. **FTS5 关键词倒排索引召回脱靶**：
   - 清单 Query 为 `多叶调节风阀 630*400`，分词后查找 `630`、`400`；而物料端仅有 `1001~1500`，FTS 检索词无法交织，造成 FTS 通道完全脱靶。
2. **向量语义检索空间偏移**：
   - 必须全量剔除 10,955 条禁用物料后重新生成向量缓存，确保语义空间一致。

### 5.2 打分层“全候选满分 100 分”的真实根因链条（关键纠偏）

实测在当前系统中输入 `多叶调节风阀 630*400 手动 镀锌钢板` 时，8 个不同半周长区间的候选物料**全部获得 100.00 分**。

经过对 `extract_device_name`、`route_domain` 与 `score_candidate` 全链路插桩追踪，**真实根因链条如下**：

```
1. 特征抽取端：
   extract_device_name("多叶调节风阀 半周长：1~500mm，...")
   -> '多叶调节风阀 半周长：~'   (数字被剥离，"半周长："残留并严重污染设备名称)

2. 领域路由端：
   route_domain(cat='多叶调节风阀', name='半周长：~', ...)
   -> 路由规则被污染的名称误导，误判为 'valve_water' (水阀)！(正确应为 damper 风阀)

3. 门禁与打分端：
   domain_config = valve_water
   -> valve_water 的 must_keys 为 ['阀型', '管径', '材质', '连接方式']，根本不包含 '尺寸'！
   -> 循环判定 '尺寸' in must_keys 为 False -> 完全不触发 missing_penalty 缺失惩罚！
   -> 仅'材质'参与打分且完美匹配 -> all_attrs_in_tolerance = True (+0.10)
   -> 叠加品类名一致(+0.12)、分类精准(+0.12)、语义分等，最终累加截断至 100.0 分！
```

> [!IMPORTANT]
> **根因纠正的重大工程价值**：  
> 若仅在 `damper` 领域中补充尺寸区间打分逻辑，由于 `route_domain` 已经误判为 `valve_water`，**新打分代码将永远不会被执行，满分问题依然存在**！  
> **必须实施的前置修复**：  
> 1. 在 `extract_device_name` 中将 `半周长`、`长度`、`面积`、`风量` 等参数标签词彻底从设备名称中剔除，避免污染路由；  
> 2. 重构 `route_domain`，优先信任标准品类字段 `category`；  
> 3. 修复 `extract_params` 将 `1~500mm` 上界误抽为 `厚度=500.0` 的属性污染缺陷。

## 七、V0.1.2 版本核心技术改造方向

1. **数据治理与精准拦截**：
   - 使用 `re.compile(r'禁用|停用|无效')` 全字段扫描，精准拦截 **10,955 条** 禁用物料，保留 **39,420 条** 有效活跃物料。
   - 杜绝 `26\d{4}` 裸数字匹配与 `废弃` 单字误杀，导出禁用清单审计 CSV 供业务复核；增加 37 行重复 `code` 去重告警。
2. **抽取层与路由层前置修复**：
   - `extract_device_name` 剔除参数标签词，`route_domain` 优先信任 `category`，确保风阀正确路由至 `damper`。
   - 修复 `extract_params` 误将区间上界识别为 `厚度` 的缺陷。
   - 支持 `半周长：` 全角冒号解析与消声器 `*长度：` 双区间抽取；清单端自动计算衍生 `半周长 = L + W`。
   - 升级 `extract_tolerance_3d_box` 支持三维容差解析。
3. **打分引擎重构**：
   - 采用**级距宽度归一化**算法实现 `score_point_vs_interval`，避免除零并合理平滑过渡；提供级距空档最近邻兜底。
   - 移除违背业务原则的 `樘 ↔ ㎡` 映射，门类按材质与开启方式区分。
4. **门禁适配与向量重建**：
   - `fan` 领域余压降级为 `should`。
   - 全量重建 39,420 条有效物料的 512 维 BGE 向量索引。
