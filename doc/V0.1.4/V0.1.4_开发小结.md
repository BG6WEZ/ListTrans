### Phase 3：并发吞吐与架构解耦治理（本期交付）

#### 1. 核心落地成果

##### (1) M1: 范围阻塞彻底卸载（主线程与事件循环 0 阻塞）
- **Excel 读表卸载**：在 `app/server.py` 中将 CPU 密集的 `openpyxl.load_workbook` 及工作表行扫描逻辑剥离为同步工作函数 `_parse_and_prepare_upload_excel`，通过 `await loop.run_in_executor(executor, _parse_and_prepare_upload_excel, task_id, temp_path)` 卸载至后台线程池。
- **匹配与重算接口卸载**：
  - `POST /api/batch_match`：通过 `await loop.run_in_executor(executor, batch_match_rows, raw_rows)` 异步化。
  - `POST /api/match`：通过 `await loop.run_in_executor(executor, match_item, query_info)` 异步化。
  - `POST /api/rematch`：单条特征重算通过 `await loop.run_in_executor(executor, match_item, query_info)` 异步化。
- **飞轮每日挖掘调度**：`_daily_flywheel_mining_loop` 中的 `miner.run_mining()` 接入 `await loop.run_in_executor(executor, miner.run_mining)`，彻底杜绝凌晨定时任务阻塞主事件循环。

##### (2) M3: 并发架构与线程安全加锁 (R1/R3/R7)
- **任务状态字典加锁 (R3)**：移除 `server.py` 历史冗余的重复赋值，引入 `_upload_tasks_lock = threading.Lock()`。封装 `update_task_progress()`、`get_task_status()`、`set_task_initial()` 与 `clean_expired_upload_tasks()`，全仓 `upload_tasks` 的增删改查 100% 受锁保护。
- **并发 POC 压测与技术裁决 (R7)**：
  - 在 Docker 生产容器针对 100 行真实清单完成不同并发模型基准压测；
  - 实测数据：单线程 12.62s (7.9 行/秒)，2 线程 13.65s (0.92x 负提速)，4 线程 14.87s (0.85x 负提速)；
  - **技术裁决**：保持 Stage 1 向量特征批量提取使用 PyTorch/C++ 多核高并发；Stage 2 行级正则与规则匹配保持流水线单线程以独占 CPU Cache 与避免 GIL 线程颠簸；多任务在 4-Worker 线程池内支持并发上传。详细压测报告见 [Phase3_POC_Benchmark_Report.md](file:///c:/Users/tlyer/project/ListTrans/doc/V0.1.4/Phase3_POC_Benchmark_Report.md)。

##### (3) M4: `score_candidate` 模块化重构与 100% 零回退验证
- **超长核心函数解耦**：将 `app/matcher.py` 中长达 1,222 行的单体巨型函数 `score_candidate` 解耦为清晰的管道架构：
  - 定义 `ScoringContext` 数据上下文对象，集中收口打分输入、属性、特征、中间权值与命中原因；
  - 拆解为 12 个高内聚领域子函数：
    - `_check_initial_hard_conflicts()`: 专业/品牌/单位硬冲突阻断
    - `_extract_candidate_specs()`: 候选物料结构化参数解析
    - `_score_model_similarity()`: 型号相似度与冲突判断
    - `_score_text_and_category()`: 名称与品类相似度计算
    - `_score_attributes()`: 领域 Schema Must/Should 属性与公差比对
    - `_calculate_base_score_and_positive_boosts()`: 场景加权与正向偏置
    - `_apply_conduit_cable_and_electrical_gates()`: 线管/桥架/配电箱/开关领域规则
    - `_apply_config_hard_gates()`: Schema 冲突/偏差硬拦截
    - `_apply_domain_cable_and_pipe_penalties()`: 线缆/管道/装饰特定参数扣分
    - `_apply_hvac_gates()`: 防火阀/机组/风盘/多联机/风机/风管 HVAC 硬隔离
    - `_apply_dynamic_rules()`: 动态 LLM 规则执行引擎
    - `_finalize_candidate_score()`: 饱和分微扰 Tie-breaker 与原因去重
  - `score_candidate` 主入口收敛为 20 行高可读性编排器。
- **可变默认参数缺陷修复**：修复 `app/matcher.py` 中 `match_item` 的 `batch_confirmed_series: List[str] = []` 危险默认参数，改为 `Optional[List[str]] = None`。
- **全量黄金集 100% 零回退验证**：

### 3. 改动实施清单与代码分布

#### (1) Anti-FOUC 防闪烁实现
在 `web/index.html`、`web/admin.html`、`web/login.html` 的 `<head>` 首部统一植入以下同步脚本（与生产代码逐字对齐）：
```javascript
(function() {
    try {
        var theme = localStorage.getItem('listtrans_theme');
        if (!theme) {
            theme = (window.matchMedia && window.matchMedia('(prefers-color-scheme: light)').matches) ? 'light' : 'dark';
        }
        document.documentElement.setAttribute('data-theme', theme);
    } catch (e) {
        document.documentElement.setAttribute('data-theme', 'dark');
    }
})();
```
**关键收益**：在 HTML 解析阶段直接将 `data-theme` 属性写入根节点 `<html>`，无需等待外部 CSS/JS 脚本加载解析完成，消除了深浅色切换时的白屏或深色暴闪现象。并且具备 `window.matchMedia` 守卫与 catch 异常兜底，安全回退到默认 dark 主题。
