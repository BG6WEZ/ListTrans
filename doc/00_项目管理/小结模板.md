# 每轮小结与终审模板

模板不是已完成记录。复制到对应版本/rounds并替换全部占位符后使用。小结建议控制在一页内，详细证据单独链接。

## 开发小结

```markdown
# <任务包> R<轮次> 开发小结
- 版本/任务/开发AI/日期：
- 状态：待审核（不得写版本终审通过）
- 基线与交付：<commit；或文件哈希与差异清单>
## 本轮完成
<变更、原因；对应F编号或审核问题编号>
## 验证
| 检查/命令 | 环境与范围 | 结果/退出码 | 证据 |
|---|---|---|---|
## 未完成、风险与回滚
<明确失败/未执行、数据迁移及回滚方法>
## 提请审核
<本包验收逐项对照；不要替审核AI写结论>
```

## 审核小结

```markdown
# <任务包> R<轮次> 审核小结
- 版本/任务/审核AI/日期：
- 实际审核基线：<与开发交付相符；不符则退回>
- 结论：通过 / 退回整改 / 待验证
## 审核范围与独立复验
<真实diff、检查命令、通过/失败/未执行及证据路径>
## 发现
| 编号 | 级别 | 文件:行/证据 | 触发条件与影响 | 整改要求/复审结果 |
|---|---|---|---|---|
## 验收对照
<每项达到/未达到/未验证；无阻断不等于全系统无缺陷>
## 下一步
<退回开发，或交统筹；不得批准进入后续版本>
```

## 统筹版本终审

```markdown
# V<版本> 终审与版本准入
- 统筹AI/日期/交付代码：
- 结论：通过 / 不通过 / 待验证
- 本版本各包：<审核小结路径、轮次及基线>
- 统筹抽查：<检查范围、真实结果、证据>
- 指标：<冻结基线、当前结果、差值、分域退化、P95与样本量>
- 未闭合项：<P0/P1必须为0；延期P2含去向与防护>
- 数据兼容、部署资产、回滚：<验证结果>
- 准入批准：允许/禁止进入V<下一版本>；初始下发<任务包>
- 发布状态：未发布 / 有独立授权且已发布<证据>
```
