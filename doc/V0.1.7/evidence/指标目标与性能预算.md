# V0.1.7 指标目标与性能预算

**M0 实测当前基准与候选预算目标，待统筹核验签认。** 本稿为 V017-M0 R01 开发实测，预算覆盖当前冻结数据、现有规则和单请求实验条件。

## 数据、环境和采样

2026-11-18，Windows 11，12th Gen Intel Core i7-12700H（14 核、20 逻辑处理器）、可见内存 16,068.74 MiB、Python 3.12.10、CPU 版 PyTorch 2.15.0。服务器使用生产线程配置。两个模式先后各启动一个独立进程，装载同一物料库和 16 份冻结配置副本。向量模式实际使用本机 `bge-small-zh-v1.5` 模型及 26,863 × 512 的 NumPy 缓存索引，1,220 个召回池均有 semantic 渠道。关键词模式 0 个。模型、配置、向量缓存、数据及单样本记录的摘要见[向量原始结果](m0_r01_validation_vector.json)及[关键词原始结果](m0_r01_validation_keyword.json)。

每种模式实际完成 1,220 条排名诊断、1,220 次带鉴权的 `/api/match` 和 25 次 `/api/upload`，上传按 24 份 50 行和尾批 20 行覆盖全部 1,220 行。每模式先用 5 条单请求和 1 个 5 行工作簿预热，预热不计入分位数。通过 ASGI TestClient 执行真实路由、生产批量匹配、入库与状态读取。计时包括应用边界内工作，不含外部网络传输、Excel 样本生成和启动/冷索引构建。RSS 每 25 ms 采样，进程工作集峰值为 Windows 已观测高水位。两种匹配模式顺序执行，BGE 单条阶段与一次约 18 秒的只读对账复算重叠。当前时延作为候选预算取值，签认复测应避免这项后台负载。[对账复算记录](m0_r01_rebuild_replay.json)
