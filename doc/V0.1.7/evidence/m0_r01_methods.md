## 五分类与等价组

| 样本类别 | 全集失配 | 核心失配 | 裁定依据 |
|---|---:|---:|---|
| `code_remapped` | 0 | 0 | 单一在库候选、历史与现库属性相符、有停用和同签名新增改版证据。现有证据不足以锁定逐条一对一换码 |
| `equivalent_candidates` | 0 | 0 | 多候选全部属于同一现库等价分区且历史属性一致。失配样本中没有满足条件的组 |
| `disabled_or_retired` | 154 | 152 | 对应旧编码和同名同规格证据明确标记停用或审计记录已失效，按 2026-11-11 快照日期计算，同名和相关同规格候选检查均未发现候选 |
| `no_substitute` | 0 | 0 | 当前离线来源不足以给未明确停用样本确认全库无替代 |
| `pending_business_review` | 226 | 186 | 仍有候选、属性或替代证据不完整，或套装仅部分目标可解释 |

每个缺失目标在对账报告的 `mismatch_ledger` 保留源文件、工作表、行号、匹配或停用证据、精确文本候选和相关候选数量。GT-0031 可查气水改版表的旧码停用记录，候选数为 0。GT-0005 同时有旧码停用和两个相关在库候选，需要业务裁定。5 个失配目标槽位虽有一个精确文本候选，仍缺少历史属性和改版依据的完整证据。停用口径只能覆盖审计和离线对照支持的范围，异名替代和 ERP 中更新的关系仍须业务确认。

合成分支探针覆盖已证换码、等价候选、停用、同名同规格但品牌或单位冲突，以及仅凭目标码缺失不得认定无替代。探针样本独立于黄金集统计。[分类探针](m0_r01_classifier_probes.json)

按库内原始名称、规格复算 157 组重复。分区进一步比较单位、品牌、分类、说明和解析后的 JSON 内容。114 组出现可映射等价分区。不同属性的分区保持分离。组间差异包含 34 组品牌、9 组单位、35 组分类、4 组说明和 5 组解析参数差异，允许一组同时命中多列。原库物料行继续逐编码存在。

## 划分与固定资产

`P1` 配对来自装饰、强电、弱电、给排水、动力气体原始和完成清单，`P2` 来自利川项目原始和完成清单。对账清单列出 12 个源工作簿、42 个工作表的文件哈希和工作表名称。

先将同 `project + source_sheet` 的所有样本合并，再跨表、跨项目合并 NFKC、去空白、忽略大小写后的名称和规格完全相同的 Query。名称相同且两个规格至少 12 字符时，三字符片段集合 Jaccard 相似度达到 0.88 也连边。对全部传递闭包求连通分量，按组大小降序和 `SHA256("V017-M0-R01:" + 最小样本 ID)` 排序分配到目标余量最大的分片，目标比例 70/15/15。报告保留 972 条相似边和 10 个连通组，最大组 784 条。自验检查组内边、同签名、同项目同工作表无跨片，并检查逆序输入的划分一致。

实际 Train/Dev/Test 为 842/218/160。总共只有两个项目，两者均跨分片。强电、医用气体和自控集中在 Train，Dev 以装饰为主，Test 中给排水占 110 条。跨项目的同签名和阈值内近似项保持同片，近似算法未测出的改写、共享工程背景及同一物料编码跨片仍可能相关。保留这一抽样限制，逐专业的分片缺样与小样本均单列，不外推其他专业的留出质量。

## 评测与复验

1. 用 `venv/Scripts/python.exe -B -X utf8 doc/V0.1.7/evidence/m0_r01_build_governance.py --asset <新资产文件> --report <新报告文件>` 重算并核对 SHA256。脚本拒绝覆写输出。
2. `m0_r01_benchmark.py --mode <vector|keyword> --root <仓外原生绝对新目录> --governance <冻结治理资产> --out <新结果文件>`。每模式独立进程，各复制冻结库和 16 份配置，向量模式复制并校验既有向量缓存的哈希和全量物料映射，再加载冻结的 512 维本机 BGE 模型，校验真实编码和检索。关键词模式按既有评测开关关闭向量通道。环境在首次业务导入前注入 10 个隔离路径，禁用 dotenv 和 LLM，评测进程阻断非回环 socket。
3. `m0_r01_summarize.py --vector <向量结果> --keyword <关键词结果> --out <新对比文件>` 生成聚合结果。对照报告与原始结果按样本 ID 可追溯。每次正式验证的解释器、完整 argv、原生根、起始时间、退出码和耗时见相应 `*.run.json`。

Legacy Full Core 保留原评估口径，按最佳原目标在生产 Top10 的位置给出 Hit 和 MRR@10。In-Catalog Core 仅计原编码在库 729 条。治理 answerable 在同一批诊断上比较严格原编码与允许等价编码，排除硬阻断候选的排序命中。各口径同时提供 MRR@10 和全排序 MRR。

召回分母为原目标槽位，同一槽位的可接受替代任一召回即一次命中。全集指生产 `hybrid_recall` 去重并集，@50/100/200 取该并集的插入顺序前缀，排序前采样且不改生产候选限额。五阶段在槽位层选择最有效的可接受编码。渠道贡献是召回该槽位的渠道并集，一槽位可由多渠道贡献，含带术语的生产渠道名。

Governed Multi-Split 同时给出全体、Train、Dev、Test 和专业分组。在核心集单独评估可回答、已停用/无答案、待复核。待复核只统计数量和专业，不进入通过率分母。81 条套装保留原目标诊断，已确认套装用最晚命中的组件计算集合 Hit@K 和倒数名次。歧义和 QC 标记的单目标样本独立计数。

HTTP 测量包含真实鉴权、生产 ASGI 路由和事务。单条样本经 `/api/match`，批量按 50 行（尾批 20 行）生成内容与标注一致的 XLSX，经 `/api/upload` 到真实 `batch_match_rows`，并取完成态结果。ASGI TestClient 在响应后执行后台任务并等到结束，批量计时包括解析、生产匹配、持久化和完成态读取。单条接口返回推荐候选和 `is_exact` 提示，生产绑定决策字段只在上传路径出现。报告分别记录候选准确率、自动接受、建议绑定和显式拒绝。无自动接受样本时准确率为 null。负例的显式拒绝和没有形成绑定分别记录。HTTP 输入使用金标样本填写的专业和单位，上传的专业由工作表名按生产逻辑路由，路由差异随报告留存。延迟为最近秩 P50/P95，运行阶段每 25 ms 采样 RSS，并同时记录进程工作集高水位。

容器回归用 `m0_r01_container_check.py <keyword|vector> --out <新结果文件>`。固定本机 V0.1.6 镜像 ID，`--pull=never --network none`，仅以只读挂载提供当前改动文件及向量模式的本机模型。容器先按 SHA256 核对实际加载的 Python 源文件，再运行既有 M4 合成闭环。两模式各 51 次 HTTP 调用。[关键词容器](m0_r01_container_keyword.json) · [向量容器](m0_r01_container_vector.json)

回归驱动可用 `venv/Scripts/python.exe -B -X utf8 -u doc/V0.1.7/evidence/m0_r01_validate.py special fixed standard gate host verify --suffix _audit_check`。使用未占用的后缀。固定根与默认 `mkdtemp` 根均带显式仓外 `--basetemp`。默认根由 conftest 创建。沙箱尝试曾卡在 Windows asyncio 的 socketpair/accept。线程栈确认回环套接字初始化的阻塞后，终止了未完成进程，正式验证在批准的原生 Windows 环境中运行，依然禁用外部访问和模型下载、隔离可写路径。首次完整回归有 376 项通过和 1 项失败。新增导出测试对同名字串做了过宽的全局结果断言。复测改用两专业同名的唯一合成记录，断言仅覆盖该用例写入的三条可信反馈，保留原有产品断言。[首轮日志](m0_r01_validation_fixed.log) · [日志字段移除记录](m0_r01_log_redactions.json)
