# 第二章 现有代码病灶诊断

## 2.1 Bug#1：`not category_hint` 逻辑短路（严重）

**位置**：[preprocessor.py#L323-L328](file:///Users/tlyer/Project/ListTrans/app/preprocessor.py#L323-L328)

```python
is_hvac = any(k in category_hint for ...) or (not category_hint and any(...))
```

# 第三章 结构化方法论

## 3.1 顶层原则

| 原则 | 说明 | 决策落地细则 |
|---|---|---|
| 分类驱动 | 385 类折叠到 30 域，每域独立规则 | 分类与规格文本联合研判，确定唯一 Domain |
| 字段稀疏容忍 | 抽不到视为 `unknown`，按缺失惩罚而非跳过 | 解决交集漏洞，保持物理层面的差异显现 |
| 字典优先，正则兜底，语义封顶 | 90% 场景用字典+正则；剩余走向量补齐 | **双轨分离**：在线侧禁用语义查询以保障极速匹配；离线侧启用语义自动反填 |
| 双端一致 | 候选侧与查询侧共用同一套 router + extractor + dict | 保证属性的完全一致性和零偏倚 |
| 数值归一强制 | Must 字段一律 `float/int`，禁字符串数值 | 消除 `float()` 崩溃阻断打分的硬伤 |
| 可回滚 | Schema 版本化 + 双表切换 + 异步 re-parse | 安全演进，系统热更新不中断服务 |
| 前端零改动 | `attrs` 仍 dict、`model` 仍 str，接口契约保留 | 保留外部契约，利用**返回别名自适应兼容**实现零改动 |
| **结构化率口径定标** | **明确定义统计口径** | 统一口径：**`结构化率 = 成功抽取全部 Must 字段的有效物料行数 / 有效物料总行数`**。在 Phase 0 必须以此口径对当前系统进行基线统计。 |
| **字典基线覆盖率** | **核心域字典前置基线** | 强制要求四大核心域（通风机、电缆、水阀、管道）的关键枚举字典（如材质、机型、连接方式等）对数据集实际出现的取值**覆盖率达 95% 以上**，未达标前不得开始核心开发。 |

## 3.2 三层结构化模型（IR-1 / IR-2 / IR-3 双轨分治）

```
Raw Text
  ▼
IR-1 归一层（Normalize，幂等）
  · 全角→半角、大小写归一、分隔符标准化（→ ，）
  · 单位大类规范与数值级换算（Unify Standard Units & Scaling）
  · 别名/错别字替换（alias_dict）与材料关键词映射（304不锈钢 → SS304）
  ▼
IR-2 分域抽取（Domain Extract）
  Step 1 · domain_router 按优先级路由：“正文强特征 > 名称 > 原始分类”（支持分类覆写与二级细分）
  Step 2 · 加载域结构：domain_schema[domain] 得 Must/Should/Flags、硬门槛参数与正则抽取模板
  Step 3 · 分发至专用提取器：根据配置的正则或解析规则提取 Must/Should/Flags 字段
  Step 4 · 非标数值后置处理器（范围值、不等式、约数处理）
  Step 5 · 标准单位级数值换算后置器（如 Pa/kW 换算，并转换为 float/int）
  ▼
IR-3 语义补齐与 Fallback（双轨分治机制）
  ├─► 【离线热建侧 (Offline Background Pipeline)】
  │     · 自动对比存量相似物料，最近邻候选智能反填缺失的 Must 字段，建立完整参数画像
  └─► 【在线匹配侧 (Online Realtime Query)】
        · ⚠️ 禁止引入向量搜索以免造成循环依赖和延迟，保持缺失字段为 unknown 并在匹配层自然扣分
```

### 3.2.1 域路由优先级与品类漂移覆写 (Category Overwrite)

为彻底解决原始数据中“分类录错”（品类漂移）的顽疾，`domain_router` 不再采用纯静态一对一映射，而是遵循以下优先级执行路由决策：
1. **第一优先级（正文强特征关键词）**：若规格型号正文或物料名称中出现其他品类的强特征专有词（如在“调节阀”分类中出现“静压箱 1500\*450”或“网孔板风口”，在“冷热水机组”分类中出现“冷热源控制系统”），则触发**分类覆写逻辑 (Category Overwrite)**，直接改道路由至目标域（如 `plenum` 或 `air_terminal` 域）。
2. **第二优先级（物料名称）**：当规格正文无强特征冲突时，以“物料名称”中的核心名作路由依据。
3. **第三优先级（原始分类）**：当正文与名称均无明确否定特征时，退回采用 `category_domain_map.json` 的静态分类映射路由。

### 3.2.2 标准单位换算与数值转换 (Unit Scale Conversion)

物理参数的数值对比建立在相同量级的基础上。在 `IR-1` / `IR-2` 数值提取后，系统强制根据 `unit_norm.json` 中的单位换算关系进行前置量级统一：
* **风量域**：统一换算为标准单位 `m³/h`。若原始单位为 `CFM` (英制风量)，则数值乘以 `1.699`；若为 `l/s`，则数值乘以 `3.6`。
* **压力/余压域**：统一换算为标准单位 `Pa`。若原始单位为 `kPa`，数值乘以 `1000`；若为 `MPa`，数值乘以 `1,000,000`；若为 `mmH2O` (毫米水柱)，数值乘以 `9.80665`。
* **电压/电位域**：统一换算为标准单位 `V`。若原始单位为 `kV`，数值乘以 `1000`。
* **功率/制冷量域**：统一换算为标准单位 `kW`。若原始单位为 `W`，数值乘以 `0.001`；若为 `HP` (匹)，数值乘以 `0.735`；若为 `kcal/h`，数值乘以 `0.001163`。
* **管径尺寸域**：统一规范为公称通径 `DN` (以毫米 mm 为单位)。

### 3.2.3 非标数值与复杂文本结构处理规范 (Non-standard Numeric Parsing)

实际物料规格文本复杂多变，系统在 `IR-2` 提取后增加如下非标数值解析器：
1. **范围值区间解析**：如 `"DN15-25"`、`"风量1000~2000m³/h"`。
   - **解析规则**：抽取并存储为 `{field}_min` 与 `{field}_max` 两个 float 类型的子字段。
   - **匹配计算**：如果一侧为单值 $V$，另一侧为区间 $[V_{min}, V_{max}]$，若 $V_{min} \le V \le V_{max}$，则判定为满分，否则按偏离度计算；若两端均为区间，则计算两个区间的交集重叠度（Overlap Ratio）作为相似度系数。
2. **不等式限制解析**：如 `"壁厚≥1.2mm"`、`"余压<500Pa"`。
   - **解析规则**：抽取为一个结构化 JSON 对象：`{"operator": ">=" | "<=" | ">" | "<", "value": float_val}`。
   - **匹配计算**：匹配时若候选侧的数值满足查询侧不等式的逻辑判定（如候选壁厚为 1.5mm，查询侧为 $\ge 1.2\text{mm}$，判定为 True），则判定相似度为满分（1.0）；反之则给予严重罚分或直接触发 Hard Gate。
3. **约数与标称值解析**：如 `"约3kW"`、`"~500Pa"`、`"电机功率11kW左右"`。
   - **解析规则**：剔除修饰词（“约”、“左右”、“~”、“approx”），保留核心数值（如 3.0 或 500.0）作为标称值（Nominal Value）存储，并将解析置信度标记为“High”。


## 3.3 30 个结构化域设计与字段矩阵
每域划分为 **Must（核心属性）**、**Should（辅助属性）** 与 **Flags（特征旗标）** 三层。详见【附录 A】。

## 3.4 二级子类精细化分流规则（以电气装备电缆为例）
由于部分源品类划分过于粗放（如 `电气装备用电线电缆` 达 2343 行），为了防止电线（单芯）与电力电缆（多芯）被归入同一个 `cable_power` 域造成漏扣分：
* **规则细分分流机制**：
  1. `domain_router` 在收到原始分类 `"电气装备用电线电缆"` 时，先检测规格正文。
  2. 若规格中匹配到典型控制代号（如 `KVV`, `KVVR`, `RVVP`, `控制`），路由至 **`cable_control`**（控制电缆域）。
  3. 若规格中无乘号 `*`，或匹配典型单芯代号（如 `BV`, `BVR`, `BYJ`, `电线`），路由至 **`wire`**（电线域，此域将 `芯数` 降为 Should 或剔除，防止误罚）。
  4. 其余默认分流至 **`cable_power`**（电力电缆域）。
详见【附录 B】。

## 3.6 打分机制配套改造

### 3.6.1 域内字段权重设计
匹配引擎在 `score_candidate` 时从 `domain_schema.json` 读取该域特有的打分权重比例，计算加权属性得分。

### 3.6.2 缺失惩罚细则

为对齐实际业务语义，防止参数越完整的优秀物料反而因为双向比较被扣分（即逆向筛选），惩罚机制修改为**单向非对称惩罚**：
* **触发条件**：仅在**「查询侧明确指定了该参数，但候选物料侧缺失」**时触发扣分惩罚。
* **惩罚力度**（扣减百分制总分）：
  - **Must 字段单向缺失**：`-15 分`（如用户查询指定了“风量”，但库中候选物料无风量）。
  - **Should 字段单向缺失**：`-5 分`。
* **免罚场景**：若查询侧未指定该字段，无论候选物料侧是否有该属性，**均不参与罚分**（0 分惩罚），从而保护参数完备的高质量物料。
* **两侧均缺失**：`0 分`。
* **Flags 一致率缺失**：若某一方具有特有旗标（如防爆），而另一方明确不具有或冲突时进行相应减分。

### 3.6.3 域内硬门槛 (Hard Gates) 拦截机制与参数配置化

为保障硬门槛拦截规则的业务适配性，所有硬门槛规则与具体过滤阈值必须**写入配置文件中进行结构化表示，禁止硬编码**。同时针对小流量/小功率场景增加绝对差值兜底：
* **电力电缆域 (cable_power) / 控制电缆域 (cable_control)**：`芯数` 或 `截面积` 发生实质冲突 $\rightarrow$ **得分封顶 30 分**（可配置参数）。
* **水暖管道 (pipe) / 阀门类 (valve)**：公称管径 `DN` 不匹配 $\rightarrow$ **得分封顶 30 分**。
* **阀门类 (valve)**：连接方式发生硬冲突（如法兰 vs 螺纹，字典同义词不匹配） $\rightarrow$ **得分乘 0.5 系数**。
* **特种门窗 (door)**：洞口宽/高尺寸偏差 $> 10\%$ $\rightarrow$ **得分乘 0.5 系数**。
* **⭐通风机域 (fan) / 空调机组域 (ahu)**：
  - **标准硬门槛**：设计风量偏差 $> 50\%$ 且绝对差值 $> 500\text{ m³/h}$ $\rightarrow$ **得分封顶 30 分**。
  - **⭐小风量兜底门槛（新增）**：当设计风量 $\le 500\text{ m³/h}$ 时，若风量偏差 $> 50\%$ 且绝对差值 $> 200\text{ m³/h}$ $\rightarrow$ **得分同样封顶 30 分**（防止小风扇错配大型风机或反之）。
* **⭐冷热水机组 (chiller) / 空调机组 (ahu)**：额定制冷量/制热量偏差 $> 50\%$ 且绝对差值（可配置）不符 $\rightarrow$ **得分封顶 30 分**。
* **配置化支持**：具体门槛关系（如绝对差兜底值、偏离系数）统一在 `domain_schema.json` 对应域的 `"hard_gates"` 结构中配置，以便按业务场景动态调参，无需修改打分引擎代码。

# 第四章 软件改造 RFC

## 4.1 不变量与安全屏障
* FastAPI 路由前缀与响应结构保持不变；
* 数据库及 API 输出的 `attrs` 仍是 `Dict[str, Any]`，`model` 仍是 `str`（保留 API 契约，前端零改动）；
* ⭐**API 响应自适应别名兼容层 (API Compatibility Layer)**：结构化改造后，内部属性键名全部标准化（如“风量”、“截面积”）。为防止前端渲染时因找不到旧字段名（如 “风量 m3/h”、“截面积 mm2”）发生显示异常，API 在序列化输出 attrs 给前端时，会**自动复制并保留双份 Key 映射**（例如：既返回新标准键 `{"风量": 8000}`，也冗余返回旧键 `{"风量 m3/h": 8000}`），确保前端零改动、零故障。
* SQLite 主表 schema 只**增加**列，不删除老数据列；
* FAISS 向量维度与预训练模型保持不变。

1. **异步计算启动**：`POST /api/db/reparse` 启动后台工作线程。
2. **缓冲表计算**：复制主表 `materials` 结构为 `materials_temp`，后台线程分批（每批 1000 条）应用最新抽取器对 `materials_temp` 进行 `parsed_params` 重新计算并写入。此时主表 `materials` 依然对外提供只读和临时写入服务。
3. **锁定与原子切换**：缓冲表数据写入完毕后，对数据库主表**施加写入排他锁（Write Lock）**。原子级执行表名交换：
   ```sql
   ALTER TABLE materials RENAME TO materials_old;
   ALTER TABLE materials_temp RENAME TO materials;
   ```
   随后立即释放写入锁，将重算期间若有积压的增量写入事务同步应用至新主表，彻底防止数据丢失。
4. **FAISS 索引热重载**：表名交换成功后，**立即后台热重建向量索引并更新时间戳**，触发 `server.py` 瞬间重载内存中的 FAISS 索引。确保外部检索时“数据表与向量索引”版本实时绝对一致，不一致窗口降为零。
5. **清理冗余**：安全删除 `materials_old` 表。
