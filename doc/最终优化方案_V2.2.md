# 企业物料清单智能匹配工具最终优化方案 (V2.2)

对《企业物料清单智能匹配工具优化技术方案 V2.1（终稿）》进行了深度审查与架构分析，评估了其在当前轻量化系统（FastAPI + SQLite）下的适用性与可行性，针对潜在的中文检索分词失效、CPU并发推理瓶颈、Excel非破坏性写入等风险，提出了关键优化升级，形成本版最终优化方案。

---

## 一、 方案适用性与可行性评估

### 1. 适用性分析（高）
*   **架构契合度**：方案坚持不引入外部复杂中间件（PostgreSQL, Elasticsearch, Milvus, Redis），采用本地 SQLite + 内存向量检索的单文件轻量化架构，非常适合目前的企业通用物料匹配工具，降低了运维门槛，具备高可用性。
*   **痛点覆盖面**：全面针对召回不足、参数解析不准、打分权重单一、性能卡顿以及自迭代能力缺失等痛点进行了针对性设计。

### 2. 可行性分析（高）
*   **计算资源**：4.6万条物料对应的 384 维向量在内存中仅占用约 70MB 空间。轻量级 MiniLM 模型在 CPU 上的推理延迟为毫秒级，符合内存增量 $\le 250\text{MB}$、进程峰值 $\le 250\text{MB}$ 的硬性资源约束。
*   **检索耗时**：SQLite FTS5 和内存向量检索均为毫秒级响应，单行检索耗时 $\le 150\text{ms}$ 在工程上完全可行。

---

## 二、 方案存在的潜在缺陷与优化建议

在可行性评估中，我们发现了以下 **5 个核心技术风险/不足**，并在本最终方案中给出了相应的优化建议：

### 1. SQLite FTS5 的中文分词“分词失真”问题（核心风险）
*   **缺陷**：原方案和现代码使用 `tokenize="unicode61"`。对于中文，该分词器将连续的中文字符串视为单个词（例如“新风机组”是一个词）。当用户输入包含“新风”或“机组”时，无法匹配到“新风机组”；并且由于工业规格没有空格分隔，FTS5 检索率会极低。
*   **优化建议**：
    *   **方案 A (推荐)：字符级空格分词（Char-Spacing）**。在写入 SQLite `materials_fts` 虚拟表前，对中文文本进行“单字空格切分”（例如“新风机组”转化为“新 风 机 组”），查询时对查询词也进行同样的单字切分。这样可以使 FTS5 在无需安装第三方 C 语言中文分词插件的前提下，完美实现中文的字词匹配和高召回。
    *   **方案 B**：引入 `jieba` 分词器将文本分词后以空格拼接存入虚拟表。考虑到离线部署和纯 SQL 触发器的便捷性，方案 A 更为轻量且无漏词风险。

### 2. 向量编码（Model.encode）的 CPU 多线程瓶颈
*   **缺陷**：原方案设计“分片进入线程池并发执行单行匹配全流程”。如果在每个线程中单独调用 `model.encode(single_text)`，会导致 PyTorch/ONNX 频繁在多线程间争抢 CPU 资源（甚至导致死锁或 CPU 满载），且单条编码无法利用矩阵计算的并行优势。
*   **优化建议**：
    *   **向量批处理化（Batch Encoding）**：在分片进入多线程匹配之前，在主线程中一次性将当前分片（如 500 行）的所有清洗后文本收集起来，调用 `model.encode(texts, batch_size=64)` 进行批量编码，再将计算好的向量分发给各行匹配线程。这可以减少模型推理次数，降低 70% 以上的 CPU 开销，匹配性能将提升 3~5 倍。

### 3. FAISS 在 Windows 离线环境下的安装兼容性
*   **缺陷**：`faiss-cpu` 在 Windows 平台上的 pip 安装有时依赖特定版本的 Visual C++ Redistributable，且在某些完全脱网的内网环境中容易安装失败。
*   **优化建议**：
    *   **Numpy 向量计算双轨备份**：4.6万条 384 维的向量矩阵大小仅为 `(46000, 384)`。在 Python 中直接使用 Numpy 进行矩阵点积计算相似度：`similarities = np.dot(matrix, query_vector)`。
    *   在单 CPU 核心上，Numpy 矩阵乘法计算 4.6 万行相似度仅需 3~5ms。因此，系统应实现 `FAISS` 优先加载，若加载失败自动降级到 `Numpy` 矩阵检索，确保 100% 部署成功率。

### 4. Excel 非破坏性回写（避免数据丢失）
*   **缺陷**：原方案中 `report_generator.py` 会执行 `sheet.delete_rows(3, max_r - 2)`，删除第3行之后的所有内容，并只写回本次匹配的行。在实际业务中，原始 Excel 模板中可能包含其他专业的物料行、人工录入的历史行，或者底部的合计公式行。直接删除会导致非本批次数据丢失。
*   **优化建议**：
    *   **精准替换/追加机制**：根据前端传递的 `original_row_idx`，仅对模板中对应的行号进行内容重写和样式套用；如果是追加新行，则在末尾插入，避免执行全表删除，无损保留其他专业和表格底部的汇总公式。

### 5. 多专业参数匹配噪声过滤
*   **缺陷**：不同专业（暖通、电气、给排水）的核心参数截然不同。如果通用正则抽取器在电气元器件的描述里抽出了“尺寸”或“功率”，并套用了暖通的公差，会产生严重噪音。
*   **优化建议**：
    *   **参数抽取 Schema 配置化**：通过行业配置后台，不仅外置公差，还要外置**参数抽取白名单**。例如：当品类判定为“电气”时，仅激活“电流/电压/极数/功率”正则，屏蔽“风量/余压/管径”正则，防止参数串扰。

## 三、 最终优化技术方案 (V2.2) 详细设计

本方案在 V2.1 架构基础上，融入上述 5 项优化建议，构成最终实施方案。

### 3.1 文本标准化与多专业参数抽取（优化版）
1.  **分词预处理**：
    *   为支持 SQLite FTS5 的中文高精度检索，在写入 `search_tokens` 和 FTS 表时，对中文部分进行单字空格化（例如：`防排烟阀` $\rightarrow$ `防 排 烟 阀`）。
2.  **单位与规范词归一化**：
    *   符号清洗、别名替换、错别字修正（通过 `config/alias_dict.json` 热加载）。
3.  **多专业参数抽取管道**：
    *   根据物料品类（Category）自动加载参数过滤 Schema，提取指定的核心物理参数，未匹配的参数置 `None`。

### 3.2 双路混合召回引擎（双轨高可用）
1.  **关键词召回 (SQLite FTS5)**：
    *   对清洗后的查询词进行单字空格化，转化为 `MATCH '"新" AND "风" AND "机"'` 进行 FTS5 检索，召回 Top 300。
    *   单独对型号字段执行 `LIKE 'model%'` 前缀召回。
2.  **语义向量召回 (FAISS / Numpy 双轨)**：
    *   使用 `paraphrase-multilingual-MiniLM-L12-v2` 提取 384 维向量。
    *   优先加载 `faiss-cpu` FlatIP 索引检索 Top 200；若 FAISS 模块缺失，自动无缝降级为 `Numpy` 点积相似度计算，保障离线单目录运行稳定性。
3.  **合并策略**：去重合并两路候选，上限 800 条。

### 3.3 自适应动态打分与阶梯公差过滤
1.  **场景权重模板配置化**：
    *   **场景 A (含型号)**：型号(50%)、参数(30%)、文本相似度(20%)，语义向量贡献额外 Boost。
    *   **场景 B (无型号有参数)**：参数(50%)、文本相似度(30%)、型号相似度(10%)、基础属性(10%)。
    *   **场景 C (纯文本无参数)**：文本相似度(60%)、语义相似度(30%)、基础属性(10%)。
2.  **工业阶梯公差计分**：
    *   偏离度 $D = \frac{|V_{query} - V_{cand}|}{\max(V_{query}, V_{cand})}$
    *   $D \le T$（公差）：得满分。
    *   $T < D \le 2T$：得分线性衰减至 0.5。
    *   $D > 2T$：最低保留 0.1 分，不完全淘汰（防止特殊非标设备漏匹配）。
3.  **Boost 偏置调整**：
    *   **正向**：品牌匹配 (+10)、分类完全匹配 (+8)、系列一致 (+5)。
    *   **负向**：分类强冲突 (-30)、管径尺寸严重不匹配 (-30)、介质冲突（冷/热，-20）。

### 3.4 2000行大清单分片与批量推理优化
1.  **主线程批量编码**：批量上传 Excel 后，后端首先一次性批量抽取所有数据行的清洗文本，使用 `sentence-transformers` 进行批量 Encode，获取所有行的向量表示。
2.  **分片线程池执行**：将批量计算好的向量与行数据结合，拆分为 500 行/分片，送入包含 10 个线程的线程池中进行纯 CPU 的 SQLite 检索与打分排序，避免线程间的 PyTorch 模型锁竞争。
3.  **降级熔断**：单行处理设置 500ms 超时阈值，超时自动关闭向量计算，降级为纯 FTS 匹配。

### 3.5 交互与自学习迭代
1.  **三色状态看板**：精确匹配（绿色，Score $\ge 85$）、待校对（黄色，$40 \le \text{Score} < 85$）、未匹配（红色，Score $< 40$）。
2.  **参数补全与实时重匹配**：前端弹窗人工补充/修正参数，点击立即调用 `/api/rematch` 重新计算当前行的 Top 3 推荐。
3.  **自学习审核机制**：人工确认修改的匹配样本提交至后台，自动分析并推荐新的别名/错别字到后台配置页面，由管理员“一键确认”写入配置文件并实时生效。

### 3.6 非破坏性 Excel 导出回写
1.  **行定位回写**：加载 `标准格式.xlsx` 模板，不删除整表。通过匹配结果中的 `original_row_idx` 定位到对应单元格，精确重写“清单编码”、“材料类型”、“清单名称”、“特征/规格型号”及“单位”、“工程量”、“损耗”等。
2.  **样式与价格保留**：使用 `copy` 模块深度克隆模板行的单元格格式。基于物料编码自动比对并回填历史单价。

## 五、 交付与验收指标

### 1. 成功率指标
*   综合匹配成功率：$\ge 85\%$（500行真实业务测试集测试）。
*   带完整型号匹配率：$\ge 95\%$。
*   无型号纯参数匹配率（Top 1）：$\ge 82\%$。
*   无字面重合纯语义场景匹配成功率：$\ge 70\%$。

### 2. 性能指标
*   **批量处理耗时**：2000 行清单整体处理总耗时 $\le 18\text{s}$。
*   **单行实时匹配**：端到端平均响应时间 $\le 150\text{ms}$。
*   **内存占用**：进程内存峰值增量不超过基线 250MB。

### 3. 健壮性指标
*   **离线部署**：不连接外网情况下，一键启动能够自动加载本地模型并提供完整语义检索。
*   **免 FAISS 运行**：即使脱网环境无法安装二进制 `faiss-cpu` 包，系统也能无缝降级使用 `numpy` 进行向量检索，且检索准确率不发生任何衰减。
