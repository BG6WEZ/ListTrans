# TMP-MAT-SYNC：物料库每周增量同步方案 R1

日期：2026-11-17（Asia/Shanghai）；编制：统筹 AI。

状态：**方案研究完成，待接口确认与方案评审；未下发开发，未连接源库，未部署定时任务。** 用户本轮要求为主线外临时任务的方案研究。源视图说明作为接口资料阅读，其中的连接信息和操作建议不视为实际连接、使用管理员账号或修改源端的授权。

## 1. 结论与任务边界

建议在局域网 ListTrans 服务器上运行独立的一次性采集任务：首次低峰初始化，之后**每周一北京时间 04:00**读取源端变化，在本地合并、校验、构建候选库和索引，再由应用内受控服务发布。用户无需每周导出、上传 Excel。

当前 `v_material_detail` 可以作为活动物料读取接口，但**单靠该视图的 `updateTime` 条件不能保证完整同步**。正式无人值守启用前，必须确认新增时间、失效事件、分类变化和迟提交语义；否则只能作为有已知缺口的隔离试验，不能宣称物料库已与源端一致。

只在 ListTrans 侧写入。采集器不向源库写业务数据，不建表、改视图、建索引、建触发器、配置数据库定时事件或订阅复制；源端确需完善接口时，由源软件方评估和实施。只读查询仍有 CPU、I/O、网络及元数据锁成本，不能承诺绝对零影响，必须用索引、限额和源方监控把影响控制在其批准预算内。

本任务独立编号 `TMP-MAT-SYNC`，不回填为 V0.1.5 已验收功能。V0.1.6～V0.2.0 继续锁定；现有终审记录不改写，PRG-F11 生产门禁保持。后续开发仍逐包下发、开发与审核交替。

## 3. 运行架构

```text
局域网服务器的系统调度器（周一 04:00，Asia/Shanghai）
    → 一次性采集器：专用只读账号，单连接、分页、有预算
    → 本地不可变批次文件 + 清单/校验和（采集结束即断开源连接）
    → 本地源数据镜像：按 source + materialId 合并和比较内容哈希
    → 新一代候选物料表 + FTS + 向量索引/缓存
    → 应用内唯一发布服务：校验、短暂读写门禁、发布、核验
    → 成功提交同步游标；保留上代以便回退
```

采集器只负责取数和投递本地批次，不直接更新运行中 SQLite，也不独立修改应用的向量缓存。推荐采集器通过仅限本机/内部网络的专用入口投递批次，应用内服务完成合并和发布；具体入口为待开发能力。使用独立、受限的机器身份，不借用个人管理员登录、不绕过现有权限、不允许任意路径或任意 SQL。

优先结构化 JSONL（逐行 JSON）加 manifest，保留源字段、NULL、整数和时间；业务 Excel 仅作按需导出，不做默认周转格式。所有原始数据、镜像和备份留在受保护的局域网持久目录，不进入 Git、镜像构建上下文或普通诊断日志。

## 4. 初始化

1. 源软件方确认真实库名、MySQL/MariaDB 及版本、存储引擎、账号权限、视图定义、规模、低峰窗口和查询预算；完成只读执行计划评估。优先使用其现有只读副本或离线快照；副本须有复制延迟水位，不能仅用副本墙钟认定数据已追平。
2. 在约定低峰首次读取全部活动记录，按 `materialId` 游标分页，每次仅取必需列。固定 `materialId` 排序，不用 OFFSET。初始化不是以后每周全量重读的理由。
3. 小规模且源方同意时，在有明确时长上限的 InnoDB 只读一致性快照内完成。若超过预算，终止并改用源方提供的快照/导出；不通过长时间持有源事务来换取一致性。不在分页之间换快照后仍声称是同一时点全量。
4. 记录初始快照边界；以快照开始前的安全时间边界建立增量起点，并回放交界窗口。该方法仍依赖第 5 节的迟提交约束和第 6 节的失效/分类事件，不单独保证不漏。
5. 在本地建立 `materialId → materialCode` 映射，逐项对照当前人工库，输出新增、变更、冲突和仅本地存在的记录。初始化不盲目覆盖：本地独有物料、描述、停用注释须先确定归属和保留策略；没有源 ID 的历史记录不能自动判成已删除。
6. 通过字段、编码、单位、分类/品牌语义和真实匹配冒烟后，首次发布完整本地库。初次真实迁移和上线属于后续独立操作，本轮未执行。

## 5. 周增量与时间边界

### 5.1 时间定义

接口语义应为：`effectiveChangeTime = COALESCE(updateTime, createTime)`，新增记录在 `updateTime IS NULL` 时按创建时间获取。源方需确认修改时间不早于创建时间、创建后所有相关变化都会刷新时间、时间不会回填到已过水位。

源时间为说明中的北京时间 DATETIME，字段本身不携带时区。采集前核对源时钟、会话时区和实际字段语义；本地用显式 `Asia/Shanghai` 解释后存标准时间，不能把北京时间直接当 UTC。

每次运行使用：

- `W`：最后一次**成功发布**的覆盖上界。
- `L = W - overlap`：重叠读取下界。
- `H = 源端当前时间 - safety_delay`：本次固定上界；读取 `[L, H)`。
- 初步候选值：`safety_delay=10分钟`、`overlap=30分钟`，均需依据源方最长事务/复制延迟、时钟误差和负载签认，不能直接当成安全保证。

不要只查“最近七天”，连续失败时仍从最后成功水位追赶；不要用 `MAX(updateTime)` 代替已完整覆盖的上界。所有分页完成并发布成功才把 W 推进到 H；空增量也只有在接口契约完整且所有读取成功时才能记录该区间已覆盖。

**迟提交限制**：若一笔事务在写入更新时间后很久才提交，或允许回填旧时间，有限重叠窗口仍可能漏掉它。必须有可验证的延迟上界，或采用源方提供的可靠已提交变更游标/安全水位与补偿接口。普通自增 ID 也不天然等于提交顺序。无法满足时禁止承诺无遗漏；需额外批准定期核对，不能通过任意增大 overlap 掩盖问题。

### 5.2 查询草案（不是已验证的生产 SQL）

为了给索引范围扫描留出空间，优先把“已修改”和“从未修改”拆为两路，分别在其时间字段上分页，而非每页对整个视图计算 COALESCE 后排序。以下仅展示已修改分支，`:参数` 由驱动绑定，不进行字符串拼接：

```sql
SELECT materialId, materialCode, materialName, categoryId, categoryName,
       unitName, spec, brandId, brandName, createTime, updateTime
FROM `确认后的库名`.`v_material_detail`
WHERE updateTime >= :low_time AND updateTime < :high_time
  AND (updateTime > :last_time
       OR (updateTime = :last_time AND materialId > :last_id))
ORDER BY updateTime, materialId
LIMIT :page_size;
```

首批省略分页续传条件；后续使用上一页最后一行的 `(updateTime, materialId)`。第二路增加 `updateTime IS NULL`，将时间范围、排序及续传字段改为 `createTime`。两路本地按 source + materialId 合并，记录分页期间重叠/变动冲突，不能按编码随意丢行。时间并列用 ID 排序，不单独使用 `updateTime > 上次时间`。

`createTime/updateTime` 双空记录在初始化时隔离并报告；若后续新增仍可双空，现有时间接口无能力发现，必须由源方修正契约或提供补充接口。时间异常、未来时间、倒退时间不静默跳过；阻断批次并报告。

初始化可能已包含安全上界之后的更新，所以本地镜像需保留行版本时间/内容哈希，重复或较旧版本不得覆盖已保存新版本。同 ID、同时间、内容不同须重新核对或阻断，不能假设秒精度时间唯一标识一次修改。采集断线默认废弃未完成批次，下次在批准窗口重取固定区间，不能将不稳定分页位置当成已完成水位。

这些条件是否能下推、是否命中物料底表的时间/ID 索引、分类关联是否高效，均由源方使用实际 DDL 和只读 EXPLAIN 验证。少返回行数不等于少扫描；不以 LIMIT 证明低负载，不在源库执行 EXPLAIN ANALYZE 或自动建索引。

## 6. 当前视图必须补齐的正确性问题

| 缺口 | 只靠当前视图为何不足 | 正式启用所需处理 |
|---|---|---|
| 删除/停用/隐藏 | 记录从视图消失，增量查询没有可返回的失效行 | 首选源方提供带状态/失效标记的增量接口，涵盖软删、硬删、隐藏、停用及重新启用；硬删需有保留的事件/墓碑。仅增加状态列但仍过滤失效行也无效。 |
| 分类变化 | 分类名、常用品牌、分类删除或父级品牌继承变化，可能不更新物料时间 | 由源方保证有效变更时间覆盖所有输出依赖，或提供分类变更与受影响物料接口；分类删除时须保留原分类 ID 以定位本地关联。 |
| 时间缺失/回填/迟提交 | 时间窗口看不到窗口外才变得可见的变化 | 确认新增时间、最长迟提交和回填约束，或提供已提交安全水位/可靠变更日志。副本延迟也计入。 |
| 状态恢复 | 物料重新进入视图但原更新时间不刷新时，仍不会被取回 | 重新启用、取消隐藏等也必须产生可读变更。 |

**推荐优先与源方落实增量契约，再做自动化开发。** 可继续读原视图获取详情，由额外只读状态/分类变更接口补齐；也可由其提供一个覆盖全部上述语义的新版视图。我们不擅自改源端。不要仅以 `GREATEST(物料时间, 分类时间)` 的公式代替完整事件语义，仍需核实 NULL、分类删除、父级继承及时间索引。

若源方暂时无法补齐，备选是其明确允许的、在周一同一窗口进行的精简活动 ID/分类信息核对，或由其交付可核验的快照文件。此类核对仍可能扫描全表，与“初始化后仅按时间增量”不是一回事，必须先评估和同意，**默认不启用**。完整、同口径、未超时的核对才能据此判断失效；增量没出现、查询出错或返回空集均不能触发批量停用。只做月度核对则必须接受最长一个月的失效滞后，不可描述为每周同步完整。

如以上补充均不可用，结论是“可做新增/修改试验，无法完成可信的无人值守全状态同步”，保留现行人工流程，不自动切换为权威库。

## 7. 字段映射与身份

| 源字段 | 本地处理 |
|---|---|
| source + materialId | 源镜像的稳定唯一键；BIGINT 按精确整数或十进制字符串保存，不经过 Excel 浮点或 JavaScript 不安全整数转换。 |
| materialCode | 应用业务编码 `code`；保留前导零。源内重复、空编码或不同 ID 争抢同一编码时阻断发布，不沿用 Excel 导入的“较完整者胜出”。 |
| materialName / spec / unitName | 映射名称、规格、计量单位；保留 NULL 与空串差异供校验。名称空、必需单位缺失等须有锁定口径。`spec` 不等于 `model`，不能自行拼造型号。 |
| categoryId / categoryName | 保留源分类 ID；映射分类展示名，分类缺失要可识别；不按名称当永久身份。 |
| brandId / brandName | 保留“分类常用品牌”的来源属性；不能未经评审就作为物料真实品牌进入硬约束/确认/导出。若沿用当前品牌列，必须验证与原 Excel 语义一致并明确业务接受，否则保留为辅助信息，实际品牌未知。 |
| createTime / updateTime | 原值和规范时间同时保留，用于增量与追溯。 |
| 描述、型号、物料/设备类型 | 当前视图未提供；描述保留策略和类型范围待业务确定，禁止用空值覆盖全部历史人工描述。需区分设备时由源方提供 itemType。 |

改码按同一 materialId 更新映射并从候选活动库移除旧编码，不生成两个当前物料；编码交换/重用必须在整批最终状态验证。旧清单、草稿、绑定规则仍引用旧码时应提示重选，不能静默改绑；同编码改了规格/单位/身份时，也须使受影响确认失效并重新校验。保留既有导出确认门禁，不能因定时同步绕过。

源数据镜像是事实层，匹配用物料库是派生层。沿用现有停用注释业务规则前须确认口径；因本地规则排除的行应保留原因和源身份，不删除原始证据。自动任务明确禁用付费 LLM 和自动下载模型，使用已批准的本地模型与解析配置。

## 8. 本地发布、恢复与回滚

新增本地持久状态至少包括源镜像、ID/编码映射、批次日志、成功水位、候选 generation 和活动 generation。镜像/映射与业务库的新一代对应，不能采集一结束就更新权威镜像和 W。

1. 先检查磁盘、前次未完成发布、恢复阻断和目标库基线；采集进程互斥，加应用内统一物料写入口互斥。等待目标发布权时不保持源连接。
2. 批次须有 source、接口版本、L/H、分页完成标记、行数、字段契约、文件哈希和版本信息；本地重试优先复用已完成批次。基线变化则重新校验合并，不直接套用旧候选。
3. 本地合并得到完整候选库，计算新增/修改/失效/改码数量，验证编码唯一、有效记录非空、字段与身份完整、异常变化阈值。异常批次冻结，不发布、不推进成功水位；异常阈值在摸清规模后锁定，不能临时降门槛。
4. 构建候选 FTS 与向量索引，首版可在本地完整构建候选索引；这不增加源库读取。只有真实内容变化才重建；零变化记录成功检查即可。索引增量优化待实测，不承诺首版只计算变动向量。
5. 复用现有提交仲裁和可逆发布服务，新增同代读门禁：交换期间新匹配/查询/导出等待或返回明确维护状态，处理在途请求，避免新 DB 配旧内存索引。现有导入锁不能自动保证这一点。
6. 本地 DB 事务联动候选物料/FTS、源镜像/映射和待提交同步状态；内存、磁盘索引与缓存均通过核验后才标记整批成功、推进 W。明确清理编码/关键词/分类及其他物料相关缓存；不能只刷新分类。
7. 跨 SQLite、内存和文件的发布没有单一数据库事务，需持久化发布日志记录各阶段和前后 generation。进程被杀/断电后，启动先判定恢复，禁止直接加载半代数据；恢复至完整旧代或完整新代再开放业务。水位不得领先于可服务版本。现有异常回滚能力不能代替这项崩溃恢复验收。
8. 任何层恢复失败，沿用并扩展现有持久化阻断，保留 stage/old/backup 和日志，禁止自动解锁或自动删除恢复材料。成功发布核验后才清理前代；回退同时恢复物料、索引、镜像、映射和水位，不恢复账号/规则等无关数据库。

源同步成为权威来源后，普通人工 replace/append 默认停用或明确要求进入维护模式；维护修改将改变本地 generation 并使旧候选失效。避免周任务覆盖人工修改。回滚包建议保留最近四次成功代，具体容量与保留期实施前核定；业务原件不纳入普通临时文件清理。

## 9. 源库保护预算

下列为首轮候选参数，**不是源方已批准的性能指标**：

| 项目 | 建议起点与失败行为 |
|---|---|
| 周期 | 周一 04:00 一次作业；按数据量分多条分页 SELECT；非窗口不轮询、不做分钟级连通性探活。 |
| 并发 | 1 个源连接、1 路分页，约 500～1000 行/页、页间至少 200ms；不并行扫表。 |
| 权限 | 专用账号，仅 SELECT 已批准视图，限制来源服务器 IP；由源方配置视图安全上下文，不顺便授予底表/整个库权限。不用说明附带的高权限账号。 |
| SQL 边界 | 固定白名单 SELECT，无存储函数副作用；无 FOR UPDATE/FOR SHARE、LOCK TABLES、DML/DDL、INTO OUTFILE 或源端临时表。只读会话配置仅作补充，不替代最小权限。 |
| 超时 | 候选连接 5 秒、单语句服务端 5 秒、客户端读取 10 秒、常规源采集总预算 10 分钟；实际版本支持的服务端限时必须验证生效。客户端超时不代表源语句已停止，确认自身连接结束，不重复叠加。 |
| 预算/索引 | DBA 明确扫描行数、耗时、CPU/I/O 或业务延迟阈值；EXPLAIN 发现全量物化/扫描或超预算就不启用。底表索引由源方按实际选择度评估，我们不执行 CREATE INDEX。 |
| 故障 | 过载/慢查询/权限/契约错误立即停止；不自动全量兜底。网络瞬断最多在批准窗口延后重试一次；窗口外只记录失败，等下一窗口或人工安排。 |

普通 InnoDB 一致性 SELECT 在适当隔离级别可不加行锁，但引擎、隔离、元数据操作和视图实现均需核对；即使无行锁也会消耗资源。MySQL 官方说明见第 12 节。源服务器版本未知，不能直接假设支持 MySQL 8.4 的超时提示，也不能以提示被忽略后正常返回当成超时已生效。

## 10. 调度和运维

目标为 Linux + systemd 时，建议宿主机 timer 调用一次性采集器，而非把第二个常驻 Web 进程当计划任务；Windows 服务器则用任务计划程序运行同一个一次性程序。当前仅提出方案，不在本机 Codex 建提醒或安装任务。

Linux timer 核心配置草案：

```ini
[Timer]
OnCalendar=Mon *-*-* 04:00:00 Asia/Shanghai
AccuracySec=1s
RandomizedDelaySec=0
Persistent=false
```

显式使用北京时间；实际系统验证配置语法和未来触发时间，04:00 是触发时刻，不承诺该时刻已完成。配套 service 采用单次任务，禁止无界自动重启。`Persistent=false` 避免错过任务后在工作时间自动补查源库；同时本地记录“错过本周同步”，下次窗口从 W 追赶。如以后选择自动补跑，仍须程序端限制在批准低峰，不能简单改成 true 后允许白天补查。

建议源访问窗口暂定周一 04:00～04:30，超过窗口不再发起源查询；总采集预算仍受第 9 节约束。窗口、初始化窗口、重试及目标本地构建时限均需与双方服务器维护计划对齐。

记录每批：计划/开始/结束时间、L/H、接口与配置版本、分页/读取量、重复/冲突量、新增/修改/失效量、源耗时、本地构建/发布耗时、generation、成功水位、失败阶段、回滚/阻断状态。日志不含密码、完整连接串或逐行业务明细。业务端显示最近成功时间、同步结果、数据覆盖上界及失败后沿用的库版本，不能把任务启动显示成同步成功。

失败、错过窗口、异常变更或过期未同步要有本地告警记录和运维可见状态；消息通知渠道待选定，研究阶段不发送外部通知。凭据通过服务器受限文件/秘密挂载提供，不入仓库、镜像、参数列表或普通日志；源说明已含明文管理员凭据，不复制、不提交，源方应评估原凭据处置并换发专用账号。

必测风险场景：

- 初始化交界更新；新增但 updateTime 为空；双空时间拒绝；同秒多页；分页期间改行；重叠重放不重复、不回退到旧版本；延迟提交越过窗口能被契约识别或阻断上线。
- 删除/停用/隐藏/恢复、分类改名/删分类/品牌继承变化；缺补充接口时不得伪称支持。
- 改码、编码交换/重用、重复/空码、BIGINT 精度、NULL/空串、缺分类、设备范围、常用品牌与实际品牌、描述保留；关联草稿/确认/导出不得静默错绑。
- 断线、超时、源慢、读权限不足、字段漂移、磁盘满；任何不完整批次不发布、不推进水位；零增量不误删。
- 人工导入并发、重算/刷新并发、在途匹配/导出跨代、候选基线过期；全部走同一目标发布门禁。
- DB/FTS/内存/磁盘任一步失败和恢复再失败；每个持久化发布阶段强杀/重启，核对 DB、源镜像、映射、索引与 W 一致，并检验持久化阻断。
- 北京时区与容器 UTC、周一触发、重复触发、错过窗口、重启、重试次数和窗口限制；源方确认扫描/耗时预算内且权限不允许写入。验证写权限拒绝优先查授权清单或在隔离副本完成，不在生产库试写。

落地前需确认的最小信息：**目标服务器系统/部署方式与路径；源软件方专用只读账号与真实数据库版本/库名；失效及分类变化的补充接口；时间刷新/迟提交保证；数据规模、执行计划与可接受预算；物料/设备及品牌/描述口径。** 不需要在聊天或文档中提供密码。
