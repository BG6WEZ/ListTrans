## 四项重点复核

### 1. exact_code 硬约束不绕过 — 通过
- **真实接线**：`matcher.hybrid_recall` 中 `recall_by_standard_code` 命中仅写入 `candidates` 并打 `recall_source="exact_code"`，随后所有候选（含 FTS/向量/结构化）在 `match_item` 中统一经 `score_candidate_with_detail` 评分；系列加分明确跳过 `hard_blocked` 候选，自动接受要求 `score>=75 且 not hard_blocked`（`matcher.py:2558-2620, 2726-2727`）。源码中 DN 封顶 `max_score<=0.15`、品牌 `hard_blocked=True/max_score=0.0` 的不可逆语义与 V015-M3 保持一致，本包未削弱。
- **真实断言**（`test_v018_m0_structured_recall.py`）：精确码命中 DN 冲突 → `score<=15, max_score<=0.15, is_exact=False`；品牌冲突 → `hard_blocked=True, max_score=0.0, is_exact=False`；未知码不伪造候选；项目码/位号/命名空间重叠正确分离。109 passed 中这些断言真实执行通过。
- 首跑日志中 `test_exact_code...` 曾因 top-10 截断取不到目标候选失败，开发改用 `diagnostic_targets` 精确定位后断言强度未降低（仍核 hard_blocked/max_score/is_exact），属测试方法正当修正，非放宽门禁。

### 2. 低置信/未知域跨域召回 — 通过
- `recall_by_structured_fields` 以 `low_conf_or_unknown = (domain=="generic") or (confidence<0.80)` 判定（`structured_recall.py:651`）；高置信域在 `_DOMAIN_FAMILIES` 兼容域族内精确召回并对稀疏查询追加强多字段跨域回退（S5/S6），低置信/generic 走显式跨域分支（S1～S4）；材质冲突在 `_material_compatible` 与 `respect_material` 下仍被拦截，不会因跨域而误扩材质。
- 断言：未知域 + 316L + DN15 命中 316L 而不命中 304、`cross_domain_allowed=True`；未知域 + De32 正确识别为外径（DN=None）不混淆。四组评测 GT-0674/0677/0678 均保持 `recommended`；误自动绑定 `0/766`（四组全 0）。

### 3. db_revision 索引失效与独立副本 — 通过
- `StructuredCatalogSnapshot` 以 `db_manager._catalog_key() = (db_identity, db_revision)` 绑定；`get_structured_index` 在 revision 变更时于 `_INDEX_LOCK` 下原子重建，导入/重解析/回滚触发 revision 递增即自动失效（`structured_recall.py:443-567`；`db_manager._next_db_revision/read_db_revision/_catalog_key:85-119`）。
- 候选由 `to_candidate_dict()` 每次新建字典返回；断言验证 revision 递增后新物料进快照、且修改返回 dict 不污染快照（`MUTATED` 不复现）。`query_by_code` 走 `deepcopy(_query_by_code(key,...))`，与 V017-M2 无共享可变对象契约一致。

### 4. Train/Dev 配对与预算合规 — 通过
- 评测脚本 `m0_r01_eval.py` 断言 `Train+Dev==1060` 且逐条排除 test split，Test 160 条零接触；golden/governance/catalog 哈希四组完全一致（c8909a21…/738a7edc…/d2ac87ff…），同分片 OFF/ON 配对、同模型同预算。
- 配对差：关键词 R@100/200 `+72/+66`、BGE `+46/+26`；分域 Recall 全专业无退化。预算：单条 P95 关键词 264.574ms/BGE 315.557ms（≤300/375ms）、50 行上传 P95 7.643s/9.653s（≤10.0/12.5s）、峰值工作集 707.48/1734.68 MiB（≤768/2048 MiB），**全部在 V0.1.7 签认上限内**。
- 通道贡献可追溯：关键词独占结构化 59+13=72 槽位，BGE 20+6=26，与 R@K 增量吻合。
