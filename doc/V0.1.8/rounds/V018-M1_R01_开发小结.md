## 一、实现内容

1. **规范名称与限定域别名治理（`app/recall_candidates/v018_m1_aliases.json`、`app/sparse_recall.py`）**：
   - 冻结 `config/alias_dict.json` 保持 0 字节只读，全部候选别名规则放入独立版本化配置 `v018_m1_aliases.json`（`v018-m1-alias-candidates-v1`）。
   - 承接 V017-M1 延期的同品类过度具体化映射治理：登记并抑制 25 条向查询注入具体规格/材质/芯数/口数/气种或导致二次重复展开的映射（如 `控制线 -> WDZB-RYY 7*1`、`光纤 -> GJPFJV型8芯单模室内光缆`、`气体终端 -> O2气体终端`、`插座 -> 防水五孔插座`、`网络配线架 -> 48位机架式光纤配线架`、`脱脂不锈钢无缝钢管 -> 304 AP脱脂不锈钢气管` 等），保留既有 5 条跨品类黑名单（`CROSS_DOMAIN_ALIAS_BLOCKLIST`）。
   - 缩写严格绑定专业与词边界：`AP/AL/ALE/AT/ACP/AX/ATD/AFC` 仅在 `强电` 独立词位生效（不再污染医用气体 `304 AP脱脂不锈钢气管`）；`AHU/PAU/FCU/MAU/RAU/RCU/VRF/VRV/FFU` 限定 `暖通`。
   - `canonicalize_sparse_query_name()` 从未受污染的 `original_name` 出发，清洗设备位号/箱号（`AHU-J-01`/`PAU-D301`/`AP-1`）、前导数量词（`2个`/`1套`）与括号噪声，避免误扩材质或物理规格。
2. **多级稀疏 FTS 召回与来源/排名透传（`app/db_manager.py`、`app/sparse_recall.py`、`app/matcher.py`）**：
   - `app/db_manager.py` 新增只读修订绑定入口 `search_materials_fts_raw()`（复用 `materials_fts`、`@catalog_read`、`_catalog_key()` 缓存失效及 `deepcopy` 独立副本）。
   - `recall_sparse_candidates()` 实现 4 级有界稀疏通道（默认预算上限 `sparse_limit=60`）：
     1. `sparse_name_param`：干净规范名 + 查询自有物理参数锚点（电缆型号+芯数截面、光纤芯数/单多模、气种、材质+DN/OD、2D 尺寸、口数、功率；严禁臆造规格）。
     2. `sparse_alias`：专业限定同义/上位词扩展，优先组合查询自有参数锚点。
     3. `sparse_phrase_split`：长 AND 拆分（剥离施工/安装修饰停用词 + 中心词提取 + 词组降级），处理长施工文本与同名异规格。
     4. `sparse_param_fallback`：稀疏时用 FTS5 BM25 OR 词元回退，替代原先无语义的 `q_name[:4]` 截断。
   - 保留渠道名（`recall_source`/`recall_sources`）、各渠道 1-based 渠道内排名（`channel_ranks`）及入池原因（`recall_reasons`），同步透传至 `match_item` 的 `top_candidates` 与 `diagnostics`。
3. **独立开关、交互与回退边界**：
   - 新增独立开关 `LISTTRANS_V018_M1_RECALL`（默认 `"0"` / `False`，支持 `recall_options["v018_m1_enabled"]` 覆写），`LISTTRANS_V018_M0_RECALL` 保持默认 `"0"`。
   - `M0=OFF, M1=OFF` 完全跳过 M1 逻辑，实测 6 项排序指标与候选池均值和 M0 放行 OFF 100% 逐项相等（`rollback_parity_vs_m0_off` 全 `True`）。支持与 M0 组合开启，另行单列实测。向量编码、TopK/RRF、排序权重、自动接受阈值与金标全量冻结。
