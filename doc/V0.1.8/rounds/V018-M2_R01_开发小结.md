## 一、实现与版本/回退设计

1. **向量编码文本与模型元数据（`app/vector_fusion.py`、`app/vector_index.py`）**：
   - 沿用本地离线 `bge-small-zh-v1.5`（512 维，`BertTokenizer`，`model_max_length=512`，`do_lower_case=false`），`VectorIndexManager.get_model_metadata()` 输出模型、tokenizer、维度、`db_revision` 与 `text_schema_version`。
   - 对比两套编码文本版本：`legacy-v1`（`f"{name} {specification}"`）与候选 `v018-m2-canon-v1`（物料端 `品类|名称|规格|品牌`，查询端基于 `original_name` 剔除设备位号/箱号与 `工作内容` 噪声、保留真实产品型号与结构化参数尾段）。长文本按确定性头尾截断（`MAX_ENCODE_CHARS=384`，头 256 + 尾 120）防止 BERT 512 token 截断丢弃尾部规格。
2. **向量 TopK 与确定性 RRF 融合（`app/vector_fusion.py`、`app/matcher.py`）**：
   - 支持受控切换向量 `TopK = 50 / 100 / 200` 与合并策略 `union`（原插入序）/ `rrf`（可配置 `rrf_k=60`、`candidate_cap`）。
   - `fuse_recall_candidates()` 保留各通道 `recall_sources`、1-based `channel_ranks`、`recall_reasons` 与最大 `semantic_score`；重复候选按 `code` 合并；`exact_code` 固定置顶；确定性同分顺序为 `(-is_exact_code, -round(rrf_score, 10), -round(semantic_score, 8), min_channel_rank, code)`。
3. **开关默认 OFF、隔离候选索引与降级回退**：
   - 新增独立开关 `LISTTRANS_V018_M2_RECALL`（默认 `"0"`），子配置 `TEXT_MODE=legacy`、`VECTOR_TOPK=50`、`FUSION_MODE=union`、`RRF_K=60`、`CANDIDATE_CAP=0`；`M0`/`M1` 维持默认 OFF。
   - 非 `legacy-v1` 候选索引仅落盘于隔离目录 `<VECTOR_CACHE_DIR>/candidates/<text_schema_version>/`，`cache_metadata.json` 绑定 `db_revision`、`model_name`、`dimension`、`text_schema_version`，绝不覆盖 `app/vector_cache/` 原有 `legacy-v1` 缓存；版本/维度失配或模型不可用时拒载并安全降级回关键词/FTS 路径。切回 `M2=OFF` 立即复现 M1/M0 放行 OFF 路径（`B0` 6 项指标与 M1 放行 OFF 100% 相等）。

- **客观消融结论**：
  1. **规范编码文本 `v018-m2-canon-v1`（`A6`/`A7`）**：召回率显著退化（`A6` R@100/200 −22/−33、Dev −6/−6；`A7` R@200 −15 且 4 项时延超预算），**明确不采纳、保持禁用**；其 `A6` 上 `Hit@1 +6 / Hit@3 +11` 的排序精度信号仅作事实留档供 V0.1.9 参考。
  2. **TopK 与 RRF（`legacy-v1`）**：扩大 `K`（50→100→200）首次在 BGE Dev 122 条取得正增益（`+1/+1` 与 `+1/+2`），但 `union` 下池均值升至 255.7；引入 `RRF (cap=200)` 有效压缩候选池并显著降低 P95 时延（`A3` 5/5 预算全过但 R@200 −9；`C1`/`C2` R@100 达 `590/591`，P95 降至 220–232 ms、上传 P95 降至 7.6–8.2 s，仅单条 P50 略高于 90 ms），留待 V018-M3 选型裁决。
  3. **关键词降级路径（`KW`）**：模型禁用下稳定降级无异常，但无语义通道时 RRF `cap=200` 导致关键词 R@100/200 −26/−12，确认关键词模式不启用 RRF。
