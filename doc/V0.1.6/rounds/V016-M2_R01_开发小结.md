## M2-C01 ～ M2-C08 实现摘要与关键口径

### 1. M2-C01 / M2-C02：三源统一发布门禁与强绑定评测凭据

- **统一门禁内核（[app/rule_governance.py](../../../app/rule_governance.py)、[app/flywheel_db.py](../../../app/flywheel_db.py)）**：新增持久化表 `rule_eval_runs`，以 `verify_eval_credential_for_publish` 作为手工规则、传统绑定规则、飞轮建议唯一权威发布门禁：
  - **手工规则（[app/llm_rule_engine.py](../../../app/llm_rule_engine.py)、[app/rule_api.py](../../../app/rule_api.py)）**：新增 `LLMRuleManager.start_rule_evaluation`、`POST /api/llm-rules/{rule_id}/eval`、`GET /api/llm-rules/eval/{eval_id}`；`publish_rule` 与 `toggle_rule_status`（`disabled -> published` 重启用）均接入同一门禁。
  - **传统绑定规则（[app/server.py](../../../app/server.py)）**：新增 `start_binding_rule_evaluation`、`POST /api/binding/rules/eval`、`GET /api/binding/rules/eval/{eval_id}`；`confirm_binding_rule_service`、`/api/binding/rules/confirm` 与 `save_auto_binding_rules` 共用同一门禁（仅纯删减/清空允许直接管理员清理，任何新增/修改规则一律核验 `eval_id`），行级 `confirm_binding` 保持独立。
  - **飞轮规则（[app/server.py](../../../app/server.py)）**：提取服务函数 `accept_flywheel_suggestion_service` 与 `/api/flywheel/suggestions/accept` 共享同一门禁；支持微调值评测与采纳校验。
- **服务端凭据绑定与伪造拦截**：凭据绑定 `eval_id`、`rule_source`、`rule_key`、`rule_revision`、规范化规则执行载荷摘要 `payload_digest`（`normalize_rule_spec` + `compute_rule_digest`）及快照字段 `baseline_release_version`、`materials_revision`（表语义哈希）、`config_digest`、`algo_version`、`model_version`、`evaluator_version`、`eval_assets_digest`、`guard_assets_digest`；忽略客户端自填 `passed`/`hash`/task 字段，拒绝跨规则/跨任务借用凭据，保留 403 越权与 409/422 门禁错误语义清晰区分。

### 2. M2-C03 / M2-C08：失效条件、专业作用域隔离与历史兼容性

- **变更/环境/TTL 失效**：评测后编辑 `edited_target_value`、`scope`、`discipline`、`priority`、`qty_ratio`，或物料库/配置/模型/基线规则/评测资产任一变更立即导致旧 `eval_id` 失效（409 `eval_revision_mismatch` / `eval_content_changed` / `eval_env_stale`）；服务端强制核验 24 小时有效期（`EVAL_TTL_SECONDS = 86400`，超时 409 `eval_expired`）。
- **专业作用域严格隔离**：所有新增与变更规则均通过 `validate_concrete_discipline` 强制绑定明确专业（`医用气体` == `医气`）；飞轮采纳的 `ALIAS` 写入专业作用域文件 `scoped_aliases.json`（[app/normalizer.py](../../../app/normalizer.py) 运行期按 `RuleContext.professional` 分组编译、命中记录线程安全 `_session_alias_hits`），绝不污染冻结基线 `config/alias_dict.json`；绑定规则在 [app/server.py](../../../app/server.py) 中通过 `_select_matching_binding_rule` 按规范专业与 `original_spec` 约束精准匹配，规格不匹配的约束规则不会劫持其他规格物料。缺失专业或 `legacy_unscoped` / `legacy_unknown` 规则拒绝升级。
- **幂等原子迁移与历史收口（[app/flywheel_db.py](../../../app/flywheel_db.py)、[app/llm_rule_engine.py](../../../app/llm_rule_engine.py)）**：对预存 `llm_rules`、`flywheel_rule_suggestions`、`flywheel_config_snapshots` 增加幂等事务迁移与故障注入回滚验证；历史无 M2 凭据行保守标记 `legacy_unverified`（历史未核验快照重置 `targeted_eval_passed = 0`），不经新评测禁止重新启用或发布；基线 `config/alias_dict.json` 保持冻结输入不变。

### 3. M2-C04 / M2-C05：沙箱真实流水线执行、全局保护集与收益分级

- **真实流水线评测（[tests/eval_golden_set.py](../../../tests/eval_golden_set.py)、[app/flywheel_sandbox.py](../../../app/flywheel_sandbox.py)）**：新增 `--eval-mode sandbox_v2`，同步运行：
  1. 定向样本集（支持 `1to1` 与 `1toN`）+ **互不重叠的分层多专业全局保护集** `_select_sandbox_subsets`；
  2. 真实 `evaluate()`（沿用 V015 `SCORE_EPS = 1e-6` 逐例 rank / T / margin 零退化门禁）；
  3. 真实生产 `batch_match_rows` 绑定流水线校验 `_evaluate_binding_pipeline` + `_compare_binding_pipeline_rows`（1 对多、`qty_ratio`、单位、硬冲突、目标编码、可导出资格）；
  4. 真实规则命中统计（`rule_execution_hits`，覆盖 `scoped_aliases`、`DynamicRuleInterpreter`、`auto_binding_rules`）。
- **安全与收益显式拆解（[app/flywheel_sandbox.py](../../../app/flywheel_sandbox.py)）**：输出独立 `safety_passed` 与四类 `benefit`（`improved` / `neutral` / `harmful` / `invalid`）。空集（`empty`）、未命中（`unhit`）、资产缺失或异常一律 `safety_passed=False, benefit="invalid"`；命中退化或全局保护集/绑定误伤一律 `harmful` 拦截；`neutral` 安全通过但禁止宣称改善或自动发布，确需启用必须由管理员人工审批并填写 `neutral_reason`（否则 422 `neutral_reason_required`）。

### 4. M2-C06 / M2-C07：进程边界、并发控制、原子恢复阻断与前端对接

- **进程边界与清理**：基线与候选子进程强制 `SUBPROCESS_TIMEOUT_SECONDS = 300s`、任务总限 `TASK_TIMEOUT_SECONDS = 660s`；超时、非零退出、输出缺失或 JSON 损坏一律失败收口并清理临时目录（WAL 安全采用 `sqlite3.Connection.backup()` 拷贝候选数据库）；先持久化脱敏摘要再清理临时目录；绝不覆写 `golden_last_run.json` 或 M0/M1 既有证据。
- **并发 CAS 与恢复阻断（[app/server.py](../../../app/server.py)、[app/llm_rule_engine.py](../../../app/llm_rule_engine.py)）**：发布与采纳阶段持有 `_PUBLISH_GATE_LOCK` 并在 `BEGIN IMMEDIATE` 中二次重核 `status`/`revision`/`payload_digest` 执行 CAS；`trigger_all_config_reloads(raise_on_error=True)` 暴露热重载失败；本地写/DB 事务/热重载与文件补偿任一环节失败立即调用 `block_rule_publish_recovery` 设置持久化阻断（拒绝后续发布返回 409 `rule_recovery_blocked`），不输出虚假“已安全恢复”文案。
- **管理端与规则界面最小化联动（[web/admin.html](../../../web/admin.html)、[web/app.js](../../../web/app.js)）**：透传 `eval_id`、`discipline`、`neutral_reason`，提供飞轮“🧪 沙箱回归”/微调编辑失效提示、LLM 规则“🧪 评测”及绑定规则“🧪 评测”动作与错误信息解析。
