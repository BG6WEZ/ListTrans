## 本轮完成

对应 `F05 / P1` 与下发契约 `C01～C09`：

1. **C01 不可变主体与防串权**：`extract_verified_actor()` 绑定 `auth.db` 实时核验的不可变整数 `actor_user_id`（`users.id`）与 `actor_account_epoch`（`users.account_epoch`），禁止 `username`、`anonymous` 或客户端 `user_id`/`actor_user_id`；未认证 401，跨用户/失效 epoch/未签发 `document_id` 统一返回 404 不泄露资源存在性；`session_manager.py` 同步校验 `owner_account_epoch`。
2. **C02/C03 文档-工作表-源行三层身份与归属校验**：
   - `POST /api/upload` 与 `async_process_upload_task` 每次上传生成独立 `upload_task_id`（`task_id`）、`document_id`（`doc_*`）、`work_session_id`（`ws_*`），同文件名同内容再次上传产生新文档；`_extract_upload_rows_from_sheets` 保留 `sheet_index`、`sheet_name`、`source_row_num`（物理行号）与 `row_idx`。
   - `persist_upload_document_tree()` 在单事务写入 `flywheel_documents` → `flywheel_sheets` → `flywheel_source_rows` → `flywheel_recommendation_snapshots(revision=1, is_initial=1)`。
   - `/api/flywheel/record` 与 `/api/feedback/submit` 统一走 `verify_row_ownership()`，缺失/`default_session`/伪造或错配 `sheet_id`/`source_row_id`/`recommendation_snapshot_id` 返回明确 422 且零副作用；不留无身份写入旁路。
3. **C04/C05 初始快照不可变与真实版本追溯**：
   - 初始推荐持久化在 `flywheel_recommendation_snapshots(revision=1, is_initial=1)`，编辑、改绑、重算永不反写初始快照；`/api/rematch` 与 `/api/match` 携带文档行身份时追加 `revision >= 2` 新快照并保留初始快照，`GET /api/flywheel/documents/{document_id}/rows/{source_row_id}/trace` 可分别读取初始快照、重算历史、事件历史与当前有效终态。
   - `compute_runtime_versions()` 实时计算 `algo_version`（代码摘要）、`model_version`（向量模型名及可用状态，禁用/未加载时显式标 `unavailable:*`）与可回算 `config_version`/`config_digest_full`（`CONFIG_DIR/*.json` + 已发布 `llm_rules` 规范摘要），废除前端/后端固定 `v1.0`/`snap_v1` 占位串；`web/app.js` 改传主链路 `professional` 与 `parsed_spec`，服务端落库全部以持久化源行与快照为准，屏蔽客户端篡改；提交反馈不写入 `binding_decisions`，不代替 M2 确认/导出凭据。
4. **C06/C07 幂等、事务替代与乱序并发**：
   - **唯一键**：`client_event_id`（全局 UNIQUE）+ `payload_digest`（SHA256 规范摘要）；同键同主体同对象同内容返回 200 幂等重放（不重插、不改 `superseded`）；同键异内容、异对象或跨用户返回 409。
   - **替代键与事务**：插入与 `UPDATE superseded = 1` 在 SQLite `isolation_level=None` + `BEGIN IMMEDIATE` 同事务执行，严格按 `(actor_user_id, actor_account_epoch, document_id, sheet_id, source_row_id)` 置过期，任一步异常完整回滚（零部分提交）且同键可安全重试。
   - **乱序/并发契约**：要求正整数单调 `event_seq`，唯一索引 `uq_fwr_trusted_obj_seq` / `uq_fwfs_trusted_obj_seq` 阻断同序号并发冲突（409）；严格滞后旧序号（`event_seq < max_seq`）以确定性单调接纳归档至历史（`superseded=1, is_stale_arrival=1`），绝不覆盖已生效的高序号终态；有效终态视图为 `flywheel_effective_records`（`trust_level='trusted' AND superseded=0`）。
5. **C08/C09 保存恢复、遗留隔离与兼容迁移**：
   - Schema 契约版本 `v0.1.6-m0-v1`（`flywheel_schema_meta` / `work_sessions.schema_version`）。`init_flywheel_tables()` 与 `init_session_db()` 使用 `BEGIN IMMEDIATE` 实现 DDL+DML 原子幂等迁移（失败零部分修改），可重复执行；历史 `default_session`/缺身份/未验证记录保留并标记 `trust_level='legacy_untrusted'`，不删记录、不伪造归属。
   - `/api/session/annotate` 验证恢复条目的文档/表/源行归属与 `owner+epoch` 并同步 `max_event_seq`/`max_feedback_seq`；无有效身份的旧草稿/会话标记 `feedback_eligible=False` 并界面提示隔离（须重新上传开启新采集边界）。`/api/flywheel/statistics`、`/api/flywheel/export/benchmark`、`/api/flywheel/export/triplets` 及 `get_feedback_suggestions()` 均过滤 `trust_level='trusted'`。
   - **M0→M1 接口**：M1 `feedback_miner.py` 后续可直接消费 `flywheel_effective_records` 视图或 `flywheel_db.trusted_flywheel_where_clause()`，无需改动本包表结构。
