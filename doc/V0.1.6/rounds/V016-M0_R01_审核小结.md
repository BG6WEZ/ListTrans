## 3. 正向确认（成立的契约）

- C01/C03 HTTP 面：`/api/flywheel/record`（[server.py L2334-2344](../../../app/server.py)）与 `/api/feedback/submit`（[server.py L2752-2761](../../../app/server.py)）均 `Depends(require_employee)`；伪造 user_id/actor_user_id 经 [feedback_contract.py L637-645](../../../app/feedback_contract.py) 返回 422 forged_actor_id；跨用户/跨上传/跨工作表归属拒绝在专项与浏览器 E2E 中成立，无 default_session 回退。
- C02/C04：document/sheet/source_row 稳定标识贯通上传→重算→反馈；初始 revision=1 快照不可变（CE4 实测 rev1_unchanged=true），重算/改绑独立记 revision≥2。
- C05 版本标识：algo/model/config 标识来自服务端 `compute_runtime_versions()` 真实计算（S1 响应实测 `listtrans-0.1.6-m0|0d81abac38ab`、`bge-small-zh-v1.5|loaded`、真实 config digest），无固定 v1.0/snap_v1 冒充。
- C06/C07：同 event_id 幂等重放不重复插入、同键冲突 409、乱序/故障回滚专项用例通过；插入与 superseded 同事务、限同一认证主体与对象。
- C09：迁移可重复执行、故障原子回滚专项通过；本轮全程未触实际业务库，业务快照前后零变化。

## 5. 结论与 R02 建议

**结论：退回整改（保持 V016-M0，递增 R02）。** 5 项 P1 均有实测证据且直接对应任务书明文要求，按协作协议未闭合 P1 阻断本包通过；不存在环境缺项，不适用“待验证”。

正向架构（认证主体、归属校验、rev1 不可变、真实版本标识、事务/幂等/409/回滚、跨对象隔离）经独立复验成立，R02 为定点收口而非重做。建议最小整改：

1. AUDIT-01：删除 `save_feedback_sample` 无 actor 可信写分支，统一强制认证主体，并更正 docstring。
2. AUDIT-02：隔离判定不得仅凭自报字段；无法与服务端事件库核验的记录一律 legacy_untrusted，不进可信建议集。
3. AUDIT-03：幂等重放时校验 JSON 是否缺事件并按需补同步（或提供 DB→JSON 对账），补故障注入自愈断言。
4. AUDIT-04：rematch/match_override 的 professional/parsed_spec 由服务端重算/复核，或显式标记 client-asserted 并排除出机器推荐可信血缘；补篡改负例。
5. AUDIT-05：命中旧草稿时新建 trusted 行/新 draft id 并保留 legacy 行与提示，禁止原地升格覆盖；SELECT 补确定性排序。
6. AUDIT-06：HTTP 边界对 event_seq 启用严格整数语义（显式拒 bool/str/浮点或书面固化强转契约），契约层去除浮点截断，两层对齐并补参数化负例。
7. AUDIT-07：guardrail fixture 使用独占临时根（重载 conftest 时不继承固定根），禁止 rmtree 共享隔离根；修复后须在固定根模式下重跑全量并给出全绿日志。

整改后 R02 交付须重新冻结哈希并保留 R01 证据不覆写；审核通过前不启动 M1，版本准入仍归统筹。
