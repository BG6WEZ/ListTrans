## 三、新增阻断与定性

### C-M0-08 / P1：前端吞掉失败，不能沿用同一事件重试

源码位置：`web/app.js` 的 `reportFlywheelAction`（L1844）、`submitFeedbackSample`（L1919）。两个函数每次调用都新建 UUID 并增加序号，不保留可重放的原 payload。前者没有 await HTTP 完成，也不检查 HTTP 状态；后者等待 fetch，但同样不检查 `response.ok`。调用处没有获得可靠的反馈提交状态。

审核报告的“前端四项语义断言全 true”并不是四项正确性门禁。其实际键包括 `no_in_built_retry_same_event_id`、`failures_swallowed_no_throw`，其余两项为每次生成新 UUID、失败仍消耗序号。统筹按字段实际含义裁决，不将 true 本身视为通过。

统筹运行态结果（未模拟数据库）：

| 场景 | 真实 HTTP / 落库 | 前端行为与后果 |
|---|---|---|
| 飞轮首请求提交成功，但响应丢失 | 首次 200 已提交；再次调用同一动作又 200，均 `idempotent_replay=false`；SQLite 两个事件，seq=1/2 | 第一次函数在响应结算前已返回；没有同事件自动重试。重做动作使用新 UUID，原请求不能作为同一事件安全重放。两行中仅后一行有效，不宣称有效视图出现双计数。 |
| 反馈 DB 已提交，JSON 同步注入失败 | 首次实际 500；前端未向调用方报告失败。再次调用生成新事件，200 且非 replay；SQLite 两事件，JSON 仅一事件 | R02 服务端“相同 ID 重放可自愈”分支没有被生产前端使用；首事件仍缺 JSON 镜像。缺少的是原事件历史镜像，不宣称当前建议集从 JSON 读取或当前有效记录丢失。 |

第二次调用在探针中显式模拟失败后重做同一语义动作，不是声称浏览器已有“重试”按钮。问题首先在于首个 500 不可见、原事件没有可调用的重试路径。修复必须区分“原操作重试”和“用户新操作”，不能按 payload 相同就合并合法的新操作。该缺口影响原任务 C06/C07 及端到端数据可靠性，不能延期到挖掘包。

## 四、唯一下发 V016-M0 / R03

仅允许修复 C-M0-08、C-M0-09 及必要回归、文档；不开发业务挖掘、不改算法权重/阈值、金标或规则发布流程。

1. **前端事件生命周期**：创建业务动作时一次性确定 event ID、seq、对象身份及 payload；网络失败、可重试服务错误或响应不确定时保留原事件，重试沿用全部原值。提供有界重试或明确可操作的重试状态。新动作使用新事件，不得合并合法重复动作。前端读取 HTTP 成功/错误结果，不能将失败显示或返回为已提交；409/422 等冲突/非法请求须明确处理，不能无限重试。保留 UI 对匹配/确认状态与反馈投递状态的区别，不因反馈失败伪造确认或导出资格。
2. **归属、恢复及顺序**：待处理事件必须绑定认证主体/epoch、document/sheet/source_row；刷新/保存恢复与切换账号时不能误投其他主体。明确待处理事件在这些边界的保留/提示策略。原事件重试不增加 seq；新动作增加 seq。迟到重试不覆盖更新状态，409 可见；服务端已提交但响应丢失时可获幂等 replay，并触发已有 JSON 自愈逻辑。
3. **离线测试治理先行**：对修改的 env、LLM 单例状态用可靠 cleanup/monkeypatch 还原；mock 或测试级网络阻断须覆盖 daemon 生命周期。真实 localhost 服务与 TestClient 仍可运行，模型只用本地文件。先证明 mock 作用域退出后、后续导入/异步任务运行时仍不会访问外部 LLM，再运行专项及全量。不得仅隐藏 401 日志、强行跳过 LLM 用例或依赖错误 key。
4. **最小改动范围**：以 `web/app.js`、必要的原生反馈提示、专项测试、`tests/test_llm_integration.py` 和必要隔离 fixture 为主。允许对事件恢复保存链路做直接必要的最小贯通；若需调整服务端契约，说明兼容与原因并保留全部 M0 保护，不扩展到 M1。不修改既有审核小结或本裁决。
