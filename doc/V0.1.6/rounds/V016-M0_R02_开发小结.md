## 本轮整改明细（AUDIT-01～AUDIT-07）

| 缺陷 | 级别 | R01 根因 | R02 定点修复 | 回归验证点 |
|---|---|---|---|---|
| `AUDIT-01` | P1 | `save_feedback_sample` 保留 `actor_user=None` 仅凭 `trust_level=="trusted"` 直接写 JSON 文件的旁路 | 删除 `actor_user=None` 可信写入分支，缺失 `actor_user` 统一抛 `ValueError`，并同步更正 docstring 与实现一致 | `test_r02_audit_01_02_03_feedback_security_and_self_heal` 验证无 `actor_user` 直调抛 `ValueError` 且不落盘 |
| `AUDIT-02` | P1 | `_quarantine_legacy_samples` 与 `get_feedback_suggestions` 仅检查 JSON 字段存在性，伪造完整身份 JSON 可入建议集 | `get_feedback_suggestions` 改为严格只从 SQLite `flywheel_feedback_samples (WHERE trust_level='trusted' AND superseded=0)` 统计；`_quarantine_legacy_samples` 同步交叉核验 `flywheel_feedback_samples` 主体+对象键，未入库伪造项一律降格 `legacy_untrusted` | 同一专项断言库外伪造 `trust_level='trusted'` JSON 被 `_quarantine_legacy_samples` 降格且 `get_feedback_suggestions` / `/api/feedback/suggestions` 不出现伪造词条 |
| `AUDIT-03` | P1 | DB 提交后 JSON 同步失败返回 500，而幂等重放跳过 `sync_trusted_feedback_file` 导致跨存储永久分叉 | `record_feedback_sample_event` 幂等重放分支补全返回持久化 `sample_record`；`save_feedback_sample` 无论首次或 `idempotent_replay=True` 均调用 `sync_trusted_feedback_file`（文件已有该 `client_event_id` 时幂等返回，缺失时自动补齐自愈） | 注入 `sync_trusted_feedback_file` 抛 `OSError` 后，同 `client_event_id` 重试返回 200 `idempotent_replay=True` 且 JSON 自愈包含该事件 |
| `AUDIT-04` | P1 | `record_rematch_snapshot` 与 `/api/match` / `/api/rematch` 信任客户端传入的 `professional` / `text` / `parsed_spec` 并落 `revision >= 2` | 新增 `load_verified_source_row` 在执行匹配前核验归属与服务端源行上下文：`/api/rematch` 与 `/api/match` 绑定文档行时拒绝不匹配 `professional` / 篡改 `raw_spec`（422），并严格基于持久化 `source_row` 重算 `prepare_query`；`/api/match`（`match_override`）仅允许切换服务端已解析 `model`/`attrs` 子集（注入未核验 key/value 返回 422）；`/api/rematch` 手动覆盖参数落库强制使用服务端 `professional`/`clean_text`/`name`/`spec`，参数差异时显式标 `snapshot_kind='rematch_client_param'` 及 `_provenance='client_param_override'` | `test_r02_audit_04_rematch_and_match_override_tamper_rejected` 覆盖篡改 `professional`、`text` 与伪造 `parsed_spec` 全 422 拒止且不新增 snapshot；合法属性子集切换与手动参数重算准确标记血缘来源 |
| `AUDIT-05` | P1 | `save_draft_session` 沿用 `_epoch_clause_and_params` 命中空 epoch `legacy_untrusted` 草稿并以同 id 原地 `UPDATE` 升格覆盖 | `save_draft_session` 按目标 `effective_trust` 严隔离查询：`trusted` 仅匹配并更新同 `(user_id, owner_account_epoch, trust_level='trusted')` 记录，命中旧空 epoch 草稿时新建 UUID 行保留原 `legacy_untrusted` 行与 `items_json`；`get_draft_session` 增加 `ORDER BY CASE WHEN trust_level='trusted' THEN 0 ELSE 1 END, updated_at DESC, rowid DESC LIMIT 1` 确定性排序 | `test_r02_audit_05_legacy_draft_preserved_not_overwritten` 验证新建 `draft_id != legacy_id`、旧空 epoch 行 `trust_level='legacy_untrusted'` 与内容完整保留、`GET /api/session/draft` 确定返回新可信草稿 |
| `AUDIT-06` | P2 | HTTP 层 `Optional[int]` 允许 `bool`/`"5"`/`1.0` 强转，契约层 `int(float)` 静默截断 `2.9 -> 2` | HTTP Schema（`FlywheelRecordRequest`、`FeedbackSubmitRequest`）统一改为 `Optional[StrictInt]`；契约层新增 `_parse_strict_event_seq` 统一应用于 `record_flywheel_event` 与 `record_feedback_sample_event`，显式拒绝 `None`/`bool`/非 `int`/`< 1` | `test_r02_audit_06_event_seq_strict_positive_int_parity` 对 `[None, True, False, 1.0, 1.5, "2", 0, -3]` 全参数化验证 HTTP 与契约直调一致返回 422 |
| `AUDIT-07` | P2 | 固定 `LISTTRANS_TEST_ROOT` 下 `guardrail_cf` 重载 `tests/conftest.py` 继承外部共享隔离根并 `rmtree`，级联破坏后续测试及 `app.<submod>` 包属性绑定 | `tests/test_m0_guardrail_regression.py` 中 `guardrail_cf` 先将 `LISTTRANS_TEST_ROOT` 指向独占 `tmp_path / "guardrail_iso_root"`，仅当 `cf._ISOLATION_ROOT == dedicated_root` 时清理；并修正 `test_real_importable_modules_resolve_inside_isolation_root` `finally` 块，在还原 `sys.modules` 时同步还原 `app` 包子模块属性与清除临时新增子模块 | 固定 `LISTTRANS_TEST_ROOT` 与标准 `mkdtemp` 双模式下 `tests/` 全量 `336 passed, 0 failed` |
