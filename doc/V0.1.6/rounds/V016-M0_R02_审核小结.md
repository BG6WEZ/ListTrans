## 4. 观察项（非阻断，不影响本轮结论）

- **OBS-01（历史测试环境污染导致的 401 噪声）**：固定根全量 stderr 出现一次 `API call failed after 2 attempts: Error code: 401`。机理已定位——[test_llm_integration.py L94-95、L122-123、L144-145](../../../tests/test_llm_integration.py) 直接置 `LLM_ENABLED=true`+`DASHSCOPE_API_KEY=sk-mock-key` 且无 tearDown 还原，进程内 env 与单例持续污染；[llm_client.py L112-123、L236-238](../../../app/llm_client.py) 门控因此开门，[db_manager.py](../../../app/db_manager.py) 的 daemon LLM 线程以假 key 真调阿里云被拒 401 后记录 error 并 `return None` 优雅回退（线程不 join，不影响主流程断言）。定性依据：涉事 4 文件均不在 R02 交付清单 28 项内；开发冻结日志 [m0_r02_full_pytest_fixed_root.log L350](../evidence/m0_r02_full_pytest_fixed_root.log) 与审核机日志（L38）均现同款 401 且终态同为 336 passed；无真实付费成功调用、无业务结果受影响；R01 日志未见属 daemon 时序/捕获差异，非 R02 回归。建议后续轮次由开发补 tearDown/monkeypatch 还原 env（审核不代改），不构成本包整改项。
- AUDIT-04 整改保留的 `client_param_override` 手动参数路径为显式血缘标记设计（非静默信任），已由专项负例（篡改 professional/raw_spec/parsed_spec 全 422）与 Chrome E2E（rev1 不可变、rev2 来源可溯）双向覆盖，审核认可该设计。
