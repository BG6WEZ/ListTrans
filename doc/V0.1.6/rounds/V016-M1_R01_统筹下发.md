## 二、已确认的调查起点

- 当前 `feedback_miner.py::_aggregate_parameter_adjustments` 仍写 `pattern_key/discipline/total_count/...`，而 `flywheel_db.py` 的 `flywheel_pattern_aggregates` 为 `source_pattern/suggestion_type/target_value/archived_support/...`，源码存在真实契约错配。至少两条有效PARAM_ADJUST必须能进入并完成该分支，不能通过不进入分支消除异常。
- 挖掘扫描、分母/分子、参数聚合仅过滤 `superseded=0`，未全面使用 M0 的可信有效谓词；多个建议直接写专业“通用”，建议upsert键也未纳入专业上下文。必须在M0身份契约上闭合该读者边界。
- `run_mining` 当前分两次提交，先置processed再挖掘；失败时另行补偿复位。须验证建议、聚合与processed状态能一起回滚，不能依赖失败后的第二次写入必定成功。
- F27旧报告中的未定义变量与固定跨专业兜底已在V015做过部分整改，不要求盲修已消失的问题。当前已有 `dynamic_rule_matches_query` 共用辅助函数，仍须调查清洗、抽取、匹配的上下文构造差异；不得将材料category/domain/name混作professional。用现存源码与反例确定剩余缺口，逐项说明已修与待修，不伪称旧报告每一项都仍存在。

上述为统筹只读调查，不冒充本轮运行态复现。开发先在隔离副本形成改前证据，再做定点修复。

## 三、实施契约

| 编号 | 必须满足 |
|---|---|
| M1-C01 统一聚合schema | 选择唯一权威schema，所有读写者使用相同字段与语义；迁移可重复、事务失败可回滚。明确历史archive累计与当前有效反馈重算的区别，不覆盖/重复累加历史支持数，不以补一组空列绕过实际业务语义。旧表未知数据保留并标识来源，不能推断补造专业或可信身份。 |
| M1-C02 可信集合 | 增量发现、全量统计、分子/分母、distinct_users、PARAM_ADJUST、sample_ids与processed更新使用同一可信有效边界，复用M0谓词或同一事实源；legacy、无身份、superseded及迟到陈旧样本不得进入建议或占分母。用户支持数来源于服务端不可变actor身份，不以username或legacy匿名兜底计为真人。 |
| M1-C03 作用域一致 | 清洗、抽取、匹配、挖掘使用相同RuleContext语义，区分professional、材料category、domain与名称；保留医气/医用气体等已验证别名。专业规则只在明确匹配的专业运行，缺专业不得靠固定“给排水/通用”补齐。显式universal按既有契约执行；缺少作用域必需字段时跳过该受限规则并给出诊断。兼容表说明既有category/name规则含义，不能静默改写已审核规则。 |
| M1-C04 建议键与专业隔离 | 相同source/target在不同专业形成独立建议和统计，不默认为“通用”，不跨专业覆写accepted/rejected状态；参数趋势同样保持上下文。明确旧建议兼容策略并保留原状态/来源，旧无上下文记录不能自动升级为可信通用规则。不得在本包自动采纳或发布建议。 |
| M1-C05 事务与重试 | 一轮挖掘的建议、聚合、processed标记构成一致提交单元；在关键阶段注入失败后不留部分状态，原反馈不丢，重试不重复累计。并发执行要有明确串行/冲突策略；旧事件被新事件替代后统计按有效视图重算，不能保留虚假的旧支持数。 |
| M1-C06 错误可见 | SQL、规则上下文/动态规则执行与关键持久化错误可定位、有明确失败状态和日志；不得except吞掉后伪报成功。确需降级的分支说明降级内容与保护。错误日志不含密钥、Token或真实业务原文。 |

## 四、最低验收矩阵

1. **聚合正例与兼容**：两个独立可信业务对象的同名称PARAM_ADJUST（含同专业重复及跨专业对照），真实调用挖掘后结果语义/计数/sample_ids正确，不报缺列；空库与旧schema脱敏副本各两次迁移、失败回滚，历史数据与归档累计保留。
2. **可信反例**：加入足以改变建议阈值或分母的legacy/untrusted/伪造JSON/已替代/迟到记录，建议与统计不受影响；重试事件不增加支持数。同名不同专业、两个用户、同用户不同文件/行分别核对，不通过任意构造trusted字段绕过真实M0采集契约。
3. **专业矩阵**：至少暖通、给排水、强电、医气/医用气体别名、缺专业及显式universal；覆盖清洗、抽取、匹配三个真实入口。错专业不执行、当前专业执行、缺必需上下文不误执行；同scope判定用同一上下文语义。保留V015否定/unknown/单位证据与动态排除保护。
4. **事务反例**：在首次建议写入、后续绑定建议、参数聚合及提交前分别注入异常；建议/聚合/processed均无部分提交，重试正确且不重复累加。并发与“已处理反馈被新事件替代”可重放。若采用运行锁，验证失败路径释放与重试，不借锁隐藏部分状态。
5. **真实HTTP链路**：认证上传/事件记录进入可信库，再调用真实挖掘入口，读取建议、聚合与事件状态；权限/错误状态正确。规则作用域使用真实生产解释/匹配管线，AST或纯mock不得替代。未修改前端时不要求为本包新建UI功能；如改变前端/保存恢复契约，须补Chrome真实DOM回归。
