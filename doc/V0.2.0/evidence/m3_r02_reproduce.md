# V020-M3 R02 性能复验方法

使用同一台 Windows 11 主机、现有 Python 3.12.10 venv 和冻结的离线模型。等待其它测试、评测和高负载任务退出。脚本从项目根启动，每个测量使用独立进程和仓外原生临时根。使用本机回环、出站审计钩子及 LLM 传输哨兵，按下发值锁定 10 项开关。业务库、缓存、配置、账号、上传和输出均独立。前后按原协议执行隔离核验。

## 同样本诊断

从冻结 Train/Dev 投影按 R01 的顺序取 200 条测时样本与独立的五条预热样本。使用相同的样本、配置、快照、依赖与主机，按关键词后 BGE 顺序，在各模式中串行比较：

1. 当前候选使用 R01 的预热流程，5 次单条和 1 份 5 行上传。
2. 当前候选完成相同预热，再用这 200 条做前置排名，之后测相同的 200 次单条。
3. 从 72 份受控归档原样恢复 V0.1.9 放行源码，用同样的排名预热和 HTTP 样本作配对对照。

三种条件记录单条原始耗时、nearest-rank P50/P95、进程阶段计时、索引元数据及测量前后的主机 CPU 使用率。诊断覆盖 Train/Dev，样本来自 R01，复验不需要解码 Test 的查询或答案。

## 签认同口径计时

诊断结束后写 `freeze.json`，固定基线、运行设置、脚本和输入哈希。随后使用 V0.1.7 原回放程序，在两种模式各执行一次 5 次单条预热和 1 份 5 行簿预热、1,220 条排名、1,220 次单条、25 次上传。24 份 50 行上传纳入预算，20 行尾批单列。全量重放只用于冻结后的计时，Test 160 随冻结查询进入负载。交付仅保留条数、汇总及无样本内容的原始计时，同步保留退出码和每模式执行凭据。峰值为进程全阶段最高工作集。原签认方法为 nearest-rank，取 `ceil(n × p)` 位有序样本。[签认口径](../../V0.1.7/evidence/指标目标与性能预算_统筹签认.md)

```powershell
$py = '.\venv\Scripts\python.exe'
$ev = 'doc/V0.2.0/evidence'
& $py -B -X utf8 "$ev/m3_r02_replay.py" --out "$ev/m3_r02_review_results"
& $py -B -X utf8 "$ev/m3_r02_summarize.py" --results "$ev/m3_r02_review_results" --out "$ev/m3_r02_review_comparison.json"
```

独立审核可直接复算本轮已落盘的 `m3_r02_results`。复算仅读取计时与哈希，不触发留出负载。获准独立重跑时使用新输出目录，保留原记录。`m3_r01_execution.jsonl` 与同前缀日志为复用 R01 执行器的文件名，所在目录为 R02，具体轮次、模式和命令以记录内容为准。全量子进程的 `EXIT=2` 表示完成测量且存在超预算项，`EXIT=1` 表示其他失败。候选是否按签认口径达标看双模式 JSON 的逐项判定。
