# V020-M2 R01 受控补参决策

## 入口与触发

默认 `LISTTRANS_V020_M2_LLM_DECISION=off`、`LLM_ENABLED=false`。本轮实现仅在前者精确为 `on`、后者启用、`TESTING=1` 且进程内注入离线传输时运行。M2 没有配置外部传输的入口，旧 Qwen 客户端未变更。非法值、默认 OFF 或缺少离线传输均走原匹配路径。

受控入口覆盖独立单条 `/api/match`、`/api/batch_match` 和 XLSX 上传中的普通匹配行。文档重匹配、客户端覆盖解析、规则/BOM 分支、已保存独立决策、精确编码、高分且关键证据完整、第一候选硬冲突或封顶保护的行均不提交模型。高置信判定在本策略中使用 75 分；该值用于限制 Mock 调用范围，不改变现有匹配分数、排序和接受阈值，也未使用 Test 160 选取。

在目录锁内读取当前物料库身份和 `db_revision`，仅审查原有排序前五的当前有效编码。服务端复用统一硬约束，检查 DN、外径、材质、防爆与提升泵三态、单位维度及动态排除。关键证据缺失时先由服务端产生待补参结果，包括防爆未知和缺失核心规格。有多个候选通过校验时，以原始行明确给出的名称、品类和品牌与当前目录的匹配结果求交集。若仍无法唯一识别，或各字段指向不同候选，返回 `need_manual_params`，请求人工补齐物料区分参数，零模型调用。没有可接受候选时服务端可直接返回无答案。普通低分且有唯一合格候选才消耗模型预算。

## 返回与授权

只接受长度至多 1,024 字符、无重复键、字段集合严格限定的 JSON 对象。

| Mock 返回 | 服务端处理 |
| --- | --- |
| `{"decision":"recommend","code":"…"}` | 仅接受本次合格目录候选，复核当前版本和数据后写入 `llm_decision.suggested_code`。 |
| `{"decision":"no_answer"}` | `llm_decision.decision=no_answer`，保留人工复核。 |
| `{"decision":"need_manual_params"}` | `llm_decision.decision=need_manual_params`。服务端识别缺参时同时提供缺失字段。 |
| 非法 JSON、额外字段、失效、越界或硬冲突编码 | 拒绝响应，保留原匹配结果，仅附 `fallback` 和原因码。 |

有效建议和两种弃答均保持 `recommended`、空 `bindings`、空 `matched_code`，原候选显示顺序保留。人工作出的服务端确认仍是导出依据。伪造客户端接受状态或附带 `llm_decision` 无法导出，HTTP 返回 422。保护行继续受已发布的确认与导出门禁约束。匹配链的现有 `algo_version` 包含源码摘要，跨版本的追溯标识会随 `server.py` 更新。OFF 的业务输出使用同构建 HTTP 等价与历史规则门禁分别复核。

## 调用治理

- 单条最多 1 次，单个批量请求或上传最多 2 次。单次等待至多 400 ms，受现有任务截止时间进一步限制。缓存命中和服务端直接弃答不耗调用预算。
- 进程内一条传输工作槽，竞争或超时后工作槽仍占用时立即退回，积压请求不排队。没有重试，晚到响应不能写缓存。
- 连续 3 次超时、传输异常或无效响应后熔断 30 秒。冷却结束仅允许一条探测通过，同时来的请求直接降级。探测成功恢复，探测失败重新熔断。
- 进程内 LRU 最多 128 条，有效期 300 秒。键包括规范化查询、候选集合和实时目录证据摘要、数据库身份及 `db_revision`、Prompt 文本和版本、策略版本和模型标识。命中前重读当前候选证据，调用后再核验版本和证据一致性。失败和超时没有缓存条目。M2 缓存、调用预算与熔断状态不落盘。

验收覆盖受控行为和安全边界，真实模型准确率、时延、成本及业务收益目前无实测证据。保持默认关闭。后续申请上线须另获真实调用授权，提交成本预算和真实模型验收证据。
