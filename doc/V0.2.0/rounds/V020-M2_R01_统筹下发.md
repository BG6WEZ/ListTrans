## 范围与验收

| 条目 | 必做与验收 |
|---|---|
| 低置信度缺参触发边界与默认关闭开关 | 仅针对**低置信度/缺参场景**（高分确定项、精确编码命中、已由受约束规则/BOM 决定或硬冲突保护行不得无故触发 LLM）设计受控补参/辅助决策路径，置于独立默认 OFF 开关下（例如 `LISTTRANS_V020_M2_LLM_DECISION=off`，同时遵守既有 `LLM_ENABLED=false` 默认关闭；缺授权、非法开关值或开关关闭时零调用、零行为变化，与现行默认路径完全一致）。 |
| 有效编码约束与硬约束不可越过 | LLM 返回的任何候选编码必须经服务端实时校验：**仅允许返回冻结物料库当前有效编码（且限定在合法候选集合或实时存在编码内），严禁编造编码、返回失效编码或越过任何硬约束**（DN/外径、材质 304 vs 316L、防爆/提升泵三态否定、单位物理维度、动态排除规则）。非法 JSON、越界编码或硬冲突响应必须被服务端拒绝并安全回退，**LLM 输出本身绝不可作为 `auto_accepted` 或直接导出凭据**（仍须维持 `recommended` 待人工确认，导出门禁 422 不得削弱）。 |
| 无答案 / 待补参分支 | 明确实现并验证 **无答案（`no_answer`）与缺参需人工补参（`need_manual_params`）分支**：当原始行信息不足以区分竞争候选（含防爆 unknown 保护样本 GT-0674/0677/0678 及缺失核心规格行）或无匹配有效物料时，受控 LLM 路径必须保守返回无答案/待补参原因，不得强行猜选或诱导自动绑定。 |
| 超时、预算、熔断与版本化缓存 | 梳理并强化 `app/llm_client.py` / 新受控决策模块的运行治理：（1）单次调用**超时**上限与单次请求/批量上传**调用预算上限**（超出预算自动降级跳过，不影响主匹配完成）；（2）连续失败**熔断**与恢复；（3）**版本化缓存键**（至少绑定规范化查询、候选集合摘要、当前物料库 `db_revision`、Prompt/策略版本与模型标识，确保目录更新或策略升级后旧缓存自动失效，不复用过期推荐）；（4）所有可写缓存与统计在测试中必须严格位于隔离测试根内，零写入生产库或工作区业务文件。 |
| 离线 / Mock 验证与诚实不启用结论 | 因当前未获真实外部 LLM 调用授权，本包全部验证使用**离线确定性 Mock / 桩响应**（覆盖有效选择、编造编码拦截、硬冲突拦截、无答案/待补参、超时/预算耗尽/熔断、目录 revision 变更缓存失效、默认 OFF 零变化）。如实交付“未获真实外部调用授权与实测收益，保持默认关闭；未来若申请上线须另有真实调用授权、成本预算与真实模型验收证据”的诚实结论，不得把 Mock 结果包装为真实模型准确率收益或已上线功能。 |
