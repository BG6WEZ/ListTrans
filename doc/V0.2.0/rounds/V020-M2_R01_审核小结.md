## 三、受控 LLM 决策安全边界（核心）

源码通读 `app/llm_decision.py`（284 行）与 `app/server.py` 接入段，关键安全约束均落到代码：

- **默认 OFF、零外连**：`offline_engine=None`，无 HTTP/环境变量设置器，未改旧 Qwen 客户端。`active_engine()` 要求 `LISTTRANS_V020_M2_LLM_DECISION=="on"` 且 `LLM_ENABLED∈{true,1}` 且 `TESTING=="1"` 三者同时满足才返回引擎，否则 None。`_apply_llm_review` 前后两次 `engine is not active_llm_decision()` 校验，防开关中途翻转。独立验证：OFF/非法值(`ON`)/无 provider 三种情况 `active_engine()` 均返回 None。
- **触发边界**：`_prepare` 对 `decision_status` 非 recommended/needs_parameters、`decision_source` 非 matcher、规则 `degraded`、精确编码命中、首候选硬冲突或封顶保护、高分且证据齐全等场景一律跳过；仅低分普通行、top5 当前有效且通过硬约束的候选才进入模型。高置信阈值 75 仅约束 Mock 调用范围，不改现有打分/排序/接受阈值，未用 Test 160 选取。
- **有效编码 + 硬约束不可越过**：候选经 `fetch_live_material_map` 实时目录核对（失效编码 `material is None` 跳过），复用 `evaluate_hard_conflicts` 复核 DN/外径/材质/防爆/提升泵/单位/动态排除；目录锁内取 `_catalog_key()`。独立验证 `_parse_response`：编造编码、伪造 `auto_accepted`、额外字段、重复键 JSON 全部 ValueError 拒绝，合法响应仅产出 `suggested_code`。
- **绝不自动接受**：`_apply_llm_review` 只写 `llm_decision` 字段，`bindings=[]`、`matched_code=""`、`is_exact=False`，状态强制 `recommended`；单条/XLSX 跳过 BOM/文档重匹配/客户端覆盖/规则行，批量跳过规则与已有人工决策行。专项 HTTP 实测：携带建议并伪造接受状态的未确认导出 **422**，经真实人工确认后 200。
- **无答案 / 待补参**：缺关键规格、防爆 unknown、候选无法区分（原始名称/品类/品牌交集不唯一）、无合格候选分别返回 `need_manual_params` / `no_answer`，零模型调用。专项含独立用例 `test_indistinguishable_catalog_entries_require_manual_parameters_without_model`。
- **超时 / 预算 / 熔断 / 缓存**：单次 400 ms、单条预算 1、批量/上传预算 2；连续 3 次失败熔断 30 秒且仅一条探测；单工作槽非阻塞、超时不排队、晚到响应不写缓存；进程内 LRU 128/TTL 300s，缓存键绑定目录身份+`db_revision`+规范化查询+候选+实时证据摘要+Prompt/策略版本+模型标识，目录 revision 变更或证据漂移使旧建议失效。专项对超时、预算耗尽、熔断恢复、revision/版本/证据缓存失效均有独立用例并通过。M2 缓存/预算/熔断状态不落盘。
- **诚实结论**：真实模型准确率、时延、成本、收益均无实测证据；两开关默认关闭，未调用真实/付费 LLM，无联网下载。开发小结与 `llm_contract.md` 明确写明未来上线须另获真实调用授权、成本预算与真实模型验收证据，未将 Mock 包装为真实收益或已上线功能。
