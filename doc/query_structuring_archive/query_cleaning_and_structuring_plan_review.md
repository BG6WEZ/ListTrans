## 二、必须修正的问题（Blocker）

### 🔴 B1. 前提数字与实测不一致，直接影响所有目标口径

方案沿用画像里的 **12,715 条 / 规格填充率 61.13% / 换行率 60.90%**。而实测：

- 抓取 **15,173 条**（未过滤前），过滤后约 **12,700 左右**取决于规则严格度；
- 规格填充率 **51.02%**（相对全部）/ 换行率相对**非空**规格是 **99.60%**；
- 冒号相对非空规格也是 **99.6%**。

**影响**：

- §4.1 "KV Parser 覆盖率 99.6%" —— ✅ 正确（相对非空）；
- §4.3 "38.87% 规格为空" —— ❌ 实测 **48.98%**，反向补全的工作量比方案预计更大；
- §6.2 "结构化率从 ~35% 提升到 ≥85%" 中的 **35% 基线未标注来源**，且分母若按 15,173 或 12,715 结果不同。

**建议**：在方案开头加入"口径与数据前提"章节，明确以"画像 v1.1 精确版"或"画像 review 修订版"为准，二选一并保持前后一致。

### 🔴 B2. 域路由矩阵不完整

第三章标题为"30 域路由映射矩阵"，但表格只列到第 20 域，21~30 域被一笔带过为 `generic_*`。实际上：

- 后端主方案的 30 域 Schema 每个域都有独立的 Must / Should / Flags；
- 若 21~30 域全部落入 `generic_*` 兜底，**5 大原则中"双端 Schema 完全对称"就无法兑现**（后端有 Schema、Query 端没有对应的抽取器）。

**建议**：补齐第 21~30 域，尤其是画像中出现较多的：`silencer 消声器`、`plenum 静压箱`、`header_steam 汽水集配器`、`ahu 洁卫型空调机组`、`led/lighting 灯具`、装饰的 `floor_tile / wall_paint / gypsum_board`、`sealant 密封胶` 等。

### 🔴 B3. IR-0 过滤规则覆盖过窄

现有 5 条规则只能剔除极少数明显噪音行。实测 15,173 → 12,715 需要剔除 **~2,458 行**，但方案的 5 条规则加起来大概只能剔除几百行：

- 未处理：**跨 Sheet 重复的表头行** —— 画像里 `名称 / 项目名称 / 构件名称` 虽被列入，但真实 Excel 中该列常被 openpyxl 读取为 `nan`，纯字符串匹配会漏掉；
- 未处理：**清单章节段落**（如 `一、总说明`、`二、图纸依据` 后紧跟长文本，其 `unit` 可能是空字符串而非 None）；
- 未处理：**"编制人:XXX / 审核人:XXX / 编制日期:XXX"** 表尾行；
- 未处理：**工程量计算式行**（name 为空、spec 为纯数字表达式）；
- 未处理：**跨行合并单元格拆散后的孤立行**（openpyxl 读到 nan+nan+单位）。

**建议**：把 IR-0 从 5 条扩展到 ≥10 条，并**同时输出剔除条数分布报告**（哪个规则剔了多少条），保证 12,715 这个数字可复现。

## 三、需修正的问题（Major）

### 🟠 M1. IR-1 "前缀序号剥离" 与画像结论矛盾

上一轮审计中，严格意义序号前缀 `1.` / `①` 只有 **0.01%**，`1.1` 这种小节号本身占比也很低。方案花大篇幅设计"前缀剥离"意义不大，反而有误伤真实型号（如 `2.5mm²`、`3.15A`）的风险。

**建议**：

- 保留规则但降低优先级；
- 增加白名单（数字后紧跟 `mm / A / kW / DN / ² / *` 时**不剔除**）。

### 🟠 M2. "名称与规格解耦"规则举例与画像不符

画像 / 实测 Top20 名称中确实存在 `无缝钢管` + `DN`、`电缆` + `YJV*`，但**画像**说 3.78%、**实测** 2.96%，绝对量约 450 条。方案把它列为"重点解耦"，实际是**极少数场景**，不必上升到主设计。

**建议**：作为 §2.2 的一个 sub-step，配合正则白名单即可，不必单独章节。

### 🟠 M3. §3 域路由的 "Sheet Hint 降级"过度简化

实测 Sheet 命名极其杂乱（例：`附件三：柯桥未来医学中心净化系统项目-装饰水电一标-0703 / 净化ICU专业转固`），一个 Sheet 常同时含"装饰+水电"或"暖通+净化"。仅靠"Sheet 名字含'暖通'"会把混合 Sheet 里的装饰条目全部错分到 `generic_hvac`。

**建议**：

1. Sheet Hint 应产出 **加权向量**（例：`{hvac:0.4, elec:0.4, deco:0.2}`），而非硬路由；
2. 只有当 Step1 / Step2 都失败时，Sheet Hint 才作为**弱先验**参与 30 域打分，而非直接 Fallback。

### 🟠 M4. IR-2 KV Parser 正则存在 bug

第 220 行的正则：

```python
r'^(?:\d+[\.\、\s]|（\d+）|\(\d+\)|[①-⑩])?\s*([\u4e00-\u9fa5A-Za-z0-9_]+)\s*[:：]\s*(.*)$'
```

问题：

- `[\u4e00-\u9fa5A-Za-z0-9_]+` **贪婪匹配**会把 `1.规格` 里的 `1` 吃掉（当 `\d+[\.\、\s]` 中 `\s` 匹配失败时前缀 group 不匹配，Key 就会变成 `1规格`）；
- 实测规格里存在 **`(mm)`、`( )`** 等英文括号单位，会污染 Key；
- 未处理 `-> / ==` 等替代分隔符。

**建议**：在 Key 与 Value 之间加 **`(?:[（\(][^）\)]*[）\)])?`**（可选单位括号），并在 Key 中**排除末尾数字**。

### 🟠 M5. §5.2 "缺字段扣分 -0.05" 与后端主方案冲突

后端主方案中 Should 字段是 **软加分**逻辑；本方案改为"缺字段就 -0.05"，**方向相反**。若真的实施，会把后端物料库中大量 Should 缺失的记录（画像显示后端 `常用品牌` 只有 84.57% 非空）系统性打压。

**建议**：

- 保持后端主方案的 "有则加分、无则不扣" 策略；
- 只对 **Query 端明确给出、后端确实存在字段但值冲突** 的情况扣分（避免把"缺失"和"冲突"两种情况混为一谈）。

## 四、值得改进的地方（Minor）

- **🟡 P1**：§4.2 `CFM × 1.699 = m³/h` 应为 **1.6990** ~ **1.699011**（近似），且 CFM 在国内清单中几乎不出现，建议移到"低优先级"。
- **🟡 P2**：§4.2 `4寸 → DN100` 是简化换算，实际 4"（DN100）、6"（DN150）等都是常规约定，建议加脚注声明使用 **JIS 惯例映射表**。
- **🟡 P3**：§6.2 目标"结构化率 ≥85%"若采用严格 Must 字段完整（例如 `fan_hvac` 必须 `airflow + pressure` 都齐全）作为分子，实测规格填充率只有 51%，**很难达到 85%**。建议拆分为：
  - "域路由成功率 ≥95%"；
  - "Must 字段抽取率 ≥60%（非空规格分母下 ≥90%）"。
- **🟡 P4**：Phase 3 缺少 **"人工标注真集从哪来"** 的说明（[真集/](./真集/) 目录里有完成清单文件可以复用），建议在实施计划里点明。
- **🟡 P5**：方案未提及 **"Query 端结果如何回写 / 落盘"**（是新增 `query_ir` 表还是 JSONL？是否入 Redis？），仅有算法侧设计而缺数据链路侧。

## 五、被证实为**可靠**的核心设计

- ✅ **两层清洗 (IR-0 + IR-1) → 域路由 → IR-2 分域抽取 → Matching Adapter** 的四段流水线架构清晰，与后端主方案严格对齐。
- ✅ **屏蔽 `工作内容 / 重复名称 / 备注` 三大噪音 Key** 是本方案最有价值的洞察，直接命中画像中 **7,469 + 5,747 + 571** 次的三大噪音源。
- ✅ **KV Parser 覆盖率 99.6%** 是审计实测数据支持的正确判断（前提是分母用"非空规格"，方案里正好用对了）。
- ✅ **单位强制归一（Air Volume / Pressure / Power / DN / Dimension / Cable Area）** 六个维度全面覆盖了画像 Top 15 属性 Key 中的物理量项。
- ✅ **无规格反向补全（`NameSpecExtractor`）** 是应对专项发包包（PVC / 橡胶）规格几乎全空场景的关键设计。

## 七、一句话结论

**这是一份合格且可实施的技术方案设计稿**，主体架构无需推翻；但在**数据前提准确性、30 域矩阵完整性、IR-0 覆盖度、评估指标口径**四个点上必须修订后，才可作为工程实施的正式蓝本。
