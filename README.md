# ListTrans · 工程物料清单智能匹配系统

ListTrans 面向洁净工程物料清单，提供 Excel 导入、规范化清洗、物料候选推荐、人工复核、草稿和标准报表导出。

当前工作区为 **V0.2.0 发布候选（RC）／待独立审核与统筹终审，未获生产发布授权**。[发布候选清单与支持边界](doc/V0.2.0/evidence/v020_release_candidate_manifest.md)

## 默认工作流程

1. 登录后上传 `.xlsx` 工程清单。工作台清洗名称、规格、单位、品牌和专业信息，返回通过硬约束过滤的候选。本地 BGE 可用时提供向量召回，向量不可用时使用关键词 FTS5。
2. 按建议状态筛查待处理行，选择候选并核对单位、数量后人工确认，或者记录拒绝。修改影响绑定的字段后需要重新确认。草稿恢复时会复验已有确认。
3. 导出前服务端复验确认凭据与当前目录。待确认、已拒绝或确认已失效的行会收到 `422`，按提示处理后重试。物料与人员导入支持其各自模板的 `.xlsx` 和 `.xls`。
4. 管理员先评测规则，再用有效评测凭据确认发布。飞轮规则快照按栈顶顺序回滚。物料更新受目录 revision 与索引切换约束。账号权限、Token 撤销和任务所有者检查持续生效。

## 受控功能与已知边界

- V0.1.8 三项召回实验、V0.1.9 实验评分／重排／自动接受校准、系列重跑及 V0.2.0 反馈排序均保持默认关闭。反馈数据尚不足以支持在线自动训练或证明排序收益。
- 受支持的分段组合 BOM 已做隔离验证。当前 `config/auto_binding_rules.json` 为 `[]`，无生效生产 BOM 规则。受控 LLM、旧 LLM 的开关均关闭，受控路径仅验证过离线 Mock。
- 冻结全量排名、错误建议及自动接受覆盖仍有已知质量缺口。离线 Cross-Encoder、1024 维评估延后至 V0.2.1 再议。Linux 离线镜像验收 `ENV-V017-01` 和首次真实部署前凭据轮换 `PRG-F11` 保持开放。具体证据见[发布候选说明](doc/V0.2.0/evidence/v020_release_candidate_manifest.md)。

## 技术栈

- 前端：HTML、CSS、原生 JavaScript
- 后端：FastAPI、Uvicorn、Pydantic
- 数据：SQLite、FTS5
- 匹配：结构化特征、关键词检索、向量召回与规则约束
- 文件：pandas、openpyxl

## 快速开始

### 本地启动

使用已核验的 Windows Python 3.12 环境及受控目录副本，从本地读取 `model_offline/bge-small-zh-v1.5`。按[运行手册](deploy_guide.md)准备隔离路径、账号与密钥，再以 Uvicorn 单 Worker 启动本机预验收。单 Worker 用于保持 SQLite 写入、进程内索引和动态规则状态一致。

### Docker

项目保留 `Dockerfile` 和历史 `docker-compose.yml`。Linux 离线运行需使用经验证的候选镜像及受控运行挂载。仓库 Compose 仍引用 V0.1.4 标签并挂载源码，使用边界见[运行手册](deploy_guide.md)。

## 测试与数据安全

测试前按[测试说明](tests/README.md)及 [R01 复验方法](doc/V0.2.0/evidence/m3_r01_reproduce.md)设置仓外临时根、离线护栏及隔离库、配置、向量缓存、上传和输出路径。先通过 `tests/verify_isolation.py` 再运行全量，结束后复核业务资产 SHA256。

## 项目目录

| 目录 | 用途 |
|---|---|
| `app/` | 后端业务代码 |
| `web/` | 前端工作台、登录和管理页面 |
| `config/` | Schema、匹配、清洗和规则配置 |
| `tests/` | 测试与评测工具 |
| `scripts/` | 运维和离线治理脚本 |
| `doc/` | 各版本任务、审核记录及项目文档 |
| `model_offline/` | 本机离线模型文件 |
| `data/`、`logs/` | 运行数据和日志。请谨慎处理 |
